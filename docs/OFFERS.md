# Предложения бизнесу: страница `/offer/<код>`

Когда делаем предложение бизнесу, клиент сразу видит, как это работает у него, и тут же может подключиться.
Одна ссылка — одна страница: «Предложение GASTECH для <имя бизнеса>», его боли, 2–3 модуля с живым демо на
выдуманных, но похожих на его данных, «Загрузите выгрузку — отчёт за 2 минуты», «Попробовать в Telegram»
и «Подключить».

Код — `src/gas_pult/offers.py` (предложения, демо-данные, сценарий Telegram, защита), `offer_report.py` (сводка по
выгрузке), страница — `src/gas_pult/web/offer.html` (один файл, без сборки), маршруты — `webapp.py`
(`/offer/…`, `/api/offer/…`), демо в боте — `bot.py` (`/start demo_…`, кнопки `dm:`).

## Как сделать предложение

На сервере пульта (там, где работает панель):

```bash
gas-pult offer example > /tmp/offer.toml          # пример с выдуманной компанией — поправить под клиента
gas-pult offer new /tmp/offer.toml --url https://<адрес панели> --expires 2026-12-31
gas-pult offer new --name "Имя бизнеса" --url https://<адрес панели>   # быстро: пример с другим именем
gas-pult offer list                                # какие есть, срок, состояние
gas-pult offer revoke <код>                        # отозвать: страница сразу «не найдена»
```

`offer new` проверяет файл (поля, модули из каталога), придумывает неугадываемый код, кладёт
`~/.config/gas-pult/offers/<код>.toml` (права 0600; каталог — от каталога конфига, `GAS_PULT_CONFIG_DIR`) и печатает
ссылку. Файл можно править и после — страница читает его на каждый запрос, перезапуск не нужен. После правки
проверьте: `gas-pult offer list` покажет ошибку, если файл сломан (страница тогда отвечает 404).

Формат — пример с комментариями: [`src/gas_pult/templates/offers/example.toml`](../src/gas_pult/templates/offers/example.toml).

| Поле | Что это |
|---|---|
| `business` | имя бизнеса — просто текст (до 80 знаков); на странице экранируется |
| `industry` | отрасль для демо-данных: `carwash`, `fitness`, `horeca`, `uk`, `sellers`, `services` |
| `pains` | что болит — 1–6 строк |
| `modules` | 1–3 id модулей из каталога (`/modules` в боте) |
| `expires` | необязательно: последний день, когда ссылка работает (`ГГГГ-ММ-ДД`) |
| `note` | внутренняя заметка — клиенту не показывается |
| `[demo]` | необязательно: `points` (точки/филиалы), `point_word`, `avg_check`, `daily_revenue`, `clients`, `items` |

Настоящие предложения — только вне репозитория. В репозитории — один пример с выдуманной компанией.

## Что видит клиент

1. **Заголовок** «Предложение GASTECH для <имя>» и плашка «Цифры и имена выдуманы для демонстрации». Логотипов,
   цветов и доменов клиента на странице нет — только наши токены и текст имени.
2. **Что болит** — строки из `pains`.
3. **Модули** — название и «для чего» из `module.toml` (тексты не дублируются) и живое демо: утренняя сводка
   (карточка цифр по его точкам), напоминание клиенту (пример сообщения из шаблона модуля и «Отправить пачку из N?»)
   или заявка; вопрос агента с кнопками из `[[decisions]]` модуля — нажатие показывает, что произошло бы, ничего не
   выполняя. Данные — детерминированно из полей предложения (одинаковые при каждом открытии).
4. **«Попробовать в Telegram»** — открывает бота пульта: 3–4 сообщения сценария (заявка → напоминание клиенту →
   утренние цифры → вопрос агента) с работающими кнопками, в конце «Подключить» и «Посмотреть ещё раз».
5. **«Загрузите выгрузку — отчёт за 2 минуты»** — CSV или XLSX (продажи, клиенты, должники) → сводка за секунды.
6. **«Подключить»** — мастер: условия → страна → модуль → вход через Telegram.

## День с агентом и калькулятор пользы

Если у предложения есть роль «Примерочной» с теми же модулями (`templates/scenarios/*.toml`: автомойки —
`carwash-owner`, УК — `uk-director`), на странице есть блок «День с агентом»: шаги дня с кнопками («Что произошло бы»,
ничего не выполняется) и «Ваша польза — оценка» с ползунками. Значения по умолчанию — из `[demo]` предложения:
филиалов — сколько точек в `demo.points`, средний чек — `demo.avg_check`, клиентов — `demo.clients` (в границах
ползунка). Допущения — отдельным блоком, с подписью и диапазоном, как в «Примерочной»; расчёт — тот же `benefitCalc`,
что в панели (тест сверяет). Гостю без входа; модель и сервер не вызываются — пересчёт в браузере. Роли с модулями
предложения нет (например, фитнес) — блока нет.

## Демо в Telegram

Кнопка на странице просит у панели **токен демо** (`TgDemos`, 24 случайных знака, живёт час, запускать сценарий —
до 10 раз на токен) и открывает `https://t.me/<бот>?start=demo_<токен>`. Код предложения в ссылку не попадает.
Токены — в `<data>/offer_tg.json` (0600): токен → предложение, модуль, срок, сколько раз запускали; людей там нет.

Бот принимает от незнакомых только `/start demo_…` и кнопки `dm:` (кроме входа в панель, как раньше): ни роли, ни меню,
ни команд, ни сессий — всё остальное от этого человека бот молча игнорирует, как от любого незнакомца. Модель и голос
не используются. Кнопка — `dm:<токен>:<шаг>:<вариант>` (до 64 байт); токен проверяется на каждое нажатие; истёк,
предложение отозвано или просрочено — «Демо закончилось — откройте ссылку на странице предложения снова».
Один человек — не больше 5 запусков в час (счётчик только в памяти бота).

Сценарий — из `[[demo.telegram]]` модуля (формат — [`MODULES.md`](MODULES.md), раздел «Демо»), с подстановкой
`{{business}}`, `{{industry}}`, `{{point}}`, `{{n}}`. Секции нет — сценарий по умолчанию из полей модуля и
предложения. Заполнены: `carwash-return`, `fitness-lapsed`, `horeca-receivables`, `uk-requests`, `wb-ozon-stock`.

«Подключить» в конце — обычный запрос доступа владельцу с пометкой предложения (один раз на человека, пока владелец
не ответил). Без этой кнопки владельцу ничего не приходит.

## Загрузка выгрузки

`POST /api/offer/<код>/upload` — тело файла, до 5 МБ и 50 000 строк. Вид файла — по содержимому (`PK` — XLSX,
иначе CSV в UTF-8, UTF-16 или cp1251; старый `.xls` — понятный отказ). Тип выгрузки угадывается по заголовкам
столбцов (`offer_report.guess`), человек может выбрать тип и столбцы вручную («Тип и столбцы — выбрать вручную»).

| Тип | Нужно | Сводка |
|---|---|---|
| Продажи | сумма (дата, точка, позиция — по желанию) | выручка, продаж, средний чек, по периодам (день/неделя/месяц), динамика, по точкам, топ позиций |
| Клиенты | клиент и последний визит (или журнал визитов: клиент + дата) | сколько, давно не были 30/45/60+ дней, повторные, «кого вернуть первыми», размер пачки напоминаний |
| Должники | клиент и долг (или сумма и оплачено) | должны всего, просрочено, больше 30 дней, корзины просрочки, топ-5 |

XLSX читается `zipfile` + `xml.etree`: не больше 300 файлов в архиве, 60 МБ распакованного всего и 25 МБ на файл
(zip-бомба — понятный отказ), `DOCTYPE`/`ENTITY` запрещены, читается только первый лист.

Расчёт — отдельный модуль пакета на стандартной библиотеке; скрипты модулей (`branch_kpi.py`, `club_kpi.py`…) остаются
скриптами пространств и в рантайме панели не импортируются: у них свой формат файлов и план, у страницы — произвольная
выгрузка клиента.

## Подключить

1. **Условия** — тот же текст и версия, что в панели (`terms.py`), «Принимаю».
2. **Страна** — тот же выбор; если для страны (вместе со страной сервера) нет ни одного поставщика — ровно «Этот
   сервис недоступен в вашей стране по условиям поставщика».
3. **Модуль** — один из предложенных.
4. **Вход через Telegram** — обычный поток (`/api/login/tg` → бот → START). Владелец получает запрос доступа с
   пометкой: «С предложения GASTECH для <имя> (код abcd…)», выбранный модуль, страна, версия принятых условий.
   Код целиком владельцу не показывается.

Пока владелец не дал роль, сессии не создаются и модель не тратится. Когда владелец нажал «👤 Участник»:

- согласие с условиями (той же версии) и страна из мастера записываются человеку; бот просит подтвердить номер
  («Поделиться номером», как обычно);
- владельцу приходит «Создать пространство «<модуль>»?» — одна кнопка создаёт папку из модуля с отметкой «чьё»
  (`modules.create`, как «Из модуля»), **без сессии**;
- сессию человек открывает сам в панели («Новая сессия» → папка), туда же загружает выгрузку (📎).

Честный минимум этого PR: загрузка выгрузки в папку модуля — после входа, из панели; до одобрения файл в папку не
попадает.

## Безопасность

- **Код** — `secrets.token_urlsafe(18)`: 24 знака, 144 бита; в URL проверяется строгим regex `[A-Za-z0-9_-]{24,64}`.
  Нет, отозвано, просрочено, файл сломан — один и тот же 404. Больше 20 неизвестных кодов с одного IP за 10 минут —
  429 на любые коды до конца окна (перебор не отличает «есть» от «нет»).
- **Не индексируется**: `X-Robots-Tag: noindex, nofollow, noarchive`, `<meta name="robots">`, `Referrer-Policy:
  no-referrer`, `Cache-Control: no-store`, `robots.txt` — `Disallow: /offer/`. Строгий CSP страницы: скрипт — только
  встроенный по хешу, запросы — только к своему адресу, без фреймов (`frame-ancestors 'none'`).
- **Без доступа к панели**: `/api/offer/…` не проверяет вход, но отвечает только на действующий код и умеет только
  своё — данные страницы, загрузку, «удалить», шаги мастера, ссылку входа и токен демо. Сессии, tmux, ключи, люди —
  недоступны (тест `test_offer_gives_no_panel_access`). Cookie демо (`gp_offer`) — отдельная от входа в панель.
- **ПДн из загрузки**: файл разбирается в памяти и на диск не пишется; в памяти процесса панели остаются только
  агрегаты и маскированные строки («Иван П.»; телефоны, ИНН, почта — никогда), привязанные к демо-сессии (cookie
  `HttpOnly`, `SameSite=Lax`, `Secure` за HTTPS) на 30 минут; потом — удаляются (фоновая уборка раз в минуту).
  «Удалить мои данные» стирает сразу. Содержимое файла не логируется. Модель не вызывается, наружу ничего не уходит.
- **Срок и отзыв**: `expires` в файле, `gas-pult offer revoke` — файл уходит в `offers/revoked/`.

## Через Caddy

Тот же адрес панели и тот же порт: `https://<адрес панели>/offer/<код>`. Панель отдаёт `/offer/…`, `/api/offer/…` и
`/robots.txt` без входа сама — Caddy проксирует всё на панель, менять его не нужно. Адрес клиента для ограничения
перебора — из `X-Forwarded-For` (последний адрес, как для страны по IP). Если перед панелью стоит своя авторизация
на уровне прокси — `/offer/*` нужно пропустить без неё.
