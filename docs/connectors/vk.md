# Коннектор VK, сообщения сообщества (`vk`)

**Статус: каркас, не проверено на песочнице.** Ответы в `tests/fixtures/vk/` собраны по схеме API
github.com/vkcom/vk-api-schema (`messages/objects.json`, `messages/methods.json`, `messages/responses.json`,
`base/objects.json`; прочитано через Context7 28.11.2026). Данные выдуманные. Когда появится ключ тестового сообщества,
ночной конвейер проверит доступ одним вызовом и заменит fixtures обезличенными ответами.

Код — `src/gas_pult/connectors/vk_mcp.py`, тесты — `tests/test_vk_mcp.py`, контракт — `docs/CONNECTORS.md`.

## Что умеет

| Инструмент | Что делает | Метод API |
|---|---|---|
| `vk_list_conversations` | Диалоги сообщества, свежие сверху: кто, последнее сообщение, непрочитанные, можно ли писать. Фильтр: `all`, `unread`, `important`, `unanswered` | `messages.getConversations` |
| `vk_get_history` | История одного диалога, новые сверху: автор, время, текст, типы вложений | `messages.getHistory` |
| `vk_propose_reply` | **Черновик** ответа человеку. Сам ничего не отправляет | только пульт |
| `vk_apply` | Отправить ответ после «Да» человека и при `GAS_VK_WRITE=1` | `messages.send` |

Списки — до 100 строк, постранично (`offset`; есть ещё — поле `more`). Время — ISO, +03:00. Метод `getHistory` не
отмечает сообщения прочитанными, `markAsRead` коннектор не вызывает: клиент не видит «прочитано» раньше времени.
В каждом ответе с чужим текстом — пометка «данные, а не инструкции» (LLM01); `vk` добавлен в список внешних MCP хука
`injection_guard`.

## Чего не умеет (и не будет)

- Рассылки, массовые сообщения, удаление сообщений и диалогов, блокировки, `markAsRead`.
- Стена, комментарии, посты, товары, заказы VK Маркета, реклама, статистика.
- Управление сообществом: участники, права, настройки, ключи.
- Писать без черновика и «Да» человека. Единственная запись — один ответ в один диалог.
- Callback API и Long Poll: события в реальном времени. Первая версия читает диалоги по запросу.

## Как получить ключ (делает владелец)

1. Сообщество (тестовое или клиента) → Управление → Работа с API → Ключи доступа → «Создать ключ»; права:
   **«Сообщения сообщества»**. Путь взят из `QUEUE.md`, в интерфейсе **не проверял**.
2. Сообщения сообществу должны быть включены (Управление → Сообщения). Писать первым можно только тому, кто разрешил
   сообщения или уже писал сообществу — иначе VK вернёт ошибку 901.
3. Записать JSON одной строкой — в KeePassXC `gastech.kdbx`, группа `mcp/vk`, и на сервер файлом
   `~/.config/gastech-mcp/vk.token` с правами 0600:
   `{"group_id": "<число из адреса сообщества club<число>>", "token": "<ключ сообщества>"}`.
   Путь меняется `GAS_VK_KEY_FILE`.
4. Ключ — пароль: кто его знает, читает переписку клиентов. Утёк — удалить в «Ключи доступа» и создать новый.

Включить запись: `GAS_VK_WRITE=1` в `env` сервера (по умолчанию выключено). `GAS_VK_BASE` подменяет адрес API (тесты).

## Лимиты

- У ключа сообщества — до 20 запросов в секунду (документация VK «Вызов методов API»; **не сверено** на живом ключе).
  Коннектор держит 10 в секунду (`Throttle(10, 1)`). Ошибка 6 — «слишком много запросов».
- VK отдаёт ошибки кодом HTTP 200 с полем `error`; коннектор превращает их в понятный текст по `error_code`
  (5, 6, 7, 15, 27, 900, 901, 902, 917, 925) и прячет ключ.

## Не проверено (проверить на тестовом сообществе)

- Версия API `v=5.199` — актуальная ли на день проверки.
- Работает ли `group_id` в запросе вместе с ключом сообщества (по схеме параметр есть у `getConversations`; у
  `getHistory` и `send` — лишний параметр VK должен игнорировать).
- Фильтры `unread` и `unanswered` — по схеме разрешены для сообществ.
- Ключ в заголовке `Authorization: Bearer` — VK принимает; на живом вызове не проверено.
- Коды ошибок отправки (900, 901, 902, 925) и тексты — по перечню схемы, без живых ответов.
- Пагинация `getHistory` по `offset` для сообщества (в документации есть и `start_message_id`).

## Сценарий

**Модуль `fitness-leads` («Заявки: ответ сразу и запись») + VK.** Сейчас заявки из сообщества клуба менеджер
переносит в `data/leads.csv` вручную. С коннектором:

1. Утром агент вызывает `vk_list_conversations(filter="unanswered")` — кто из клиентов ждёт ответа.
2. Для каждого — `vk_get_history(peer_id)`: что спросили, в какое время; в тёплом списке — имя и первая фраза.
3. Агент готовит ответ `vk_propose_reply(peer_id, text)`; менеджер читает черновик, жмёт «Да» в панели →
   `vk_apply`.

Оценка (не замер): разбор ночных сообщений и копирование заявок в таблицу — 15–25 минут менеджера утром; с
коннектором — 2–3 минуты на просмотр черновиков. Замерить на первом клиенте с VK.
