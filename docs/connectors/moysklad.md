# Коннектор МойСклад (`moysklad`)

**Статус: каркас, не проверено на песочнице.** Ответы в `tests/fixtures/moysklad/` собраны по примерам из официальной
документации (JSON API 1.2, [github.com/moysklad/api-remap-1.2-doc](https://github.com/moysklad/api-remap-1.2-doc),
коммит `012cd53` от 12.11.2026). После появления токена демо-аккаунта ночной конвейер проверит доступ одним вызовом и
заменит fixtures обезличенными ответами.

Код — `src/gas_pult/connectors/moysklad_mcp.py`, тесты — `tests/test_moysklad_mcp.py`, контракт — `docs/CONNECTORS.md`.

## Что умеет

| Инструмент | Что делает | Запрос к API |
|---|---|---|
| `moysklad_list_stock` | Остатки: остаток, резерв, доступно, ожидание, себестоимость и цена продажи в ₽, дней на складе. Поиск по названию, режим остатка (`underMinimum` — ниже неснижаемого, для дозаказа) | `GET /report/stock/all` |
| `moysklad_list_orders` | Заказы покупателей, новые сверху: номер, дата, покупатель, статус, сумма/оплачено/отгружено в ₽, ссылка в МойСклад | `GET /entity/customerorder?expand=agent,state` |
| `moysklad_get_order` | Один заказ с позициями (до 50) | `GET /entity/customerorder/{id}?expand=agent,state,positions.assortment` |
| `moysklad_list_balances` | Взаиморасчёты: баланс контрагента в ₽, число и сумма продаж, последняя продажа | `GET /report/counterparty` |
| `moysklad_list_order_states` | Статусы заказов, настроенные в аккаунте | `GET /entity/customerorder/metadata` |
| `moysklad_propose_order_state` | **Черновик** смены статуса заказа. Сам ничего не меняет | только чтение |
| `moysklad_apply` | Выполнить черновик после подтверждения человека и при `GAS_MOYSKLAD_WRITE=1` | `PUT /entity/customerorder/{id}` (только поле `state`) |

Суммы МойСклад отдаёт в копейках — коннектор переводит в рубли. Даты — ISO без часового пояса (время Москвы, как в
аккаунте). Списки — до 100 строк за вызов; если строк больше, в ответе поле `more` и параметр `offset` для следующей
страницы.

## Чего не умеет (и не будет)

- Создавать, удалять, проводить документы; менять суммы, позиции, цены, контрагентов.
- Платежи, кассы, права пользователей, токены.
- Писать что-либо без черновика и подтверждения человека. Единственная запись — смена статуса заказа.

## Как получить ключ (делает владелец)

1. Демо-аккаунт: [moysklad.ru](https://www.moysklad.ru/) → «Попробовать бесплатно» (на клиента — его аккаунт и отдельный
   сотрудник только с правами на чтение нужных разделов).
2. В аккаунте: Настройки → Пользователи → Токены → создать токен для сотрудника пульта (путь из каталога
   `portfolio-hq/products/integrations-market.md`; в интерфейсе **не проверял**).
3. Положить токен одной строкой в KeePassXC `gastech.kdbx`, группа `mcp/moysklad`, и на сервер — файлом
   `~/.config/gastech-mcp/moysklad.token` с правами 0600. Путь меняется переменной `GAS_MOYSKLAD_KEY_FILE`.
4. Токен даёт те же права, что у сотрудника. Сотрудник пульта без права на изменение заказов — запись не сработает
   даже после подтверждения (это хорошо).

Включить запись: `GAS_MOYSKLAD_WRITE=1` в `env` сервера (по умолчанию выключено).

## Лимиты (по документации, раздел «Ограничения»)

- 45 единиц лимита за 3 с на пользователя. Запрос по токену пользователя стоит 3 единицы (с 01.09.2026) и 4 единицы
  (с 01.12.2026) — то есть 11 запросов за 3 с. Отчёт об остатках `/report/stock/all` — 5 единиц. Коннектор считает
  единицы сам (`Throttle(44, 3)`, обычный запрос — 4, остатки — 5).
- Не больше 5 параллельных запросов от пользователя. Превышение — ответ 429, коннектор пишет «лимит запросов, подождите».
- `expand` (подтянуть покупателя и статус в одном запросе) работает только при `limit` ≤ 100 — поэтому максимум 100.
- Обязательны заголовки `Accept-Encoding: gzip` (иначе 415) и `Accept: application/json;charset=utf-8` (иначе
  ошибка 1062). Ядро `_core.http` распаковывает gzip.
- Отчёт «Показатели контрагентов» требует опцию CRM в тарифе — без неё `moysklad_list_balances` вернёт ошибку доступа.

## Не проверено (проверить на демо-аккаунте)

- Знак баланса в отчёте «Показатели контрагентов»: минус — долг покупателя нам? В документации не описан.
- Наличие `meta.uuidHref` (ссылка на запись в веб-интерфейсе) в ответе с `expand`: в примере документации есть у
  заказов (`workbook/_workbook_paging.md`), у контрагентов — не видел.
- Работает ли вложенный `expand=positions.assortment` вместе с `agent,state` одним запросом.

## Сценарий

**Модуль `horeca-reorder` («Повторный заказ по циклу») + МойСклад.** Сейчас модуль берёт историю заказов из
`data/orders.csv` — выгрузку из учёта поставщика делает человек. С коннектором:

1. В 11:00 агент вызывает `moysklad_list_orders(since=<60 дней назад>, limit=100)` и `moysklad_get_order` для
   последних заказов каждого ресторана — получает ту же историю (дата, ресторан, позиции), без выгрузки.
2. Навык `reorder-cycle` считает циклы как раньше; для «обычного набора» берёт позиции из `get_order`.
3. `moysklad_list_stock(stock_mode="underMinimum")` — в сводку попадает, каких позиций не хватит под ожидаемые заказы.
4. После ответа шефа и «Да» менеджера — `moysklad_propose_order_state` («Подтвержден») → человек подтверждает → `apply`.

Связка с `horeca-receivables`: `moysklad_list_balances` заменяет ручную выгрузку `data/settlements.csv` для сводки по
долгам (после проверки знака баланса на демо).

**Оценка «минут до/после» (не замерено, оценка):** выгрузка истории заказов и остатков в CSV и загрузка в модуль —
~15 мин в день вручную → 0 мин (агент читает сам); проверка статуса заказа и перевод в «Подтвержден» — ~1 мин на
заказ → нажатие одной кнопки. Замерить на первом клиенте-поставщике HoReCa.

## Подключение в harness

Запись `moysklad` в `portfolio-hq/integrations/servers.json` (`auth.kind: "file"`, файл `moysklad.token`,
KeePassXC `mcp/moysklad`); `bootstrap/mcp-install.sh` пропускает сервер, пока нет файла ключа.
