# Telegram Business — коннектор пульта

Код — `src/gas_pult/connectors/tgbiz_mcp.py`, тесты — `tests/test_tgbiz_mcp.py`, контракт — `docs/CONNECTORS.md`.
Задача — gvriil/gas-pult#201 (решение владельца 14.11: Telegram Business вместо Telethon для рабочих переписок).
Документация — Bot API 10.4, https://core.telegram.org/bots/api (типы `BusinessConnection`, `BusinessBotRights`,
`BusinessMessagesDeleted`, методы `getUpdates`, `getBusinessConnection`, `sendMessage`), сверено 16.11.2026.

**Статус: каркас, не проверено на живом боте.** Fixtures собраны по описанию типов, данные выдуманные.

## Зачем

Владелец (или клиент пульта) подключает бота к своему аккаунту: Настройки → Telegram для бизнеса → Чат-боты. Бот
видит только выбранные чаты и отвечает, только если владелец включил право «отвечать». Это официальный путь с
правами, которые задаёт Telegram. Telethon даёт полный доступ к аккаунту — для рабочих переписок он больше не нужен.

## Что умеет

| Инструмент | Что делает | Метод Bot API |
|---|---|---|
| `tgbiz_list_messages` | Сообщения из подключённых чатов за 24 ч: новые, изменённые, удалённые; кто, когда, входящее или исходящее, текст. Вложения — пометкой (`[фото] подпись`, `[голосовое]`). Фильтры: `chat_id`, `connection_id`, `only_incoming` | `getUpdates` (без `offset`) |
| `tgbiz_list_connections` | Подключения бота: чей аккаунт, включено ли, есть ли право отвечать | `getUpdates` + `getBusinessConnection` |
| `tgbiz_get_connection` | Одно подключение по id: владелец, включено, права | `getBusinessConnection` |
| `tgbiz_get_bot` | Проверка ключа: имя бота, включён ли режим бизнеса | `getMe` (`can_connect_to_business`) |
| `tgbiz_propose_reply` | Черновик ответа клиенту от имени владельца аккаунта. Ничего не отправляет. Заранее проверяет, что подключение включено и есть право отвечать | `getBusinessConnection` (чтение) |
| `tgbiz_apply` | Отправить подтверждённый человеком черновик. Только при `GAS_TGBIZ_WRITE=1` и подтверждении в пульте | `sendMessage` с `business_connection_id` |

## Чего не умеет (и не будет без решения владельца)

- Не подтверждает очередь Telegram (`offset` не передаёт) и не отмечает сообщения прочитанными.
- Не хранит переписку на диске. Telegram держит неподтверждённые апдейты **до 24 ч** и отдаёт **до 100 самых
  старых** — история старше суток в пульте не видна. Нужен постоянный приём → отдельная служба пульта с хранением
  только выбранных чатов и сроком хранения (152-ФЗ); это следующий шаг по #201, не этот PR.
- Не скачивает файлы, фото и голосовые (расшифровка голосовых — следующий шаг через `voice.py stt`).
- Не удаляет и не редактирует сообщения, не меняет профиль, подарки, звёзды — даже если у бота есть такие права.
- Не работает, если у бота включён вебхук: `getUpdates` вернёт 409 (коннектор так и скажет).
- Отвечать можно только в чат, где было входящее за последние 24 ч (правило Telegram, `can_reply`).

## Ключ (делает владелец)

1. @BotFather → `/newbot` → имя и адрес бота → токен.
2. Включить у бота режим бизнеса в настройках @BotFather (название пункта **не проверено**; `tgbiz_get_bot`
   покажет `can_connect_to_business: true`, когда включено).
3. Токен — в KeePassXC `gastech.kdbx`, группа `mcp/tgbiz`; на сервер — файлом
   `~/.config/gastech-mcp/tg-business-bot.token` (одна строка, права 0600). Путь меняется `GAS_TGBIZ_KEY_FILE`.
   В чат токен не присылать.
4. В Telegram: Настройки → Telegram для бизнеса → Чат-боты → выбрать бота → **1 тестовый чат**; право «отвечать»
   пока выключить (чтение проверяем без него).

Токен стоит в адресе запроса (так устроен Bot API) — коннектор вычищает его из всех ответов и ошибок.
`GAS_TGBIZ_BASE` меняет адрес API (тесты; тестовая среда Telegram — **не проверял**).

## Служба бота `gas-pult-tgbiz` (решение владельца 16.11)

Апдейты бота читает **одна** служба (`gas-pult tgbiz run`) со своим offset и кладёт их в журнал
`~/.local/state/gas-pult/tgbiz/updates.jsonl` (0600, 7 дней; отметка жизни — `alive`). Коннектор, пока служба жива
(отметка свежее 2 мин), читает журнал, а не Telegram: второй читатель не забирает апдейты у первого. Служба не
запущена — коннектор, как раньше, читает очередь Telegram без подтверждения.

Владелец (``owners`` пульта) пишет боту в личный чат: `/заметка <текст>` (`/note`) — заметка сразу (Notion или файл),
голосовое — текст на этом сервере (T-one / whisper), голос не хранится. Чужим людям бот в личке не отвечает.

Юнит (пути — свои):

```ini
[Unit]
Description=gas-pult-tgbiz — бот Telegram Business: апдейты в журнал, команды владельца
After=network-online.target

[Service]
ExecStart=%h/.local/bin/gas-pult tgbiz run
Restart=on-failure
RestartSec=10
MemoryMax=300M

[Install]
WantedBy=default.target
```

## Лимиты

Telegram: около 30 сообщений в секунду на бота, в один чат — около 1 в секунду (FAQ Bot API, цифры **не сверял** в
этот раз). Коннектор держит не больше 20 запросов в секунду (`Throttle(20, 1)`); 429 — ошибка с текстом Telegram
«retry after N».

## Не проверено

- Всё на живом боте: формат ответов, поведение `getUpdates` при 100+ апдейтах, права в `rights`.
- Название пункта в @BotFather для режима бизнеса.
- Что `getUpdates` без `offset` не мешает другой программе с тем же ботом (рекомендация — отдельный бот на пульт).

## Сценарий

**УК + обращения жителей в Telegram (модуль `uk-requests`).** Жители пишут в личный Telegram управляющей. Утром
агент вызывает `tgbiz_list_messages(only_incoming=true)`, раскладывает обращения по видам и срокам навыком
`request-deadline` (реестр `requests.csv`, канал `telegram`) и готовит ответы навыком `resident-reply`. Ответ уходит
только после «Отправить»: `tgbiz_propose_reply` → кнопка в пульте → `tgbiz_apply`. Персональные данные — только на
российской модели (правило модуля).

**Владелец GASTECH (#201).** Тот же поток для рабочих чатов владельца: краткое содержание, договорённости и сроки →
черновик задачи; ответ — по кнопке.

**Оценка «минут до/после» (не замерено, оценка):** разобрать 20 сообщений за утро, завести обращения и написать
ответы — ~40 мин → ~10 мин (прочитать сводку, поправить и подтвердить черновики). Замерить на первом клиенте.

## Подключение в harness

```json
"tgbiz": {
  "type": "stdio", "command": "python3",
  "args": ["{gas_pult}/src/gas_pult/connectors/tgbiz_mcp.py"],
  "env": {"GAS_TGBIZ_KEY_FILE": "{secrets}/tg-business-bot.token"},
  "auth": {"kind": "file", "file": "tg-business-bot.token", "keepass": "mcp/tgbiz",
           "get_key": "@BotFather → новый бот → токен; Telegram → Настройки → Telegram для бизнеса → Чат-боты"},
  "purpose": "Telegram Business: входящие рабочих чатов — чтение; ответ — через подтверждение (gas-pult PR #244)"
}
```
