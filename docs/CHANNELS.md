# Каналы связи

Сейчас пульт говорит только через Telegram. Ниже — что дают другие каналы, чем они ограничены в России и сколько
работы их подключить. Дата сверки — **01.11.2026**; правила площадок и законы меняются, «уточнить» — не проверено
по первоисточнику. Код: интерфейс `Channel` в `src/gas_pult/channels.py`, первая реализация — `TelegramChannel`.

Объём: **S** — до дня, **M** — несколько дней, **L** — неделя и больше или нужны договоры и юрлицо.

**Модели и регион.** Российские каналы (MAX, VK) — только с поставщиком моделей, который разрешён для России; Claude (Anthropic) там не используется: Россия не входит в список поддерживаемых стран Anthropic. То же для любого канала, где собеседник из неподдерживаемой страны. Правила — `docs/COMPLIANCE.md`.

## MAX

Бот-платформа мессенджера VK: REST API, токен — только в заголовке `Authorization`. С 2026 года запросы идут на
`platform-api2.max.ru` (раньше `platform-api.max.ru`), и в доверенные нужно добавить сертификат Минцифры. События:
вебхук (`POST /subscriptions`) — для работы; `GET /updates` с `marker` и `timeout` до 90 с — по документации «только
для разработки», скорость и срок хранения событий ограничены. Есть инлайн-клавиатуры с callback, ответ на нажатие,
правка сообщений, загрузка файлов и аудио, мини-приложения. Ограничения: бота регистрирует организация, ИП или
самозанятый на «MAX для партнёров» после проверки бизнеса и модерации карточки бота (по блогам — до 5 ботов на
организацию; уточнить). Для пульта нужен вебхук, значит — публичный HTTPS: его даёт сервер панели. Объём **M**:
клиент на urllib, разбор `Update` → `Incoming`, приём вебхука в `webapp.py`; плюс бумажная часть.

## VK (сообщения сообщества)

Бот — это сообщество с включёнными сообщениями и ключом доступа; юрлицо не нужно, бесплатно. Bots Long Poll API
(опрос без публичного адреса — как сейчас у Telegram) или Callback API (вебхук). Клавиатуры: обычные и инлайн,
callback-кнопки с ответом `messages.sendMessageEventAnswer`, ссылки и VK Mini Apps; правка — `messages.edit`.
Файлы и голосовые — через загрузку на сервер VK (`docs.getMessagesUploadServer`, тип `audio_message`). Лимиты
частоты для сообществ мягче, чем у Telegram (уточнить точные числа). Объём **M**.

## WhatsApp Business (Cloud API, Meta)

Вебхук от Meta, исходящие — HTTP Graph API. Писать первым можно только шаблоном, одобренным Meta; свободный текст —
в течение 24 ч после сообщения человека. Кнопки — до 3 быстрых ответов или список до 10 пунктов, правки сообщений
нет. Нужны Meta Business Manager, подтверждённый номер, оплата за разговоры/шаблоны. В РФ: с августа 2025 РКН
поэтапно ограничивает WhatsApp, без VPN у большинства не работает, полная блокировка обсуждается; Meta признана
экстремистской организацией. Россия в списке стран, где платформа запрещена Meta, не значится, но оплата из РФ и
судьба аккаунтов российских компаний — уточнить. Для пульта сейчас **не рекомендуем**; объём **L**.

## E-mail

IMAP и SMTP есть в стандартной библиотеке (`imaplib`, `smtplib`, `email`) — ни зависимостей, ни публичного адреса.
Входящие — опрос IMAP или IDLE; ответ на нужное письмо — по `In-Reply-To`. Кнопок нет: вместо них ссылки на панель
(с одноразовым кодом) или ответ словом («да», «1»). Голос — вложением. Задержка — секунды-минуты. В РФ работает
любой почтовый ящик; для своего домена — SPF/DKIM, иначе письма уходят в спам. Если в письмах персональные данные
граждан РФ — 152-ФЗ (хранение на территории РФ). Объём **S** на уведомления и ответы текстом, **M** — с разбором цепочек.

## Веб-виджет

Окно чата на своём сайте, которое говорит с тем же сервером, что и панель (`webapp.py`): входящие — POST, исходящие —
опрос или SSE. Всё под нашим контролем: кнопки, правка, файлы, голос. Нужны вход (уже есть «Войти через Telegram» и
код), защита от спама и, если пишут посторонние, — согласие на обработку данных и политика по 152-ФЗ. Объём **M**:
часть уже есть в панели, нужны отдельный лёгкий виджет и `WebChannel`.

## SMS

Через шлюз (SMS.ru, SMSC, МТС Exolve, Билайн и др. — HTTP API). Исходящие — платно за сообщение, буквенное имя
отправителя регистрируется у операторов (до ~2 недель, нужно юрлицо или ИП и гарантийное письмо); без имени —
общий номер шлюза, такие SMS операторы часто режут. Входящие — только на выделенный (виртуальный) номер с вебхуком, это отдельная
плата. Ни кнопок, ни файлов, 70 знаков кириллицы на часть. Рекламные SMS — только с согласия (38-ФЗ); требования
2025–2026 годов к рассылкам и антифроду — уточнить у шлюза. Годится только для срочных уведомлений «Claude ждёт».
Объём **M** (только исходящие) — **L** (с входящими).

## Интерфейс и путь перевода бота

`Channel` (Protocol) — то, чем бот реально пользуется:

- `send_text(chat, text, keyboard)` → id сообщения; кнопки — нейтральные `Button(text, data | url | web_app)`;
- `edit_text(chat, message_id, text, keyboard)`, `answer(callback_id, text)` — правка и ответ на нажатие;
- `send_file(chat, name, data, kind)` — `document`, `voice`, `audio`; `download(attachment, dst_dir)`;
- `poll(timeout)` → список `Incoming` (канал, чат, пользователь, текст, нажатая кнопка, вложение, сырой update);
- `caps` — что умеет канал: кнопки, правка, голос, файлы, Mini App, длина сообщения.

Бот пока вызывает `telegram.Api` напрямую — интерфейс добавлен, поведение не менялось. Перевод — по шагам, каждый
отдельным PR с тестами:

1. `Pult.send`/`broadcast` → `channel.send_text`; разметка `reply_markup` из `kb()` → `Keyboard` (`buttons()`).
   Особые случаи — постоянное меню (`ReplyKeyboardMarkup`) и кнопка «Панель» — добавить в `Button`/`Caps`.
2. `run` → `channel.poll()`, `handle(Incoming)`; проверка владельца — по паре (канал, user).
3. Голос и файлы (`speak`, `send_file` в командах, `download` во входящих) — через канал; `caps.voice` — без голоса
   отвечать текстом.
4. Правки (`show_dialog`, подсказка 💡 через `editMessageReplyMarkup`) — через `edit_text`; без `caps.edit` —
   новое сообщение. Реакции и `setChatMenuButton` — необязательные возможности, только у Telegram.
5. Владельцы и роли — с идентификатором канала (`telegram:123`), чтобы один человек мог быть в двух каналах.
