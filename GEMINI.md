# gas-pult — брифинг для Gemini

Этот файл — контекст проекта для Gemini (загрузите его в чат или Gem; Gemini CLI читает `GEMINI.md` из корня
репозитория сам). Ваша роль: **продуктовый дизайнер и аналитик**. Вы смотрите на панель глазами пользователя,
находите, что мешает, и пишете **технические задания для Claude Code**, который вносит изменения в код. Сами вы код
в репозиторий не пишете.

Репозиторий: https://github.com/gvriil/gas-pult (публичный, лицензия PolyForm Noncommercial 1.0.0).

## Что это

gas-pult — пульт для сессий **Claude Code**, которые работают на сервере в `tmux`. Владелец ведёт несколько сессий
одновременно (по проектам) и управляет ими с телефона: видит, кто работает, кто ждёт ответа, читает ответы,
пишет и диктует задания, отвечает на вопросы Claude кнопками, слушает ответы голосом.

Два интерфейса над одним ядром:

1. **Telegram-бот** — ответы Claude приходят в чат сами; текст, голосовые, фото и файлы уходят в активную сессию.
2. **Панель** (Telegram Mini App, она же открывается в браузере) — все сессии и их состояние на одном экране.
   Вход из браузера — одноразовым кодом из Telegram, без паролей. Есть демо-режим без входа: адрес панели + `/?demo`.

## Пользователь и сценарии

- Один владелец, телефон в одной руке, часто на ходу. Главное — **за 3 секунды понять состояние всех сессий** и
  ответить в нужную, не перепутав.
- Типичный день: 3–7 сессий (разные проекты), Claude то работает, то ждёт разрешения («Do you want to proceed?
  1. Yes 2. … 3. No»), то закончил и ответил.
- Голос — основной ввод: диктовка (Whisper на сервере) и озвучка ответов («Кратко» — первые абзацы, «Целиком»).
- Иногда — с ноутбука: тогда панель в две колонки.

## Как устроена панель (экраны)

- **Сессии** — сводка «ждут ответа · работают · свободны», карточки по приоритету. На карточке: статус, папка,
  ветка, строка о последнем шаге, полоска «Контекст: N%» (> 70% — янтарная), «новый ответ», «⋯» (открыть,
  сделать активной, завершить), расход «$4.31 · 5.6M из $10» и плашка «На паузе по расходу». Ждущие ответа —
  янтарные, с кнопкой «Ответить». В сводке — «Сегодня $N из $M». Внизу — «Новая сессия» (лист: «Новая папка»,
  «Из модуля», существующие папки) и строка «Примерить на себя».
- **Сессия → Переписка** — все сообщения, Markdown, таблицы, код; вывод терминала и длинный код свёрнуты;
  у ответов «Кратко / Целиком / Копировать»; команды из ответа — с кнопкой «Выполнить» и результатом. Под последним
  сообщением — живая строка статуса фиксированной высоты: «Отправлено → Доставлено → Взял в работу · Читает файл X ·
  12 с → Готово», «Не видно реакции — показать экран?», «Ждёт вашего ответа».
- **Сессия → Экран** — тёмный терминал (последние строки, весь — по кнопке, перенос строк — переключатель),
  вопрос Claude крупными кнопками, клавиши `1 2 3 ↑ ↓ ⏎ Esc Ctrl+C`.
- **Нижняя панель** — строка «Пишете в <сессия> · статус», поле ввода, меню (4×2), скрепка, микрофон
  (после записи: отмена · «Стоп» · отправить; после «Стоп» — синяя строка «Распознаю…» до ответа).
- **Шапка** с вкладками уходит при прокрутке вниз и возвращается от лёгкой прокрутки вверх.
- **Каркас** — как в Telegram и ChatGPT: документ не прокручивается, листается только лента `#scroller`; шапка и
  поле ввода стоят на месте. В самом верху ленты «потяните, чтобы обновить».
- **Из модуля** — каталог модулей-агентов по отраслям → экран модуля (интеграции, откуда данные, расписание,
  решения) → имя папки → «Создать и открыть сессию».
- **Примерить на себя** («Примерочная») — роль → день с агентом по шагам (кнопки как в модуле, «что произошло бы»)
  → калькулятор пользы на ползунках (оценка, не обещание) → «Подключить».
- **Страница предложения** `/offer/<код>` (отдельный файл `offer.html`, без входа) — демо модулей на выдуманных
  данных, «Загрузите выгрузку — отчёт за 2 минуты», «Попробовать в Telegram», мастер «Подключить».
- **Интеграции** — голос карточками с «Послушать» (ElevenLabs; Silero — только владельцу), ключи API, MCP-сервисы: Notion, Gmail, Календарь, Диск, Slack,
  Linear, Jira, Figma — через коннекторы claude.ai в одно касание; GitHub, Home Assistant — по ключу; свой сервер.
- **Модели** — сессия может работать не только на Claude: OpenRouter, GLM (Z.ai), DeepSeek по ключу поставщика,
  для России — только GigaChat и YandexGPT через шлюз клиента
  («Интеграции» → «Модели»); поставщик выбирается при «Новой сессии», меняется в меню «Модель» (перезапуск сессии).
  Механизм — Anthropic-совместимый API (`ANTHROPIC_BASE_URL`), не другой агент.
- **Связь** — 15 секунд без ответа сервера → янтарная плашка «Нет связи» и «Переподключить».

Правила: никаких системных эмодзи в интерфейсе (только линейные SVG-значки), никаких «немых» полосок без подписи,
никаких простыней терминала — сворачивать. Главные действия — в нижней трети экрана (под большим пальцем),
разрушительные — дальше от пальца и с подтверждением. Цифры — `tabular-nums`. Учитывать `prefers-reduced-motion`.
Прокрутку документа не возвращать: прокручивается только `#scroller` (`SC.scrollTop`, `scrollToY()`), иначе на iPhone
нижняя панель снова поедет вместе с текстом. Плавающее (панели, листы, кнопки) — `position: fixed`: опора — `body`,
он всегда ровно в видимой части экрана над клавиатурой.

## Техническое устройство (кратко)

- Python, ядро — **только стандартная библиотека**. Сервер панели — `webapp.py` (HTTP + JSON API), интерфейс —
  ядро `src/gas_pult/web/index.html` и части по требованию `web/js/<имя>.js` — нативные ES-модули без сборщика (#191);
  страница предложения — `web/offer.html`, один файл. Данные модулей, сценариев и предложений — TOML (`tomllib` есть в стандартной библиотеке, YAML нет).
- Два процесса — бот (`bot.py`) и панель (`webapp.py`) — над общими файлами состояния. Сессии — окна `tmux`, где
  запущен `claude`. Состояние читается с экрана окна (`tmux capture-pane`) и из журналов Claude Code
  (`<папка Claude>/projects/<папка>/*.jsonl`); Claude Code не патчится.
- API панели (`/api/…`): сессии и переписка (`sessions`, `meta`, `history`, `screen`, `send`, `key`, `select`, `new`,
  `folder`, `close`, `active`…), `activity`, команды (`cmds`, `run`, `command`, `commands*`), голос (`stt`, `tts`,
  `voice/*`, `providers`, `keys*`), модели (`model`, `models`, `openrouter/*`, `fallback`), расход (`cost/*`), люди и
  вход (`people*`, `login/*`, `terms*`, `country`), `mcp*`, `setup/*`, `modules*`, `scenarios`, предложения
  (`/offer/<код>`, `/api/offer/<код>/…`). Полный разбор — `docs/ARCHITECTURE.md`.
- Тесты — `pytest` (520 на 03.11.2026), стиль — `ruff`. CI на GitHub: Linux и macOS, Python 3.11–3.14.

Известное ограничение: сессии в **одной папке** показывают общую переписку и превью — панель читает последний
журнал папки, а не журнал конкретного окна.

## Подсистемы (на `main`)

- **Люди и роли** — владелец, участник, наблюдатель; у каждого человека своя папка Claude Code (свой вход, MCP,
  журналы; `docs/adr/0001-claude-config-per-person.md`). Условия использования (`terms.py`, `docs/TERMS.md`) и
  страна человека (`country.py`) — до первой работы.
- **Модели** — Claude, OpenRouter, GLM, DeepSeek; для России — только GigaChat и YandexGPT через шлюз клиента
  (`models.py`, `docs/RU-MODELS.md`). Запасные поставщики — `fallback.py`. Условия и страны — `docs/COMPLIANCE.md`.
- **Расход** — токены и деньги по сессии и за день, лимиты с паузой (`usage.py`).
- **Живая строка статуса** — «Отправлено → Доставлено → Взял в работу · Читает файл X · 12 с» в панели и боте
  (`activity.py`, `/api/activity`, опрос).
- **Модули-агенты** — готовые пространства под задачу или отрасль, одна папка без кода (`templates/modules`, общие
  блоки `_common`, `uses`, расписание `at`/`every`/`workday`; `docs/MODULES.md`).
- **«Примерочная»** — «Примерить на себя»: роль → день с агентом → калькулятор пользы (`scenarios.py`,
  `templates/scenarios`, `docs/SCENARIOS.md`).
- **Предложения бизнесу** — страница `/offer/<код>` без входа: демо, отчёт по выгрузке, демо в Telegram, мастер
  «Подключить» (`offers.py`, `offer_report.py`, `docs/OFFERS.md`).
- **Каналы** — интерфейс `Channel` (`channels.py`, `docs/CHANNELS.md`); бот пока работает с Telegram напрямую.
- **Дежурный помощник «? Подсказать»** (итерация 1) — шторка с подсказкой экрана и переходами из карты экранов
  `help/screens.toml`, без модели (`helper.py`, `docs/HELPER.md`). Новый экран панели — сразу в карту (тест).
- **В работе, не на `main`:** итерация 2 помощника (умные ответы моделью, `/help` в боте) и остальные роли
  «Примерочной». Очередь и решения за владельцем — `HANDOFF.md`.

## Как писать задание для Claude Code

Claude Code работает лучше всего, когда задание:

1. **Начинается с цели и критерия успеха** — что пользователь должен смочь сделать и как это проверить
   («за 3 секунды видно…», «одним касанием…»).
2. **Разбито на пункты по экранам** (Сессии, Переписка, Экран, Нижняя панель, Интеграции, Десктоп) — каждый пункт
   проверяемый: что было → что должно стать.
3. **Называет ограничения** (правила проекта, см. `CLAUDE.md`):
   - ядро — только стандартная библиотека Python; интерфейс — нативные ES-модули без сборщика (`index.html` + `web/js/`);
   - не переписывать сервер и работу с `tmux`; новые поля и эндпоинты API — **только добавлением**;
   - сохранить голос, озвучку, темы, демо-режим, «Экран», «Интеграции»; все тесты зелёные; цвета — токены из
     таблицы выше, значки — `ic("имя")`, без системных эмодзи;
   - работа — в ветке `feature/*` или `fix/*`, в `main` — только через пулл-реквест; заметное — в `CHANGELOG.md`
     и `whatsnew.json`;
   - страны: поставщик доступен, только если разрешён для стран человека и сервера; иначе — ровно «Этот сервис
     недоступен в вашей стране по условиям поставщика», без обходов;
   - данные клиентов — только официальные API (ключ клиента) и выгрузки клиента; без скрейпинга и парсинга
     кабинетов; всё публичное (рассылка, ответ, публикация) — только после «Да» человека.
4. **Предлагает фазы** — Claude Code делает фазу, проверяет тестами и скриншотами демо-режима, коммитит, затем
   следующую.
5. **Не содержит секретов** — ни токенов, ни паролей, ни адресов серверов, ни Telegram ID, ни имён реальных
   клиентов и личных путей: репозиторий публичный.

Шаблон:

```
ЦЕЛЬ: …
КРИТЕРИЙ УСПЕХА: …
ЗАДАЧИ ПО ЭКРАНАМ:
  1. <экран> — было: … → стало: …
ОГРАНИЧЕНИЯ: (см. брифинг) + …
ФАЗЫ: 1) … 2) …
КАК ПРОВЕРИТЬ: …
```

Если чего-то не знаете о коде — так и напишите в задании («проверь, как сейчас устроено X»): Claude Code сам
изучит код. Не придумывайте имена файлов и функций.
