# Коннектор amoCRM (`amocrm`)

**Статус: каркас, не проверено на песочнице.** Ответы в `tests/fixtures/amocrm/` собраны по примерам из официальной
документации API v4 (amocrm.ru/developers/content/crm_platform — `leads-api`, `leads_pipelines`, `tasks-api`,
`filters-api`, `error-codes`; `api/contacts`, `api/recommendations`; прочитано через Context7 23.11.2026). Данные
выдуманные. После появления токена тестового аккаунта ночной конвейер проверит доступ одним вызовом и заменит
fixtures обезличенными ответами.

Код — `src/gas_pult/connectors/amocrm_mcp.py`, тесты — `tests/test_amocrm_mcp.py`, контракт — `docs/CONNECTORS.md`.

## Что умеет

| Инструмент | Что делает | Метод API v4 |
|---|---|---|
| `amocrm_list_leads` | Сделки, новые сверху: название, бюджет, воронка и этап, «в работе / успех / провал», ответственный, ближайшая задача, теги, ссылка. Фильтры: воронка, этап (вместе с воронкой), «создана с», поиск | `GET /api/v4/leads` |
| `amocrm_get_lead` | Одна сделка: плюс id контактов и компании, причина отказа | `GET /api/v4/leads/{id}?with=contacts,loss_reason` |
| `amocrm_list_contacts` | Контакты, недавно изменённые сверху: имя, телефоны, почта, компания, ссылка. Поиск по имени, телефону или почте | `GET /api/v4/contacts` |
| `amocrm_list_pipelines` | Воронки и этапы по порядку: id, название, «неразобранное / в работе / успех / провал» | `GET /api/v4/leads/pipelines` |
| `amocrm_list_tasks` | Задачи, ближайший срок сверху: текст, тип (звонок, встреча, письмо), срок, просрочена ли, к какой сделке или контакту. По умолчанию невыполненные; `overdue=true` — только просроченные | `GET /api/v4/tasks` |
| `amocrm_propose_lead_status` | **Черновик** перевода сделки на другой этап её воронки (по id этапа или названию). Сам ничего не меняет | только чтение |
| `amocrm_apply` | Выполнить черновик после подтверждения человека и при `GAS_AMOCRM_WRITE=1` | `PATCH /api/v4/leads/{id}` (только `pipeline_id`, `status_id`) |

Списки — до 100 строк за вызов, постранично (`page`); есть следующая страница — в ответе поле `more`. Бюджет — как в
CRM (валюта аккаунта). Даты — ISO, московское время (+03:00): API отдаёт Unix-время без часового пояса аккаунта.
Пустой результат amoCRM отдаёт кодом 204 без тела — коннектор вернёт пустой список.

## Чего не умеет (и не будет)

- Создавать, удалять, объединять сделки, контакты, компании; менять бюджет, ответственного, поля, теги.
- Чаты и сообщения (amojo), звонки, рассылки, Salesbot, вебхуки, виджеты, права пользователей.
- Счета, оплаты, покупатели (customers), каталоги.
- Писать что-либо без черновика и подтверждения человека. Единственная запись — этап сделки внутри её воронки
  (перенос в другую воронку — нет).
- OAuth с обновлением токена (`refresh_token`): первая версия работает только с долгосрочным токеном.

## Как получить ключ (делает владелец)

1. Тестовый аккаунт: amocrm.ru → регистрация, пробный период. Есть ли у amoCRM отдельная песочница для
   разработчиков — в документации **не нашёл** (`integrations-market.md`: «технический аккаунт — нет данных»).
2. В аккаунте: amoМаркет → «Создать интеграцию» → внешняя (приватная) интеграция → вкладка «Ключи и доступы» →
   «Долгосрочный токен» (путь из `QUEUE.md`; в интерфейсе **не проверял**). Права интеграции — доступ к CRM.
   Токен действует от имени создавшего его пользователя и с его правами: для клиента — от отдельного сотрудника с
   правом только на чтение нужных воронок (и на изменение сделок, если нужна смена этапа). Срок токена
   выбирается при создании — записать дату в KeePassXC.
3. Записать JSON одной строкой — в KeePassXC `gastech.kdbx`, группа `mcp/amocrm`, и на сервер файлом
   `~/.config/gastech-mcp/amocrm.token` с правами 0600:
   `{"subdomain": "<поддомен из адреса https://<поддомен>.amocrm.ru>", "token": "<долгосрочный токен>"}`.
   Путь меняется переменной `GAS_AMOCRM_KEY_FILE`.
4. Токен — это пароль: кто его знает, читает CRM. Утёк — отозвать в настройках интеграции и создать новый.

Включить запись: `GAS_AMOCRM_WRITE=1` в `env` сервера (по умолчанию выключено). `GAS_AMOCRM_BASE` подменяет адрес
аккаунта (тесты; аккаунт Kommo на `*.kommo.com`).

## Лимиты (документация `api/recommendations`, `crm_platform/error-codes`)

- Не более 7 запросов в секунду на интеграцию и 50 на аккаунт. Коннектор держит 7 в секунду (`Throttle(7, 1)`).
- Превышение — 429 («лимит запросов, подождите»); многократное — блокировка аккаунта, 403 на любой запрос
  (коннектор пишет «нет прав или аккаунт заблокирован за превышение лимита»).
- Подписка закончилась — 402; чтение закрывается через 30 дней, запись — сразу.
- Списки — до 250 записей за запрос (коннектор берёт до 100). Документация предупреждает о блокировке при
  «бесконтрольном переборе всех данных» — не листать все страницы подряд без нужды.

## Не проверено (проверить на тестовом аккаунте)

- Поиск `query` помечен в документации «скоро будет признан устаревшим» — работает ли он для сделок и контактов.
- Фильтр `filter[is_completed]=0` у задач — в документации тип `bool`, в примере `filter[is_completed][]=1`.
- Ответ `PATCH /api/v4/leads/{id}` — по описанию метода (`id`, `updated_at`), без живого примера.
- Текст ошибки 401 — форма `application/problem+json` по документации, текст `detail` — не из документации.
- Ссылки `…/leads/detail/<id>` и `…/contacts/detail/<id>` — привычный формат веб-интерфейса, не из документации API.

## Сценарий

**Модуль `fitness-leads` («Заявки: ответ сразу и запись») + amoCRM.** Сейчас модуль берёт заявки из
`data/leads.csv` — если сайт и соцсети клуба пишут заявки в amoCRM, выгрузку делает менеджер. С коннектором:

1. Ночью и утром агент вызывает `amocrm_list_pipelines` (один раз — узнать id этапа «Неразобранное» / «Первичный
   контакт»), затем `amocrm_list_leads(pipeline_id, status_id, since=<вчера>)` — новые заявки без выгрузки.
2. Для первого ответа нужен контакт: `amocrm_get_lead(id)` → `amocrm_list_contacts(search=<телефон>)`; в тёплом
   списке — ссылка на сделку, менеджер открывает её одним нажатием.
3. Утренний «тёплый список» дополняется `amocrm_list_tasks(overdue=true)` — какие перезвоны просрочены.
4. Клиент записался на вводную — агент предлагает `amocrm_propose_lead_status(id, "Принимают решение")` → менеджер
   подтверждает кнопкой «Да» → `amocrm_apply`.

Оценка (не замер): выгрузка заявок из CRM и сверка просроченных задач — около 15–20 минут менеджера утром; с
коннектором — 1–2 минуты на просмотр тёплого списка. Замерить на первом клиенте с amoCRM.
