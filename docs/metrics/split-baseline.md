# Эталон перед разбиением пульта на модули — 12.11.2026

Решение владельца: «разбиение пульта на модули: по лучшим практикам и чтобы ничего не сломалось». Порядок: сначала
эталонные e2e-прогоны (телефон, ПК, Mini App) и замер загрузки, потом по одному модулю за PR; после каждого — тот же
прогон зелёный и замер «до/после». Точка отсчёта — `main` @ f91f373 (index.html одним файлом: 8361 строка, 855 КБ,
в gzip — 240 КБ; webapp.py — 3896 строк).

## Как повторить

```
/tmp/gp-venv/bin/python tests/e2e/run_all.py -j 2            # все сценарии; свой сервер демо на 127.0.0.1, гасится сам
/tmp/gp-venv/bin/python tests/e2e/measure_load.py --runs 7 --ref docs/metrics/split-baseline.json   # «было → стало»
```

- `run_all.py` запускает каждый `tests/e2e/*.py` отдельным процессом (кроме `ago_check` — его сверяет pytest, и
  самих инструментов): демо-сценарии — на адресе `…/?demo`, «живые» (`*_live.py`) поднимают настоящую панель со своим
  tmux и подставным claude. Ширины 390 и 1366, светлую и тёмную тему сценарии проходят сами; общая сетка экранов —
  `smoke_demo.py` (8 экранов × 390/1366 × светлая/тёмная), Mini App — `miniapp_demo.py` (новый: заглушка
  Telegram.WebApp с initData; ready/expand, кнопка «Назад» Telegram, цвета шапки из токена, openLink, showConfirm).
  Нестабильные (palette_demo, chat_keeps_place, stt_stream_demo, delete_live) при падении повторяются один раз.
- `measure_load.py` — настоящий сервер панели (`demo_server.py` → `focus_live.start`, заголовки как в бою), Chrome
  без окна, медиана 7 прогонов. Телефон 390 — процессор ×4 медленнее, сеть «4G» (задержка 60 мс, 9 Мбит/с);
  компьютер 1366 — без замедления. «cold» — новый профиль, «warm» — повторный заход в том же профиле. Внешние адреса
  (telegram.org, cdnjs) подменены пустым ответом. Цель: «home» — первая карточка сессии, «chat» — первое сообщение.
  Цифры JSON — `docs/metrics/split-baseline.json` (для `--ref`).
