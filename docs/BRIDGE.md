# Мост к браузеру пользователя

Пульт управляет браузером на вашем компьютере (Mac, Windows), где вы уже вошли в свои сервисы. Команды можно давать
с телефона и с компьютера. Основа — Playwright MCP в режиме `--extension` (Microsoft, Apache-2.0):
«Connect to a running browser instance (Edge/Chrome only). Requires the "Playwright Extension"» —
https://github.com/microsoft/playwright-mcp

## Как устроено

```
телефон / компьютер → пульт (сервер) ⇄ wss /api/bridge/ws ⇄ мост на вашем компьютере → Playwright MCP --extension → ваш Chrome/Edge
агент в окне пульта → gas-pult bridge-mcp (MCP «browser-local») → /api/bridge/rpc ↗
```

- Мост сам подключается к пульту (исходящее соединение): на компьютере не нужно открывать порты.
- Пара: одноразовый код (10 минут) → токен устройства. Токен хранится у вас в `~/.gas-pult-bridge.json` (0600), на
  сервере — только его хэш. Список и отзыв — панель → «Настройки» → «Компьютеры — ваш браузер».
- Банки и госуслуги выключены. Включает только пользователь у себя: `node gas-pult-bridge.mjs allow <домен>` — мост
  предупреждает, что правила сервиса могут запрещать автоматизацию.
- «Сохранить на компьютер» — инструмент `save_to_computer`: файл в папку Загрузки, без перезаписи.
- Подтверждение «да» перед отправкой, оплатой, удалением — правило агентов пульта, как для коннекторов.

## Руки на компьютере — уровень 1 (белый список)

Владелец 17.11: свободной командной строки на компьютере пользователя нет. Мост добавляет к инструментам браузера:

| Инструмент | Что делает | Ограничение |
|---|---|---|
| `list_dir` | файлы и папки (без скрытых) | только внутри домашней папки (realpath) |
| `open_app` | открыть программу | macOS, только `.app` из /Applications, /System/Applications |
| `screenshot` | снимок экрана, JPEG до 1600 px | macOS; нужно разрешение «Запись экрана» для Терминала |
| `save_to_computer` | файл в Загрузки | без перезаписи |

## Заметки, Напоминания, Календарь Мака (GAS-15)

**Статус: не проверено на живом Маке.** Скрипты JXA проверены только на подделке (`tests/test_bridge_apple.py`:
подменённый `osascript` и объекты «Заметок» и «Напоминаний»). Чужих программ не ставим: только `osascript` из macOS.

| Инструмент | Что делает | Запись |
|---|---|---|
| `notes_list` | папки и заметки: название, папка, когда изменена; `query` — поиск по названию и тексту | нет |
| `notes_get` | текст заметки по `id` (до 20000 знаков) | нет |
| `notes_create` | новая заметка: `title`, `body`, `folder` | только после «Да» |
| `reminders_lists` | списки напоминаний и сколько в них невыполненных | нет |
| `reminders_list` | напоминания: `list`, `query`, `include_completed`, срок | нет |
| `reminders_create` | новое напоминание: `title`, `list`, `due` (ГГГГ-ММ-ДД[TЧЧ:ММ], часы Мака), `notes` | только после «Да» |
| `mac_calendar_events` | события «Календаря» за период до 62 дней; повторяющиеся — по первому событию серии | нет |

Изменять и удалять заметки, напоминания и события мост не умеет. Точные повторы событий — коннектор iCloud
(`docs/connectors/calendar.md`, CalDAV с сервера, Мак не нужен).

**Запись — только после «Да» человека.** Проверяет сервер пульта, а не агент:
1. Агент вызывает `notes_create` (или `reminders_create`) без `draft` → пульт сохраняет черновик
   (`~/.local/state/gas-pult/confirm/mac/<id>.json`, 0600) и отвечает текстом «СОЗДАТЬ заметку «…» …». На Мак
   ничего не уходит.
2. Агент показывает текст человеку и команду `gas-pult bridge-confirm <id>`. Человек жмёт «▶️ Выполнить» в пульте —
   это его «Да».
3. Агент вызывает инструмент с `draft=<id>` → пульт берёт аргументы **из черновика** (не от агента), ставит отметку
   `_confirmed` и отправляет мосту. Черновик одноразовый, привязан к инструменту и компьютеру.
Без отметки пульта мост сам тоже не пишет. Отметку `_confirmed` от агента пульт отклоняет. Пространства клиентов:
подтверждает только владелец (команда — на сервере пульта).

**Права macOS — по одному, при первом обращении.** macOS спросит «“Терминал” хочет управлять “Заметками”» (потом —
«Напоминаниями», «Календарём»). Нажмите «OK». Нажали «Не разрешать» — включите вручную: меню Apple → «Системные
настройки» → «Защита и безопасность» → «Конфиденциальность» → «Автоматизация» → «Терминал» → включить «Заметки»,
«Напоминания», «Календарь». Мост отвечает этими шагами сам, если доступа нет (ошибка macOS -1743). Названия пунктов —
по macOS 11; в новых версиях: «Конфиденциальность и безопасность» → «Автоматизация». В интерфейсе **не проверял**.

Обновить мост на Маке: заменить файл `gas-pult-bridge.mjs` новой версией из репозитория и перезапустить
`node gas-pult-bridge.mjs`.

Каждый вызов — в журнале устройства. Окно «Мак <имя>» = обычная сессия Claude Code на сервере с MCP «browser-local»:
подтверждения — стандартные Claude Code. Claude Code на самом Маке не ставим: «macOS 13.0+»
(https://code.claude.com/docs/en/setup), а MacBook Pro 2014 — не новее macOS 11. Мост на Node 22 работает с macOS 11
(nodejs v22.x BUILDING.md: macOS x64 ≥ 11.0).

## Установка (Mac, Windows)

1. Node.js 22 или новее — https://nodejs.org (на Маке можно `brew install node`).
2. В Chrome или Edge — расширение «Playwright Extension» (ссылка — в README Playwright MCP).
3. Файл моста: `bridge/gas-pult-bridge.mjs` из этого репозитория — в любую папку.
4. Код пары: панель → «Настройки» → «Компьютеры — ваш браузер» → «Подключить компьютер» (или на сервере
   `gas-pult bridge-code --url https://<адрес панели>`).
5. На компьютере: `node gas-pult-bridge.mjs pair https://<адрес панели> <КОД>`, затем `node gas-pult-bridge.mjs`.

## Агенты пульта

Окно агента получает браузер пользователя как MCP-сервер:

```
claude mcp add browser-local -- gas-pult bridge-mcp
```

Несколько компьютеров — `gas-pult bridge-mcp --device <id>` (список — `GET /api/bridge/devices`).

## Браузер по фокус-ссылке (клиент, коллега)

Владелец 17.11: тот, кто открыл фокус-ссылку, может подключить **свой** браузер к **этой** сессии.

1. Владелец выпускает фокус-ссылку и в её окне нажимает «Разрешить подключить свой браузер».
2. Пользователь на фокус-странице: меню сессии → «Подключить браузер» → код и команда, как в «Компьютерах».
3. Его устройство помечено id ссылки (`bridge_devices.json`, поле `focus`).

Границы:
- `gas-pult bridge-mcp` узнаёт своё окно tmux (`TMUX_PANE`) и передаёт его серверу. Окно фокус-ссылки с «Браузер» —
  только устройства этой ссылки. Любое другое окно и вызов без окна — только устройства владельца.
- Фокус-пользователь видит и отзывает только свои устройства. Браузеры владельца ему не видны.
- Ссылка отозвана, истекла или сессия завершена — устройство не работает: проверка при подключении моста и при
  каждом вызове (`Panel.bridge_dev_ok`).
- Владелец видит устройство в «Компьютерах» с пометкой «фокус: <сессия>», может отозвать его и открыть журнал.
- Банки и госуслуги — выключены. Включает только хозяин компьютера у себя (`allow`).
- Подтверждение «да» перед отправкой, оплатой, удалением — как у всех агентов пульта.

Журнал: `bridge_log.jsonl` в папке данных (0600, 30 дней) — время, устройство, инструмент, адрес перехода, итог. Без
содержимого страниц и введённого текста. Владельцу — «Компьютеры» → устройство → «Журнал действий»
(`GET /api/bridge/log?id=`).

Честная оговорка: агенты всех окон работают от одного пользователя Linux. Граница между окнами держится на правилах
сервера (окно → устройства), а не на правах операционной системы. Агент, который сам прочитает секрет
`bridge-local.token` и подделает окно, обойдёт её. Для чужих людей — пространство (отдельный пользователь
Linux, docs/TENANTS.md, «Шаг 4б»): агент пространства не видит дом владельца и его секрет, а мост пространства
(`pult-tenant bridge`) отдаёт ему только устройства фокус-ссылок этого пространства.

## Не проверено

- Яндекс Браузер (на Chromium): работает ли расширение — проверить на компьютере пользователя.
- Телефон: iOS и Android не дают расширениям управлять вкладками браузера — для телефона браузер в облаке пульта
  (рабочий стол Ubuntu). Первоисточник Apple/Google не проверен.
