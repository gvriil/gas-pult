# Заказ из сообщения

1. **Кто и на когда**: ресторан — по отправителю/каналу из `data/customers.csv`; дата — «на завтра», «в пятницу»,
   иначе ближайший день доставки ресторана (`дни_доставки`). Не ясно — спроси человека, не угадывай.
2. **Позиции**: каждое упоминание → код прайса по `позиция` и `синонимы` (без учёта регистра, «рукола» = «руккола»).
   Два кандидата — спроси. Нет в прайсе — «не нашёл: <как написал шеф>».
3. **Количество и единицы**: «2 кг», «3 пучка», «5 лотков»; без единицы — единица прайса. «как обычно» — последний
   заказ ресторана из `orders/` (покажи, что взял). Меньше `мин_партия` — округли вверх и отметь.
4. **Наличие**: остаток минус уже подтверждённые на эту дату. Не хватает — замена из `замена` (если есть в остатке)
   или «нет».
5. **Сумма** = Σ цена × количество. Ресторан в стоп-листе — пометка.
6. **Файл** `orders/<дата>/<ресторан>.md`: исходное сообщение, таблица позиций (код, позиция, кол-во, ед, цена,
   сумма, пометки), статус `ждёт решения`.
7. **Вопрос** (до шести строк): «Заказ <ресторан> на <дата>: N позиций, <сумма> ₽. Нет: <позиция> → замена <…>?»
   — «Подтвердить», «Предложить замену», «Изменить», «Отклонить».

## Лист сборки (18:00)

Подтверждённые заказы на завтра → `orders/<дата>/PICK.md`: итог по позициям (сколько собрать), по ресторанам
(адрес, окно доставки), чего не хватает по остаткам. Неподтверждённые — списком и одним вопросом.
