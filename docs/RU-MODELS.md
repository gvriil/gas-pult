# Российские модели: GigaChat и YandexGPT

Для людей из России пульт открывает только два профиля — **GigaChat (через шлюз)** и **YandexGPT (через шлюз)**.
Claude, OpenRouter, GLM и DeepSeek для России закрыты, как и раньше (`docs/COMPLIANCE.md`). Здесь: что есть у
поставщиков, почему нужен шлюз, как его поднять, что в пульте работает на этих моделях и что нет, и что важно по
закону. Сравнение всех поставщиков (коннекторы claude.ai, веб-поиск, картинки, окно контекста) и ежедневный
автотест — [`PROVIDERS.md`](PROVIDERS.md).

Сверено с первоисточниками **02.11.2026**. Реальный шлюз и ключи поставщиков с пультом **не проверялись** — всё,
что ниже помечено «не проверено», нужно проверить на своей задаче до работы с клиентом.

## Итог в трёх строках

1. **Официального API, совместимого с Anthropic, нет ни у Сбера, ни у Яндекса.** У Yandex AI Studio — API,
   совместимый с OpenAI; у GigaChat — свой API и OAuth-токен. Claude Code говорит только на API Anthropic Messages.
2. **Честный путь есть: свой шлюз-переводчик у клиента, в России, с его ключом.** Для GigaChat — `gpt2giga`
   (открытый код, MIT, организация ai-forever на GitHub), для обоих — LiteLLM Proxy. Трафик идёт из России
   к российскому поставщику по его условиям — это не обход. Шлюз — забота клиента; в пульте — адрес шлюза и его ключ.
3. **Главный открытый вопрос — не модель, а сам Claude Code** (раздел «Claude Code — программа Anthropic»).
   До ответа юриста профили для клиентов в России не включайте.

## Что есть у поставщиков

| | GigaChat (Сбер) | YandexGPT (Yandex AI Studio) |
|---|---|---|
| API | свой REST (`/chat/completions` в своём формате) | совместимый с OpenAI: Chat Completions, Responses; свой REST и gRPC |
| Совместим с Anthropic (`/v1/messages`) | **нет** | **нет** |
| Вход | ключ авторизации → OAuth-токен **на 30 минут** (scope `GIGACHAT_API_PERS` / `_B2B` / `_CORP`); для TLS — корневой сертификат НУЦ Минцифры | API-ключ сервисного аккаунта или IAM-токен, ID каталога |
| Инструменты (tool use) | функции есть; через LiteLLM — «одна функция за запрос»; через gpt2giga параллельные вызовы — только GigaChat-2-Max на v2 | function calling в API, совместимом с OpenAI |
| Кто клиент | физлица; по корпоративным офертам — **российские** юрлица и ИП | клиенты Yandex Cloud по договору |
| Данные запросов | п. 6.4 корпоративной оферты: Сбер «не использует … Контент в собственных целях» | п. 5.4.1 условий AI Studio: запросы могут использоваться для отладки и обучения, **если не отключено логирование** (п. 5.5–5.6) — заголовок `x-data-logging-enabled: false` |

## Почему нужен шлюз

Claude Code шлёт запросы только в формате Anthropic Messages: `POST {ANTHROPIC_BASE_URL}/v1/messages` со
стримингом (SSE), блоками `tool_use` / `tool_result`, системным промптом и подсчётом токенов. Пульт запускает
сессию сторонней модели, подставляя `ANTHROPIC_BASE_URL` и ключ (`src/gas_pult/models.py`), — значит, по этому
адресу должен отвечать сервер, говорящий на языке Anthropic. Шлюз принимает запрос Claude Code, переводит его
в API поставщика и обратно. Токен GigaChat на 30 минут шлюз получает и обновляет сам по ключу авторизации
(в gpt2giga это делает SDK GigaChat) — в пульте только адрес шлюза и **ключ шлюза** (не ключ Сбера или Яндекса).

## Claude Code — программа Anthropic: вопрос к юристу

Модель можно сменить, а программа остаётся: Claude Code распространяется Anthropic, и его лицензия
([LICENSE.md](https://github.com/anthropics/claude-code/blob/main/LICENSE.md)) отсылает к
[Commercial Terms](https://www.anthropic.com/legal/commercial-terms), а они (раздел D.2) — к Supported Regions Policy,
где России нет. Используется ли «Сервис» Anthropic, когда Claude Code работает в России с моделью другого
поставщика и без запросов к Anthropic, — в условиях прямо не сказано. Это решает **владелец с юристом**, до
подключения первого клиента из России. Если ответ «нельзя» — профили не помогут: нужен другой агент
(открытый CLI, говорящий с API, совместимым с OpenAI), это отдельная доработка пульта.

Что пульт делает уже сейчас, чтобы из такой сессии ничего не уходило в Anthropic: в профилях стоит
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (без телеметрии, отчётов об ошибках и автообновления), вход
в аккаунт Claude не нужен. Обновлять Claude Code на таком сервере — вручную владельцем.

## Как клиент поднимает шлюз (в России, у себя)

Общие правила:

- шлюз — на сервере клиента **в России**; лучше на том же сервере, что пульт (`http://127.0.0.1:8090`), иначе —
  за HTTPS (nginx, Caddy);
- ключ поставщика — **клиента**, по его договору со Сбером или Яндексом; в пульт он не попадает;
- на шлюзе — свой ключ доступа (`GPT2GIGA_API_KEY` или `master_key` LiteLLM); его и вставляют в пульт;
- проверку TLS не отключать: для GigaChat — сертификат НУЦ Минцифры в доверенные (`GIGACHAT_CA_BUNDLE_FILE`
  или системное хранилище), а не `verify=False`.

### GigaChat через gpt2giga

[gpt2giga](https://github.com/ai-forever/gpt2giga) — прокси на FastAPI (MIT): принимает запросы в форматах OpenAI,
Anthropic и Gemini и шлёт их в GigaChat. В его [таблице совместимости](https://ai-forever.github.io/gpt2giga/api-compatibility/)
`POST /messages` (стриминг, локальные инструменты) — «поддерживается», `count_tokens` — «зависит от поставщика»,
пакеты и Files API — нет; в [инструкции для Claude Code](https://github.com/ai-forever/gpt2giga/blob/main/integrations/claude-code/README.md)
запись «Проверено: 26 июня 2026 — 2.1.187 (Claude Code)». Пример `.env` (значения — ваши):

```ini
GPT2GIGA_MODE=PROD
GPT2GIGA_HOST=127.0.0.1
GPT2GIGA_PORT=8090
GPT2GIGA_ENABLE_API_KEY_AUTH=True
GPT2GIGA_API_KEY=<длинный случайный ключ шлюза — его вставите в пульт>
GIGACHAT_CREDENTIALS=<ключ авторизации GigaChat API>
GIGACHAT_SCOPE=GIGACHAT_API_CORP          # или _B2B / _PERS — по вашему договору
GIGACHAT_VERIFY_SSL_CERTS=True
GIGACHAT_CA_BUNDLE_FILE=/путь/к/russian_trusted_root_ca.pem
```

Запуск — по [README проекта](https://github.com/ai-forever/gpt2giga) (`pip install gpt2giga` → `gpt2giga`, или Docker
Compose). Адрес для пульта — корень шлюза, без `/v1`: `http://127.0.0.1:8090`. Модели — `GigaChat-2-Max`
(основная) и `GigaChat-2-Lite` (быстрая), так в профиле по умолчанию.

### YandexGPT (и GigaChat) через LiteLLM Proxy

[LiteLLM Proxy](https://docs.litellm.ai/docs/anthropic_unified/) отдаёт `/v1/messages` в формате Anthropic для
любого своего поставщика, в том числе для API, совместимого с OpenAI
([`openai/` + `api_base`](https://docs.litellm.ai/docs/providers/openai_compatible)); у LiteLLM есть и
[поставщик GigaChat](https://docs.litellm.ai/docs/providers/gigachat) (там же: «одна функция за запрос»). Пример
`config.yaml` для YandexGPT — имена `model_name` должны совпасть с моделями профиля в пульте:

```yaml
model_list:
  - model_name: yandexgpt
    litellm_params:
      model: openai/gpt://<ID каталога>/yandexgpt/latest
      api_base: https://llm.api.cloud.yandex.net/v1
      api_key: os.environ/YANDEX_API_KEY
      extra_headers: {"x-data-logging-enabled": "false"}   # запросы не логируются и не идут в обучение
  - model_name: yandexgpt-lite
    litellm_params:
      model: openai/gpt://<ID каталога>/yandexgpt-lite/latest
      api_base: https://llm.api.cloud.yandex.net/v1
      api_key: os.environ/YANDEX_API_KEY
      extra_headers: {"x-data-logging-enabled": "false"}
general_settings:
  master_key: os.environ/LITELLM_MASTER_KEY               # ключ шлюза — его вставите в пульт
```

Запуск: `litellm --config config.yaml --host 127.0.0.1 --port 4000`; адрес для пульта — `http://127.0.0.1:4000`.
Не проверено: передача `extra_headers` и точные URI моделей в вашей версии LiteLLM и AI Studio — сверьте с их
документацией и проверьте одним запросом до подключения пульта.

### Подключить в пульте

1. В `config.toml` сервера — `region = "RU"` (сервер в России). Люди из России должны выбрать страну RU.
2. Панель → «Интеграции» → «Модели» → «GigaChat (через шлюз)» или «YandexGPT (через шлюз)» → «Адрес шлюза» →
   «Сохранить адрес»; ниже — «Ключ шлюза».
3. «Новая сессия» → папка → поставщик. Сессия запускается с `claude --settings …/profiles/<id>.json`: адрес
   и ключ — в файле 0600, в командной строке и tmux их нет.
4. Запасные: «Интеграции» → «Модели» → «Запасные» — только эти два профиля (Claude для России в цепочку не
   добавится). Шлюз не отвечает — пульт переключит на второй, если у него задан адрес и ключ.

Без адреса шлюза профиль не запускается: «не задан адрес шлюза … — „Интеграции“ → „Модели“». Это не отказ по
стране — страна проверяется отдельно, как у всех профилей.

## Что работает на этих моделях

«Да» — не зависит от модели. «С оговорками» — работает, если модель надёжно вызывает инструменты в формате Claude
Code; **на живом шлюзе не проверялось**. «Нет» — не работает или не предусмотрено.

| Функция пульта | GigaChat / YandexGPT | Почему |
|---|---|---|
| Бот в Telegram, панель, вход, роли, люди, страна | да | не зависят от модели |
| Окна tmux, «Новая сессия», «Сменить поставщика», перезапуск остановленной | да | пульт только запускает Claude Code с другим адресом |
| Варианты кнопками (меню и вопросы Claude Code), «Ждёт ответа», «Команды» | да | пульт читает экран Claude Code, а не ответ модели |
| Файлы в сессию (вложения из бота и панели) | да / с оговорками | файл кладётся на сервер; прочитать его модель должна сама инструментом |
| Голос на сервере (whisper — распознавание, Piper — озвучка) | да | работает на сервере, без модели |
| Голос ElevenLabs | решение владельца | зарубежный сервис; страна в пульте для него не проверяется, условия для России не сверены |
| Утренняя сводка | да | PR из GitHub (`gh`), окна tmux и `HANDOFF.md` — без модели |
| Запасные поставщики | да, только между этими двумя | для России других профилей нет |
| Ответ модели текстом, переписка | да | основной режим шлюза |
| Инструменты Claude Code: чтение и правка файлов, Bash, поиск | с оговорками | tool use у GigaChat и YandexGPT слабее, чем у Claude; через LiteLLM у GigaChat — одна функция за запрос, Claude Code часто вызывает несколько сразу |
| MCP-серверы на сервере | с оговорками | MCP — локальные инструменты Claude Code; то же ограничение tool use |
| Коннекторы claude.ai (Notion, Gmail…) | нет | они в аккаунте Claude, а вход в Claude таким сессиям не нужен и не делается |
| Субагенты и быстрая модель (haiku → «быстрая») | с оговорками | идут на быструю модель профиля (`GigaChat-2-Lite`, `yandexgpt-lite`) — у них tool use ещё слабее |
| Модели main/fast в панели | да | любые имена, которые знает шлюз |
| `/model`, `/compact` и прочие слэш-команды | да / с оговорками | команды — Claude Code; сжатие — запрос к модели |
| Сжатие контекста (автоматическое) | с оговорками | окно у этих моделей меньше, чем у Claude; Claude Code считает порог по своим правилам — при обрывах задайте меньший порог (`CLAUDE_CODE_AUTO_COMPACT_WINDOW`) |
| Длинный контекст `[1m]` | нет | режим Claude; суффикс в этих профилях убирается |
| Картинки и скриншоты | с оговорками / нет | GigaChat-2-Pro и -Max понимают картинки (в gpt2giga — `GPT2GIGA_ENABLE_IMAGES`), Lite — нет; YandexGPT через LiteLLM — только текст |
| Веб-поиск и загрузка страниц Claude Code (WebSearch, WebFetch) | с оговорками / нет | серверные инструменты Anthropic; gpt2giga переводит их во встроенные инструменты GigaChat v2, LiteLLM — нет |
| Размышления (thinking), кэш промптов | нет / не проверено | в документации шлюзов не описаны |
| Подсказка в строке ввода (серый текст) | с оговорками | её генерирует модель через Claude Code; может не появляться |
| Модули-агенты (сессии Claude Code с заданием) | с оговорками | то же, что сессии: зависят от tool use модели |

Практический совет: начните с GigaChat-2-Max через gpt2giga на v2 и простой задачи (прочитать файл, поправить
строку, запустить тест). Если модель путается в инструментах — режим «только переписка», без правки файлов.

## Законность и где данные

- **Не обход.** Трафик к модели: сервер пульта в России → шлюз в России → API российского поставщика, по договору
  клиента и с его ключом, страна не подменяется. Claude, OpenRouter, GLM, DeepSeek для России в пульте закрыты,
  и этот документ не описывает путей к ним.
- **Условия поставщиков.** Сбер: использовать сервис для своих продуктов можно, перепродавать сервис и передавать
  учётные данные (ключи) — нельзя (п. 2.2, 5.3.4 оферты). Яндекс: встраивать в свой продукт можно, перепродавать
  «простым вызовом» — нельзя (п. 1.2.2, 3.15 условий AI Studio). Агентные сценарии прямо не запрещены ни там, ни
  там; обход лимитов и квот — запрещён у обоих.
- **Где хранятся данные.** Переписка сессий — на сервере пульта (журналы Claude Code в папке Claude человека,
  `state.json`), в шлюзе (его журналы — настройте или выключите) и у поставщика: Сбер — «в облачной
  инфраструктуре» (п. 1.14, 6.3 оферты, место не названо); Яндекс — в Yandex Cloud, логирование запросов
  отключается заголовком.

## 152-ФЗ

Если в сессиях есть персональные данные граждан России (переписка клиентов, имена, телефоны в коде и файлах):

- **Локализация** (ст. 18 ч. 5): запись, хранение и накопление — в базах на территории России. Значит, для
  клиентов из России сервер пульта, шлюз и папки Claude Code — в России (`region = "RU"`).
- **Отдельное согласие** (ст. 9 ч. 1 в ред. 156-ФЗ от 24.06.2025, действует с 01.09.2025): согласие на обработку —
  отдельным документом, не внутри условий использования пульта (`docs/TERMS.md`). Отдельно — согласие на передачу
  поставщику модели.
- **Поручение обработки и трансграничная передача.** Поставщик модели обрабатывает данные по поручению — это
  должно быть в договоре (у Яндекса — п. 5.1–5.2, у Сбера по корпоративной оферте обработка ПДн клиентом «не
  осуществляется», п. 8.6 — уточнить). Telegram — зарубежный сервис: передача через него — трансграничная
  (ст. 12), с уведомлением Роскомнадзора.
- **Яндекс:** отключите логирование запросов (`x-data-logging-enabled: false`), если в запросах могут быть ПДн —
  так рекомендует сам Яндекс.

Это памятка, а не заключение: формулировки сверяйте с юристом и действующей редакцией закона.

## Как это устроено в коде

- `src/gas_pult/models.py`: профили `gigachat` и `yandexgpt` с `gateway: True` и `regions = {"RU"}`; адреса по
  умолчанию нет. Адрес шлюза — `state.json` → `model_profiles[<id>].base_url` (`set_models(..., base_url)`), ключ
  шлюза — `secrets.json` (как у всех ключей). `command()` без адреса — ошибка «не задан адрес шлюза».
- API (только добавлением): `POST /api/models` принимает `base_url`; у профилей в `/api/meta` новые поля
  `gateway`, `base_url`, `guide`, `regions`, `not_ready`.
- `src/gas_pult/fallback.py`: запасной без адреса шлюза пропускается («нет адреса шлюза»); для России в цепочку
  попадают только разрешённые для России профили.
- Тесты — `tests/test_ru_models.py` (без сети, без tmux и без настоящего Claude Code).
