# Яндекс Метрика — коннектор пульта

Код — `src/gas_pult/connectors/metrika_mcp.py`, тесты — `tests/test_metrika_mcp.py`, контракт — `docs/CONNECTORS.md`.
Документация API — https://yandex.ru/dev/metrika/ru/ . Методы и примеры сверены 22.11.2026 по индексу Context7
`/websites/yandex_ru_dev_metrika_ru` (страницы intro/authorization, intro/quotas, intro/quick-start,
management/openapi/counter/counters, management/openapi/goal/goals, stat/openapi/data_1, stat/examples, stat/localize).

**Статус: каркас, не проверено на песочнице.** Песочницы у Метрики нет. Ключа ещё нет.

## Что умеет (только чтение)

| Инструмент | Что делает | Метод API |
|---|---|---|
| `metrika_list_counters` | Счётчики по ключу: id, название, сайт, статус, права (own/edit/view) | `GET /management/v1/counters` |
| `metrika_get_summary` | Сводка за период (по умолчанию — вчера): визиты, посетители, просмотры, отказы, время на сайте, доля новых; изменение к прошлому периоду той же длины, % | `GET /stat/v1/data` (2 запроса) |
| `metrika_list_days` | Визиты, посетители, просмотры по дням (по умолчанию 7 дней, не больше 92) | `GET /stat/v1/data`, `dimensions=ym:s:date` |
| `metrika_list_sources` | Источники трафика: поиск, прямые заходы, реклама, ссылки, соцсети | `GET /stat/v1/data`, `dimensions=ym:s:lastTrafficSource` |
| `metrika_list_goals` | Цели счётчика и их достижения за период, конверсия % (до 10 целей) | `GET /management/v1/counter/{id}/goals` + `GET /stat/v1/data` |

- Даты — ГГГГ-ММ-ДД, в часовом поясе счётчика (так считает Метрика).
- Отчёты запрашиваются с `accuracy=full` (без выборки). Если Метрика всё же посчитала по выборке — в ответе поле
  `sampled`. Если Метрика скрыла часть данных (мало визитов) — поле `privacy`.
- Счётчик — параметр `counter` или поле `counter` в файле ключа. `metrika_list_counters` работает без него.

## Чего не умеет (и не будет)

- Создавать, менять, удалять счётчики, цели, фильтры, метки.
- Выдавать доступ к счётчику (представители, гостевой доступ).
- Logs API (сырые визиты) и загрузку офлайн-конверсий и расходов. Добавим, если понадобится модулю.
- Персональные данные посетителей не запрашивает: только сводные цифры.

Записи у коннектора нет: инструментов `propose`/`apply` нет, все запросы — `GET`.

## Ключ

Файл `~/.config/gastech-mcp/metrika.token` (права 0600), путь меняется `GAS_METRIKA_KEY_FILE`:

```json
{"token": "<OAuth-токен>", "counter": "<id счётчика>"}
```

Можно положить только токен одной строкой — тогда счётчик передаётся параметром `counter`.

Как получить (делает владелец или клиент — хозяин счётчика; шаги в интерфейсе **не проверял** — по документации
Яндекс OAuth и описанию в очереди):

1. Откройте https://oauth.yandex.ru и создайте приложение («Создать приложение» → для доступа к API).
2. В правах выберите только «Яндекс Метрика: получение статистики, чтение параметров своих и доверенных счётчиков»
   (`metrika:read`). Права на запись не давайте.
3. Получите отладочный токен для своего аккаунта (страница приложения → отладочный токен).
4. Номер счётчика — в интерфейсе Метрики (рядом с названием) или через `metrika_list_counters`.
5. Сохраните в KeePassXC `gastech.kdbx`, группа `mcp/metrika`, и положите файл на сервер с правами 0600.

- Токен боевой: песочницы нет. Поэтому — только право `metrika:read`.
- Счётчик клиента: клиент выдаёт вашему аккаунту Яндекса гостевой доступ «только просмотр» в настройках счётчика,
  либо токен делает сам клиент.
- Заголовок авторизации — `Authorization: OAuth <токен>` (не `Bearer`).

## Лимиты

intro/quotas: 30 запросов в секунду с одного IP; 3 параллельных и 5000 в сутки на пользователя; к отчётам
`/stat/v1/data` — 200 за 5 минут. Коннектор держит не больше 3 запросов в секунду (`Throttle(3, 1)`). Ответ 429 ядро
переводит в понятную ошибку.

## Сценарий

**Модуль `morning-numbers` + сайт клиента.** Каждое утро агент вызывает `metrika_get_summary` (вчера к позавчера)
и `metrika_list_goals` (заявки и звонки за вчера). Цифры «визиты, заявки, конверсия» идут в сводку рядом с планом
из `plan.csv`. Отклонение больше порога — `metrika_list_sources`, чтобы показать, какой источник просел
(например, «реклама −40 %»). Решения о рекламе принимает человек.

**Оценка «минут до/после» (не замерено, оценка):** открыть Метрику, выбрать период, переписать визиты и цели
в таблицу — ~10 мин в день → готовая строка в утренней сводке без действий человека. Замерить на первом клиенте
с сайтом.
