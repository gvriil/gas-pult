# Хранение служебных данных: JSON → SQLite

Решение владельца 22.11: служебные данные пульта переходят с файлов JSON на SQLite — малыми PR, с откатом.
Условия: перед переходом — копия JSON; на время перехода — запись в обе системы; вернуться к JSON — одним флагом;
замер до и после.

Код — `src/gas_pult/sqlstore.py`; подключение к общим `store.load` / `store.save` — `src/gas_pult/store.py`.

## Порядок модулей

| Шаг | Модуль | Файлы | Статус |
|---|---|---|---|
| 1 | люди | `people.json`, `terms.json`, `countries.json`, `prefs.json`, `emails.json`, `tours.json`, `ui.json` | этот PR |
| 2 | сессии | — | дальше |
| 3 | фокус-ссылки | `focus.json` | дальше |
| 4 | приглашения | `invites.json` | дальше |
| 5 | задачи | — | дальше |
| 6 | события | — | дальше |

Модуль переводится добавлением его файлов в `sqlstore.COLLECTIONS`. Остальные файлы при любом режиме живут в JSON.

## Режимы

Ключ `storage` в `~/.config/gas-pult/config.toml` (переменная `GAS_PULT_STORAGE` важнее — для тестов и замера).
Службы видят смену режима без перезапуска: файл настроек перечитывается, когда меняется.

| Режим | Читаем | Пишем | Для чего |
|---|---|---|---|
| `json` (по умолчанию) | JSON | JSON | как было до перехода |
| `dual` | JSON (источник истины) | JSON, затем SQLite — под тем же замком | проверка перехода: `verify` должен быть чистым |
| `sqlite` | SQLite | только SQLite; JSON остаётся последней копией | после проверки dual |

- **Ошибка SQLite в dual** запись не ломает: JSON записан, в журнале службы — `storage: … запись в SQLite не удалась`.
- **Расхождение в dual** (JSON поменяли мимо пульта или пульт работал в json): при следующей записи — предупреждение
  `storage: … расхождение` и SQLite выравнивается по JSON.
- **Замок** (`store.locked`, flock) — во всех режимах: он держит «прочитать → изменить → записать» целиком.

## Откат и защита от потерь

- Откат — `gas-pult storage disable` (или руками `storage = "json"`). В режиме sqlite каждая запись ставит рядом с
  JSON отметку `.<имя>.sqlite-only`; режим json или dual, увидев её, сначала выгружает SQLite в JSON. Поэтому откат
  одним флагом ничего не теряет, даже без команды.
- Обратно в sqlite после работы в json: JSON, изменённый мимо SQLite (подпись «время изменения:размер» не совпала с
  запомненной), переносится в SQLite заново.
- Копия JSON — `<данные>/backup/json-<дата>/` (папка 0700, файлы 0600): снимается автоматически один раз — при
  `storage enable` или при первом обращении к SQLite, если флаг поставили руками. Ещё одна — `gas-pult storage backup`.

## Устройство базы

- Файл `<данные>/pult.sqlite3`, права 0600 (и `-wal`, `-shm`).
- `journal_mode=WAL` — читатели не ждут писателя (бот и панель — разные процессы).
- `synchronous=FULL` — та же гарантия, что у JSON сейчас (`write_private` делает fsync): записанное переживает
  отключение питания. В WAL это один fsync на транзакцию; при нашей частоте записи цена — доли миллисекунды (замер ниже).
- `busy_timeout` — 10 с.
- Схема — по номеру `PRAGMA user_version`, шаги — список `SCHEMA`; новый шаг — добавлением в конец.
- Таблица `kv(collection, key, json, updated)`: коллекция — имя файла, ключ — ключ верхнего уровня (Telegram ID),
  значение — запись как в JSON. Почему не таблицы с колонками: файлы пульта — словари записей; такой вид повторяет их
  один в один — один код на все шесть модулей, сверка с JSON — построчно, откат — простая выгрузка, новое поле записи
  не требует миграции. Пишутся только изменённые строки. Колонки и индексы — потом, шагом схемы, когда понадобится
  запрос, а не чтение всего файла.
- `collections(name, version, json_sig, imported)` — версия схемы файла (как `.<имя>.v` у JSON) и подпись JSON на
  момент последней сверки; `meta` — где лежит копия JSON.

## Команды

```
gas-pult storage status            # режим, база, строки по файлам, копия
gas-pult storage enable dual       # копия JSON (один раз) → перенос в SQLite → storage = "dual"
gas-pult storage verify            # JSON и SQLite: совпадают ли (для dual)
gas-pult storage enable sqlite     # после чистого verify в dual
gas-pult storage disable           # обратно в json: новое из SQLite → JSON, storage = "json"
gas-pult storage backup            # ещё одна копия JSON
```

`enable` и `disable` правят только строку `storage` в config.toml — комментарии и секции остаются.

## Замер (22.11.2026)

`tools/bench-storage.py --dir <папка на диске>`: 1000 людей в people.json — `add`, затем `role` и `seen` каждому
(среднее на операцию); гонка — 2 процесса × 200 записей. ВМ: 6 ядер, ext4, Python 3.14.4.

| Режим | add, мс | role, мс | seen, мс | Гонка: дошло | Гонка, с |
|---|---|---|---|---|---|
| json (до) | 1.68 | 0.34 | 2.18 | 400 из 400 | 0.6 |
| dual | 3.38 | 0.34 | 4.64 | 400 из 400 | 1.4 |
| sqlite | 2.47 | 1.08 | 3.61 | 400 из 400 | 0.9 |

До `store.py` (замер 22.11, без межпроцессного замка) гонка давала 229 из 400.

Вывод: dual — примерно вдвое дороже записи JSON (пишет обе системы), чтение не меняется. В sqlite запись дороже JSON
на ~0,8–1,4 мс, чтение `role` — 1 мс вместо 0,3: каждый вызов читает всю коллекцию, как и с JSON, но разбирает каждую
запись отдельно. На 1000 людей это незаметно человеку; выигрыш SQLite — в следующих шагах (запрос одной записи вместо
чтения файла целиком, события и задачи без переписывания всего файла).
