# Как помочь проекту

Спасибо, что хотите улучшить gas-pult! Ошибки и идеи — в [issues](https://github.com/gvriil/gas-pult/issues),
код — пулл-реквестом.

## Окружение

```bash
git clone https://github.com/gvriil/gas-pult && cd gas-pult
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/pre-commit install   # необязательно: ruff + gitleaks перед каждым коммитом
```

Проверить вживую, не трогая основной пульт: заведите отдельного тестового бота и отдельные каталоги.

```bash
export GAS_PULT_CONFIG_DIR=/tmp/pult-cfg GAS_PULT_DATA_DIR=/tmp/pult-data
gas-pult init && gas-pult run
```

У одного токена может быть только один процесс, читающий `getUpdates`. Не запускайте второй пульт на боевом боте.

## Правила

- **Ядро — только стандартная библиотека.** Тяжёлое (голос, модели) — в extras и в отдельном процессе
  `python -m gas_pult.voice`.
- **Тесты на логику.** Разбор транскриптов, команд и настроек покрыт `pytest`. Новая логика — с тестом.
  Telegram и tmux в тестах не нужны.
- **Боевой tmux тесты не трогают.** Настоящий tmux — только свой сервер по короткому сокету: `tmux -S /tmp/gp-XXXX/s`
  (в коде — `Tmux(session, socket=…)` или `GAS_PULT_TMUX_SOCKET`; фикстура `tmux_socket` в `tests/test_integration.py`).
  `TMUX_TMPDIR` с длинным путём не годится: сокет не помещается (~104 знака), и tmux уходит на сервер по умолчанию —
  так 31.10 `kill-server` из проверки закрыл все окна владельца. `kill-server`/`kill-session` без `-S` тест не пропустит.
  Остальные тесты автоматически смотрят на пустой сокет (`tests/conftest.py`).
- **Стиль.** `ruff check .` без ошибок, строка до 120 знаков. Комментарии короткие, по делу, по-русски.
  Интерфейс бота — на русском.
- **Никаких секретов.** Ни токенов, ни Telegram ID, ни личных путей в коде, тестах, issues и скриншотах.
- **Коммиты.** Одно изменение — один коммит, сообщение в повелительном наклонении («Добавить голос …»).
  Заметные изменения — в `CHANGELOG.md`, раздел «Не выпущено».

## Ветки и выпуск

- `main` — рабочая стабильная версия: CI зелёный, панель и бот запускаются. Прямо в `main` не коммитим.
- Работа — в ветке `feature/<коротко>` (или `fix/…`), пулл-реквест в `main`. CI гоняет `ruff` и `pytest` на Linux
  и macOS (Python 3.11–3.14); сливаем, когда всё зелёное.
- Выпуск: раздел «Не выпущено» в `CHANGELOG.md` → `## [X.Y.Z] — дата`, версия в `src/gas_pult/__init__.py`, тег
  `vX.Y.Z` — GitHub Actions соберёт пакет и создаст релиз.

## Панель: как проверить изменения

Интерфейс — один файл `src/gas_pult/web/index.html` (HTML, CSS и JS без сборки), сервер — `webapp.py`.

```bash
gas-pult webapp --port 8797          # локально, без Telegram
```

Откройте `http://127.0.0.1:8797/?demo` — демо-режим: те же экраны на примерах, сервер и сессии не трогаются.
Параметры демо для проверки и скриншотов: `theme=light|dark`, `open=@1|@2|@3` (работает · ждёт ответа · свободна),
`view=integrations|login`, `terms` (экран условий использования), `menu=1`, `files=1`, `expand=1` (развернуть логи), `mic=1` (запись), `offline=1`
(обрыв связи, плашка через 15 с), `conn=notion`, `form=github`, `noscroll`.

- Ширина 390 px (телефон) и 1366 px (две колонки), светлая и тёмная тема; консоль браузера без ошибок.
- Цвета — только токены `--bg-*`, `--text-*`, `--status-*`, `--accent-*` из начала `<style>`; значки — `ic("имя")`
  (линейные SVG), системные эмодзи в интерфейсе не используем.
- Изменили поведение — добавьте пункт в `whatsnew.json` (панель покажет «Что нового») и строку в `docs/MINI_APP.md`.
- Скриншоты для README — из демо-режима, 390×800, в `docs/img/`.
- Новое поле в API — только добавлением (старый интерфейс не должен сломаться).

Задания на доработку удобно готовить с Gemini — контекст проекта для него в [`GEMINI.md`](GEMINI.md).
