панель шесть раз ответила 502 на `/api/projects`, а CI `main` был красным семь слияний подряд — никто не узнал.

## Что сделано

| Сбой | Что делает пульт | Кто узнаёт |
|---|---|---|
| Исключение в обработчике панели | Ответ `500` `{"error": "внутренняя ошибка", "code": "server_error", "id": "<8 знаков>"}` вместо обрыва (Caddy отдавал 502). Событие `server_error` (`path` без query, `exc` — класс исключения, `id`) — в `<данные>/chat-events.jsonl`. Трассировка с тем же `id` — в журнал службы (`journalctl --user -u gas-pult-webapp`, строка `server_error <id> <путь>:`). Ловят `dispatch` и `handle_one_request` (то, что упало мимо `dispatch`). Обрыв со стороны человека (`ConnectionError`) — не сбой | Владелец — сводкой (ниже) |
| Ошибки панели и JS (`server_error`, `js_error`) | Бот раз в 5 минут (цикл `monitor`) читает новые события через `chatlog.Log.since` и шлёт одно сообщение на класс, **не чаще раза в 30 минут**. Пока рано — события копятся до следующей сводки. Первый запуск — только запоминает «отсюда», старое не шлёт. Состояние — `<данные>/alerts_state.json` | Владелец — `broadcast(kind="error")`: Telegram, телефон, почта — что он выбрал |
| CI `main` красный | Последний законченный push-прогон CI в `main` (`gh run list -b main -w CI -e push`; отменённые пропускаются), «красный с» — время первого красного прогона после последнего зелёного, задание — первое упавшее (`gh run view --json jobs`). Ответ `gh` держится 5 минут. Проверка — только при запуске из исходников (рядом есть `.git`) | Брифинг: строка «CI main красный с <время>: <задание>» в блоке «Не выполнено — и почему» (источник GitHub). Вне брифинга — одно сообщение, если красный **дольше часа**, не чаще раза в 6 часов (бот, раз в 10 минут) |

Пример сводки: `⚠ Панель: ошибки сервера — 6 за 2 мин (/api/projects ×6; CalledProcessError)`.
В сводке нет текстов: маршрут — только `/api/…`, не больше трёх частей, части с цифрами, `@` или `:` — `*`; у
`js_error` — экран и тип, без текста ошибки и места.

## Признак жизни: для внешнего сторожа

- `<данные>/heartbeat-bot` — пишет цикл `monitor` бота (раз в ~3 с проходит, файл — не чаще раза в минуту). Цикл
  упал на исключении — отметка не обновится (ошибка каждого прохода — тоже повод проверить).
- `<данные>/heartbeat-web` — пишет панель на каждый ответ с кодом ниже 500, не чаще раза в минуту. Без запросов
  отметка стареет — это не сбой: панель проверяется ещё и запросом.
- Формат: одна строка `<время Unix> <время ISO>`, например `1763795400 2026-11-22T07:30:00`. Запись атомарная
  (временный файл и `rename`).
- `<данные>` — папка данных пульта (`GAS_PULT_DATA_DIR`, по умолчанию `~/.local/share/gas-pult`).

Как читать (сторож — вне репозитория, например `infra-watch`):

```bash
d=${GAS_PULT_DATA_DIR:-$HOME/.local/share/gas-pult}
age=$(( $(date +%s) - $(cut -d' ' -f1 "$d/heartbeat-bot") ))
[ "$age" -lt 180 ] || echo "бот: отметке $age с"
```

Панель: отметка `heartbeat-web` свежее 3 минут **или** локальный запрос отвечает (`curl --resolve …:127.0.0.1`).
Два сбоя подряд — сообщение через `gas-notify`: он шлёт в Telegram напрямую и работает, когда бот лежит.
