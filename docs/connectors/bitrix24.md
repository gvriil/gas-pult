# Коннектор Битрикс24 (`bitrix24`)

**Статус: каркас, не проверено на песочнице.** Ответы в `tests/fixtures/bitrix24/` собраны по примерам из официальной
документации REST ([github.com/bitrix24/b24restdocs](https://github.com/bitrix24/b24restdocs), коммит `30861a4` от
12.11.2026; сайт — apidocs.bitrix24.ru). Данные выдуманные. После появления вебхука демо-портала ночной конвейер
проверит доступ одним вызовом и заменит fixtures обезличенными ответами.

Код — `src/gas_pult/connectors/bitrix24_mcp.py`, тесты — `tests/test_bitrix24_mcp.py`, контракт — `docs/CONNECTORS.md`.

## Что умеет

| Инструмент | Что делает | Метод REST |
|---|---|---|
| `bitrix24_list_deals` | Сделки, новые сверху: название, стадия, сумма и валюта, контакт, ответственный, ссылка. Фильтры: стадия, воронка, «создана с», часть названия; по умолчанию только открытые | `crm.deal.list` |
| `bitrix24_get_deal` | Одна сделка: плюс вероятность, источник, комментарий (до 1000 знаков) | `crm.deal.get` |
| `bitrix24_list_leads` | Лиды (заявки), новые сверху: имя, статус, источник, есть ли телефон/почта, комментарий | `crm.lead.list` |
| `bitrix24_list_contacts` | Контакты: имя, телефоны, почта. Поиск по фамилии или по точному телефону | `crm.contact.list` |
| `bitrix24_list_stages` | Стадии воронки сделок по порядку: id, название, «в работе / успех / провал» | `crm.status.list` |
| `bitrix24_list_tasks` | Задачи, ближайший срок сверху: статус, срок, ответственный, связь с CRM. `overdue=true` — только просроченные | `tasks.task.list` |
| `bitrix24_propose_deal_stage` | **Черновик** перевода сделки на другую стадию (по id стадии или названию). Сам ничего не меняет | только чтение |
| `bitrix24_apply` | Выполнить черновик после подтверждения человека и при `GAS_BITRIX24_WRITE=1` | `crm.deal.update` (только `STAGE_ID`) |

Списки — до 100 строк за вызов (Битрикс24 отдаёт страницы по 50, коннектор делает не больше двух запросов). Если строк
больше — в ответе поле `more` и параметр `offset` для следующей страницы. Суммы — как в CRM, с полем `currency`.
Даты — ISO с часовым поясом портала.

## Чего не умеет (и не будет)

- Создавать, удалять, объединять сделки, лиды, контакты; менять суммы, ответственных, поля.
- Счета, платежи, телефонию, рассылки, открытые линии, права пользователей, вебхуки и приложения.
- Писать что-либо без черновика и подтверждения человека. Единственная запись — стадия сделки.
- Телефоны лидов (`list_leads` отдаёт только «есть телефон»): телефоны — через `list_contacts` после конвертации лида.

## Как получить ключ (делает владелец)

1. Демо-портал: [bitrix24.ru](https://www.bitrix24.ru/) → регистрация, пробный период тарифа с REST API. По документации
   (`_includes/system-errors.md`) REST есть не на всех тарифах; какие тарифы в РФ — **не проверял**. Без REST
   коннектор скажет «на тарифе портала REST API недоступен».
2. На портале: Разработчикам → Другое → Входящий вебхук (путь из `portfolio-hq/products/integrations-market.md`; в
   интерфейсе **не проверял**). Права: `crm`, `task`. Вебхук работает от имени создавшего его пользователя и с его
   правами — для клиента создавать от отдельного сотрудника с правом только на чтение нужных разделов (и на
   изменение сделок, если нужна смена стадии).
3. Скопировать адрес вебхука целиком (`https://<портал>.bitrix24.ru/rest/<id>/<код>/`) — одной строкой в KeePassXC
   `gastech.kdbx`, группа `mcp/bitrix24`, и на сервер — файлом `~/.config/gastech-mcp/bitrix24.token` с правами 0600.
   Путь меняется переменной `GAS_BITRIX24_KEY_FILE`.
4. Код в адресе — это пароль: кто его знает, читает CRM. Утёк — удалить вебхук на портале и создать новый.

Включить запись: `GAS_BITRIX24_WRITE=1` в `env` сервера (по умолчанию выключено). `GAS_BITRIX24_BASE` подменяет
схему и хост портала (тесты, коробочная версия за прокси); путь `/rest/<id>/<код>/` берётся из вебхука.

## Лимиты (документация `settings/performance/limits.md`)

- «Дырявое ведро» на портал: 2 запроса в секунду и запас 50 (Enterprise — 5 в секунду и 250). Превышение — ответ 503
  `QUERY_LIMIT_EXCEEDED`; коннектор держит 2 в секунду (`Throttle(2, 1)`) и пишет «лимит запросов портала».
- Ещё есть лимит «тяжести» метода — 429 `OPERATION_TIME_LIMIT`, снимается сам; коннектор пишет то же.
- Страница списков — всегда 50 записей.
- Фильтр по телефону — только точное совпадение (множественное поле). Поиск `%` не работает по стадиям и статусам.

## Не проверено (проверить на демо-портале)

- Методы `crm.deal.list`, `crm.status.list` помечены в документации как «развитие остановлено» (рекомендуют REST 3.0,
  `/rest/api/`). Работают ли они на новом портале через вебхук — проверить первым вызовом.
- Ссылка на задачу `…/company/personal/user/0/tasks/task/view/<id>/` — формат не из документации.
- Фильтр задач `<REAL_STATUS: 5` (открытые) и `STATUS: -1` (просроченные) — по описанию фильтра, без примера.
- Тело запроса JSON (`Content-Type: application/json`) для вебхука — в документации есть пример curl с JSON для
  `tasks.task.list`; для методов CRM — проверить.

## Сценарий

**Модуль `fitness-leads` («Заявки: ответ сразу и запись») + Битрикс24.** Сейчас модуль берёт заявки из
`data/leads.csv` — если сайт клуба пишет заявки в Битрикс24, выгрузку делает менеджер. С коннектором:

1. Ночью и утром агент вызывает `bitrix24_list_leads(status="NEW", since=<вчера>)` — получает новые заявки с сайта
   и из соцсетей без выгрузки.
2. Для первого ответа нужен контакт: `bitrix24_list_contacts(phone=…)` или ссылка на лид в тёплом списке — менеджер
   открывает его одним нажатием.
3. Утренний «тёплый список» дополняется `bitrix24_list_tasks(overdue=true)` — какие перезвоны просрочены.
4. Клиент записался — агент предлагает `bitrix24_propose_deal_stage(id, "Подготовка договора")` → менеджер
   подтверждает кнопкой → `bitrix24_apply`.

Связка с `client-alerts` и утренними сводками (`fitness-morning`, `morning-numbers`): `list_deals` по стадиям даёт
«сколько сделок и на какую сумму в работе».

**Оценка «минут до/после» (не замерено, оценка):** выгрузка заявок из CRM в CSV и загрузка в модуль — ~10 мин дважды
в день → 0 мин; перевод сделки по стадии после записи — ~1 мин (найти сделку, открыть, сменить) → одно нажатие.
Замерить на первом клубе с Битрикс24.
