# 0002. Интеграции не зависят от поставщика модели

Статус: принято · ноябрь 2026 · этап 1 — в работе, этап 2 — план

## Контекст

Сессия пульта может работать не на Claude, а на модели другого поставщика (OpenRouter, GLM от Z.ai, DeepSeek,
GigaChat и YandexGPT через шлюз — `models.py`). Проверка на GLM в Claude Code (ноябрь 2026) показала:

- работают `CLAUDE.md`, файлы и команды, MCP-серверы из настроек Claude Code (например, GitHub), WebFetch;
- **не работают коннекторы claude.ai** (Google Drive, Notion, Claude Docs и другие): «claude.ai connectors are disabled
  because ANTHROPIC_API_KEY or another auth source is set». Коннекторы приходят из аккаунта claude.ai, а сессия
  с чужим ключом (`ANTHROPIC_AUTH_TOKEN`) в этот аккаунт не входит;
- WebSearch молча возвращает пусто — это серверный инструмент Anthropic (у DeepSeek свой, он работает);
- нет PushNotification, RemoteTrigger, DesignSync — они тоже идут через аккаунт claude.ai.

До сих пор «Интеграции» панели предлагали в первую очередь коннекторы claude.ai. На подписке Claude это удобно
(вход в браузере, ничего не хранится на сервере), но как только владелец или клиент переходит на дешёвую модель,
интеграции молча пропадают.

Claude Code сам по себе — MCP-клиент: MCP-серверы из `mcpServers` в его папке (`CLAUDE_CONFIG_DIR`, у владельца —
`~/.claude.json`, у человека пульта — `<data>/people/<id>/claude`, ADR-0001) он запускает и вызывает одинаково,
какая бы модель ни отвечала. Вход по OAuth в такой сервер (Notion, Linear, Atlassian) хранится в той же папке и
действует для сессий любого поставщика.

## Решение

1. **Интеграция пульта — это MCP-сервер в папке Claude Code человека или пространства, а не коннектор claude.ai.**
   Коннекторы claude.ai остаются как удобство для сессий Claude по подписке, но в панели помечены «только Claude», и у
   каждого — кнопка замены «через сервер».
2. **Этап 1 — каталог в «Интеграциях»** (`mcp.PRESETS`, у каждого шаблона `providers: "all"`, в панели — раздел
   «Для любой модели» с отметкой «все поставщики»):
   - а) официальные удалённые серверы с OAuth (`claude mcp add-json … {"type": "http"}`), вход — «Войти» в панели
     (`/api/mcp/login` → ссылка с экрана `/mcp` → адрес страницы после входа — `/api/mcp/finish`):
     Notion (`https://mcp.notion.com/mcp`), Linear (`https://mcp.linear.app/mcp`), GitHub
     (`https://api.githubcopilot.com/mcp/`, токен), Atlassian (`https://mcp.atlassian.com/v1/mcp`), Google Диск
     (`https://drivemcp.googleapis.com/mcp/v1`, превью). У Google нет автоматической регистрации клиентов: нужен свой
     OAuth-клиент типа «Desktop app» в Google Cloud (включить Google Drive API и Drive MCP API); id клиента — в
     настройке сервера (`oauth.clientId`), секрет — `claude mcp add-json --client-secret` через `MCP_CLIENT_SECRET`
     (Claude Code хранит его в своём хранилище ключей, не в `.claude.json`). Сервер Google 04.11.2026 отвечает на
     `initialize` без входа и требует OAuth `accounts.google.com` для инструментов; доступ к превью может быть закрыт
     для аккаунта или проекта — панель так и пишет;
   - веб-поиск и Google Диск — **свои серверы пульта** (`base_mcp.py`, stdio, только stdlib; задача 48): «Веб-поиск»
     (Яндекс, Brave, Tavily, Exa — по ключу, ключ в файле 0600) и «Google Диск (rclone)» (свой `rclone.conf` у
     каждого, пути — только в папке сессии); для пространств — `pult-tenant mcp`. Сравнение сервисов и проверка
     на Claude, GLM и DeepSeek — `docs/PROVIDERS.md`. Шаблон удалённого Tavily убран: его заменяет «Веб-поиск»;
   - б) локальные stdio-серверы по ключу — **вторым шагом** (отдельный PR): Brave Search
     (`npx -y @brave/brave-search-mcp-server`, `BRAVE_API_KEY`), для России — Яндекс Search API, Google Диск через
     сервисный аккаунт (`npx -y @piotr-agier/google-drive-mcp`, `GOOGLE_APPLICATION_CREDENTIALS`) или rclone,
     Битрикс24 по вебхуку, 1С по OData, Notion по токену (`@notionhq/notion-mcp-server`, `NOTION_TOKEN`; Notion
     называет его устаревающим и советует удалённый). Ключи — в secrets человека или пространства (0600), сервер
     запускает сам Claude Code (`npx`/`uvx`), в систему ничего не ставится;
   - в) у каждой интеграции — отметка, на каких поставщиках она работает.
3. **Честная плашка.** У профиля модели — что не работает (`limits`), под вопросом (`unsure`), работает (`works`) и
   замена (`alt`) — `models.CAPS`, отдаётся в `/api/meta` добавлением полей. Панель показывает это при выборе
   поставщика, на экране поставщика и одной строкой над полем ввода сессии.
4. **Автотест поставщиков раз в сутки** (`selftest.py`): `claude -p` на каждом поставщике с ключом —
   кодовое слово из `CLAUDE.md`, список инструментов, вызов Read, WebFetch; итог — «Настройки» → «Поставщики».
5. **Профиль «claude» не меняется**: подписка, коннекторы claude.ai владельца работают как раньше, каталог только
   добавляется.

## Этап 2 — MCP-шлюз на пространство (план, без кода)

Когда клиентов (пространств) станет больше пяти, ключи и токены каждого клиента в его папке Claude Code станет
трудно вести: нет общего аудита, фильтра инструментов и шифрования. Тогда — самохостинговый MCP-шлюз на пространство:
сессия видит один MCP-адрес шлюза, шлюз хранит токены и проксирует вызовы.

| Критерий | IBM ContextForge (MCP Gateway) | Klavis Strata |
|---|---|---|
| Лицензия | Apache-2.0 | Apache-2.0 |
| Самохостинг | да: SQLite или PostgreSQL, Redis — кэш и сессии | да: `pipx install strata-mcp`; есть и облако Klavis |
| Шифрованное хранение токенов на человека | сохранённые учётные данные шифруются (`AUTH_ENCRYPTION_SECRET`), OAuth-токены — на пользователя; алгоритм и охват — проверить | в README не описано — проверить в коде до выбора |
| Аудит | OpenTelemetry (Jaeger, Tempo и др.), журнал в админке, кто вызвал — в заголовках | в README не описан |
| Фильтр инструментов | виртуальные серверы: свой набор инструментов из разных серверов; RBAC, вход через SSO | Strata на `user_id` с выбранными серверами; фильтр по инструментам — проверить |
| Постепенное раскрытие инструментов | нет: модель видит список виртуального сервера целиком | главная идея («optimize context window»): модель раскрывает инструменты по шагам — экономит контекст дешёвых моделей |

Источники (04.11.2026): [github.com/IBM/mcp-context-forge](https://github.com/IBM/mcp-context-forge),
[github.com/Klavis-AI/klavis](https://github.com/Klavis-AI/klavis). Пробелы «проверить» закрываем на пилоте.

Предварительный выбор: **ContextForge** — когда главное аудит, шифрование и разделение по командам; **Strata** —
если главным станет контекст дешёвых моделей. Решение — после пилота на двух пространствах, отдельным ADR.

**SaaS-шлюзы (Composio, Pipedream, Arcade) не подходят**: токены и данные клиентов (в том числе персональные данные
граждан РФ) уходят в облако за рубежом — это противоречит требованиям к хранению ПДн (152-ФЗ, локализация) и
обещаниям клиентам пульта.

## Картинки для моделей без зрения

GLM-5.3 — только текст, DeepSeek V4 Pro заменяет картинку на «[Unsupported Image]». План: свой MCP-инструмент
«опиши картинку» (`describe_image(path, вопрос)`), который отправляет файл модели со зрением (Claude по ключу, DeepSeek
Flash или другая — по выбору владельца) и возвращает текст. Модель без зрения вызывает его, когда видит путь к картинке
(панель и бот и так присылают путь к файлу). Реализация — следующим шагом, отдельно: нужно решить, чей ключ и чья
модель платят за описание, и не отправлять картинки клиентов поставщику без его согласия.

## Последствия

- Интеграции, подключённые через сервер, работают в сессиях любого поставщика; вход по OAuth — один раз на папку
  Claude Code человека.
- Ключи сервисов лежат на сервере пульта (в настройках Claude Code человека или в его хранилище ключей), а не в
  аккаунте claude.ai: владелец отвечает за их хранение; удалить — «Убрать» в «Интеграциях».
- Google Диск через официальный сервер требует своего проекта Google Cloud — это сложнее, чем коннектор claude.ai; для
  тех, у кого нет проекта, — сервисный аккаунт или rclone на втором шаге.
- Модули (`modules.py`), которые требуют коннектор claude.ai, на других поставщиках по-прежнему видят его как «не
  подключён»; перевод модулей на интеграции через сервер — отдельная задача.
- Откат: вернуть предыдущую версию пульта. Подключённые MCP-серверы остаются в настройках Claude Code и работают;
  убрать — `claude mcp remove <имя> -s user`.

## Отвергнутые варианты

- **Только коннекторы claude.ai**: не работают на других поставщиках — именно это и сломалось.
- **Свой прокси, который выдаёт себя за API Anthropic и возвращает коннекторы**: невозможно без аккаунта claude.ai и
  нарушало бы условия Anthropic.
- **SaaS-шлюз интеграций** (Composio, Pipedream, Arcade): см. выше — ПДн клиентов за рубежом.
