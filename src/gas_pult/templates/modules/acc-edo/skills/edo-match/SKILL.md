# Сверка ЭДО с первичкой

1. **Первичка** — `../acc-primary/registry/<клиент-id>/<ГГГГ-ММ>.csv` (путь — `primary` в настройках модуля);
   нет соседней папки — `data/primary-example/`. Формат — как у реестра acc-primary: `файл, вид, номер, дата,
   контрагент, инн_контрагента, сумма, ндс, статус`. Файлы первички только читаешь.
2. **Пара** для входящего: тот же клиент и месяц, `инн_контрагента` совпадает, номер совпадает (без пробелов и
   регистра, «№» не важен). Нет пары по номеру — ищи по ИНН + дате + сумме.
3. **Итог в колонку `сверка`:**
   - `совпало` — дата, сумма и НДС равны (±1 коп.);
   - `расхождение: <поле> ЭДО X / первичка Y` — что не так, по каждому полю;
   - `нет в первичке` — бумажного или сканового двойника нет (бывает: документ пришёл только по ЭДО);
   - `дубль` — такой входящий уже есть в реестре.
4. Сводка — по клиентам: всего, совпало, расхождений, нет в первичке. Расхождения и дубли — отдельным вопросом на
   документ («Принять как в ЭДО», «Черновик запроса исправления», «Отложить»).
5. «Черновик запроса исправления» — `document-draft` по `templates/fix-request.md` в `outbox/docs/`; отправляет
   человек сам, через оператора или почтой.
