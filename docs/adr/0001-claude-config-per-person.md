# 0001. У каждого человека пульта — своя папка Claude Code

Статус: принято · ноябрь 2026

## Контекст

Интеграции (MCP-серверы) панель добавляет командой `claude mcp add-json -s user`, а она пишет в общий
`~/.claude.json` пользователя, под которым работает пульт. Поэтому все люди пульта (владелец, участники) видят и
используют одни и те же интеграции, один вход в Claude и одни коннекторы claude.ai. Участник, подключивший свой Notion,
подключает его всем; владелец не может держать почту и задачи только у себя.

Claude Code берёт всё своё — вход, `.claude.json` с MCP, `settings.json`, журналы `projects/` — из папки
`CLAUDE_CONFIG_DIR` (по умолчанию `~/.claude` и `~/.claude.json`).

## Решение

- У каждого человека из `people.json` — своя папка `<data>/people/<Telegram ID>/claude` (права 0700), создаётся при
  первом обращении (`people.claude_dir`).
- Окно, которое человек открыл, запускается с `CLAUDE_CONFIG_DIR=<его папка>` (префикс команды). Кто открыл, пишется в
  опцию окна tmux `@gas_pult_by` рядом с `@gas_pult`; перезапуск и «продолжить» берут папку того, кто окно открыл, а не
  того, кто нажал кнопку. Окно без отметки — владельца.
- `/api/mcp*` и экран «Интеграции» работают с папкой того, кто вошёл в панель. Участнику экран открыт (только
  интеграции; модели, ключи и голос — по-прежнему владельцу). Своя программа (stdio) — только владельцу.
- Вход в MCP-сервис из панели (`/mcp` → Authenticate) идёт в свободной сессии этого же человека.
- Журналы сессий человека читаются из его папки (`<папка>/projects`).
- Владелец — как раньше: `~/.claude` без переноса и без переменной в окружении.

## Последствия

- Вход в Claude у каждого свой: в новой папке пусто, первая сессия человека покажет приветствие и вход (на «Экране»).
  Сессии с ключом другого поставщика (OpenRouter, GLM, DeepSeek) работают и без входа.
- Интеграции и коннекторы claude.ai человека переживают конец сессии — они в его папке, а не в окне.
- Общие настройки владельца (хуки, плагины, `CLAUDE.md` в `~/.claude`) в сессиях людей не действуют.
- Одно окно на проект осталось: если в папке уже работает чужая сессия, человек попадает в неё (с её интеграциями).
- Удалить человека из `people.json` — папку не удаляет; удалить её можно вручную.
- Откат: вернуть предыдущую версию пульта. Папки `<data>/people/` никому не мешают; окна с `@gas_pult_by` продолжат
  работать со своей папкой до закрытия, новые откроются с `~/.claude`.

## Отвергнутые варианты

- **Общие MCP с проектными scope** (`-s project`/`local`): делит интеграции по папкам, а не по людям; два человека
  в одной папке опять видят одно и то же, вход в Claude остаётся общим.
- **Отдельный пользователь Unix на человека**: настоящая изоляция, но нужны sudo, свои tmux, права на папки проектов
  и переписывание запуска окон — несоразмерно для пульта на одном сервере.
