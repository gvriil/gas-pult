# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [Не выпущено]

### Исправлено
- «Перезапустить» остановленную сессию из панели (`/api/revive`) снова работает: запрос раньше упирался в проверку «окна с Claude нет».

### Добавлено
- **Страна человека и списки стран поставщиков (allowlist).** Проверка регионов — по официальным спискам: у Claude и OpenRouter (модели Anthropic) — список Anthropic целиком (185 стран, сверено 01.11.2026, плюс их территории), у Z.ai и DeepSeek — их запреты и санкционные страны. Страна человека — по трём признакам (`country.py`): выбор при первом входе (бот — кнопками частых или кодом, панель — экран «Из какой страны вы работаете?» после условий; до выбора API отвечает `403 {"code": "country"}`), номер телефона в боте («📱 Поделиться номером», принимается только свой контакт; храним код страны и HMAC-SHA256 номера с солью установки, сам номер — нигде) и IP при каждом входе в панель (локальная база db-ip lite, без внешних запросов; IP не храним — только код и время). Доступно то, что поставщик разрешает для **каждой** из стран (и страны сервера); признаки расходятся — только пересечение и одна строка владельцам (имя/ID и коды стран). Проверка — при новой сессии, перезапуске, смене поставщика, тексте в сессию (панель и бот) и в цепочке запасных (по странам того, кто открыл окно, `@gas_pult_by`, иначе владельца). Отказ — ровно «Этот сервис недоступен в вашей стране по условиям поставщика». В «Людях» (панель и бот) — страна, код номера, страна по IP и пометка о расхождении. API добавлением: `GET/POST /api/country`, поле `country` в `/api/meta` и `/api/people`, `allowed`/`denied` у профилей. База — командой владельца `gas-pult geoip update` (IP Geolocation by DB-IP, CC BY 4.0); нет базы — признак IP «нет данных», не блокирует. Демо — `?demo&country`. Условия использования — версия 2026-11-02 (пункт «Ваша страна»): согласие спросят заново.
- **Запасной поставщик модели.** Поставщик сессии не ответил (401/403 — ключ или оплата, 429 — лимит, 5xx и «Overloaded» — сбой, таймаут и нет связи) — когда сессия остановилась на этой ошибке (не идёт ответ, нет вопроса, вы ничего не набираете), пульт сам перезапускает это же окно у следующего по цепочке с `--continue`: разговор продолжается. Владельцам — одна строка в Telegram («Поставщик OpenRouter не отвечает (429) — сессия «x» переключена на Claude»), в панели — та же строка. Цепочка — «Интеграции» → «Модели» → «Запасные» (порядок, добавить, убрать; `GET/POST /api/fallback`, хранится в `state.json` как `fallback_chain`); по умолчанию — базовый Claude. Не чаще раза на окно за 5 минут, на упавшего поставщика окно час не возвращается; список исчерпан — строка «запасных нет». Поставщик без ключа или не разрешённый для региона пропускается.
- **Регион сервера.** `region = "NL"` в config.toml: у профилей моделей — страны, где поставщик не поддерживается (`models.allowed`); Россия запрещена для всех, для Claude и OpenRouter (модели Anthropic) — ещё Китай. Запасной не для региона не выбирается никогда, в цепочку его не поставить.
- **Запасной голос.** ElevenLabs не ответил (ключ, лимит, сеть) — озвучка и распознавание сами переходят на локальные Piper и whisper, без ошибки. Панель пишет «ElevenLabs не ответил — распознал локально», запись — в журнал службы, последняя за час — `fallback` в `/api/providers`.
- **Выбор локального голоса в панели.** «Голос» → «На сервере» → список установленных голосов (Ирина, Дмитрий, Денис, Руслан…), выбор общий с ботом.
- **Условия использования и соблюдение условий поставщиков моделей.** `docs/COMPLIANCE.md` — политика (у каждого свой аккаунт или ключ, подписка Claude не делится и не перепродаётся, страны и поставщики — по их спискам поддерживаемых регионов, сервер и выход в интернет — в поддерживаемой стране; российские каналы MAX/VK — только с поставщиком, разрешённым для региона, не Claude), официальные страницы Anthropic, OpenRouter, OpenAI, Google, Z.ai, DeepSeek (сверено 01.11.2026) и чек-лист владельца. `docs/TERMS.md` — условия для людей пульта (черновик, на проверку юристу). При первом `/start` (и любом действии до согласия) бот показывает условия и «✅ Принимаю»; панель при первом входе — экран условий, до согласия остальное API отвечает `403 {"code": "terms"}` (`GET /api/terms`, `POST /api/terms/accept`, поле `terms` в `/api/meta`). Согласие с версией и датой: у человека — `terms` в его записи `people.json`, у владельцев — `terms.json` (0600). Новая версия (`terms.VERSION`) — согласие заново. Вход в панель через Telegram (`/start login_…`) не задерживается.
- **«Отключить человека».** Панель: «Настройки» → «Люди» → человек → «Отключить» (было «Убрать доступ»), с подтверждением; в списке — приняты ли условия и когда. Бот: ⚙️ Настройки → 👥 Люди → «⛔ Отключить» → «Да, отключить». Роль и согласие удаляются, любой вход человека перестаёт работать сразу.
- **Широкий экран: список сессий тянется, сворачивается, шрифт меняется.** На экране от 1024 px список слева можно тянуть мышью за край (200–480 px; стрелки на ручке — по 16 px, Shift — по 48; двойной щелчок или Enter — 340 px по умолчанию). Кнопка в углу списка сворачивает его в полосу 56 px: у каждой сессии кружок с первой буквой имени и точка статуса той же системы цветов, имя, статус и поставщик — в подсказке, открытая сессия выделена, внизу «+» — новая сессия. Cmd/Ctrl + «+»/«−»/«0» меняют шрифт панели (12–20 px, по умолчанию 15) через CSS-переменную `--fz`, страница не масштабируется; клавиши ловятся по `e.code` (любая раскладка, цифровой блок). Ширина, свёртка и шрифт запоминаются в `localStorage` (`sideW`, `sideMini`, `fontPx`). На телефоне ничего не меняется.
- **Запасной голос.** ElevenLabs не ответил (ключ, лимит, сеть) — озвучка и распознавание сами переходят на локальные Piper и whisper, без ошибки. Панель пишет «ElevenLabs не ответил — распознал локально», запись — в журнал службы, последняя за час — `fallback` в `/api/providers`.
- **Выбор локального голоса в панели.** «Голос» → «На сервере» → список установленных голосов (Ирина, Дмитрий, Денис, Руслан…), выбор общий с ботом.
- **Каналы связи: обзор и интерфейс.** `docs/CHANNELS.md` — MAX, VK, WhatsApp Business, e-mail, веб-виджет, SMS: что даёт API, ограничения в РФ, объём S/M/L, шаги перевода бота. `channels.py` — интерфейс `Channel` (текст с нейтральными кнопками, правка, ответ на нажатие, файл и голос, скачивание, опрос → `Incoming`, `caps`) и `TelegramChannel` поверх `telegram.Api`. Бот пока работает как раньше.
- **Бот и панель заводятся без Claude и без оператора** (`setup.py`). Если Claude Code не установлен или вход не выполнен, бот всё равно стартует, а `/start` (и `/setup`) показывает мастер: «🔑 Войти в Claude», «🔌 Подключить интеграции» и «🗝 Ключ провайдера» (кнопки Mini App на «Интеграции» панели), «🩺 Проверка», «📖 Инструкция». Вход — `claude auth login` в отдельном окне tmux (сессия `<сессия>-setup`, метка `login` — сессией пульта не считается); ссылку с экрана пульт присылает в Telegram, следующее сообщение — код, он вставляется в окно, вход проверяется `claude auth status --json` (без сети), окно закрывается. В панели у владельца — карточка «Claude не готов» на главной с тем же входом и полем для кода, «Проверка» в «Настройках»; API добавлением: `GET /api/setup/status`, `POST /api/setup/login`, `/api/setup/code`, `/api/setup/cancel` (только владелец); демо — `?demo&setup=login` и `?demo&setup=none`. Функции входа принимают `config_dir`/`env` (`CLAUDE_CONFIG_DIR`) — под отдельные папки Claude для людей. `gas-pult doctor` берёт проверки оттуда же. Без Claude Code `claude mcp` больше не бросает `FileNotFoundError` (список интеграций пуст), новая сессия — понятной ошибкой. Если вход через пульт невозможен — [docs/SETUP-CLAUDE.md](docs/SETUP-CLAUDE.md): вручную по ssh+tmux, `claude setup-token` на другой машине, ключ API, сторонний поставщик.
- **Enter отправляет сообщение.** Как в мессенджерах: Enter — отправить, ⌘/Ctrl/Shift/Alt + Enter — новая строка; на iPhone клавиша ввода подписана «Отправить» (`enterkeyhint="send"`). Во время набора с автозаменой (`isComposing`) Enter не перехватывается.
- **Итог команды: «Копировать» и разбор ошибки.** У команды и её вывода — «Копировать»; вывод копируется целиком, а не только видимый конец (сервер хранит до 1 МБ в `outputs/`, `GET /api/commands/output`). Где буфер обмена недоступен (WebView на iPhone), панель выделяет текст в скрытом поле, а не вышло — показывает его в шторке. Команда упала (код ≠ 0) — её текст, код и последние 60 строк вывода сами уходят в сессию, откуда она пришла: «Команда упала — разбери и предложи исправление: …». Одну ошибку (папка, команда, код, хвост вывода) — один раз; Claude ждёт ответа на вопрос — не отправляем, следующий запуск попробует снова. В карточке — «на разборе» и «Отправлено на разбор в «…»». Упавшую команду во вкладке можно «Выполнить снова». Бот — то же: строка под итогом, длинный вывод — файлом `output.txt`.
- **«▶️ Выполнить» в боте отмечает команду во вкладке «Команды».** Раньше у бота был свой список, и выполненная там команда оставалась в панели невыполненной. Теперь бот после выполнения ставит ту же отметку: код, время, вывод, «кнопкой в боте». Отмечается самая свежая такая команда этой папки. Файл журнала общий для бота и панели, запись под блокировкой `flock`.
- **`docs/ONBOARDING-BUSINESS.md`** — как подключить новый бизнес: требования к серверу, бот, роли, проекты, модели и данные; шаги с командами CLI и время; что не готово для нескольких клиентов (изоляция, доступ по папкам, учёт расхода, российские модели, 152-ФЗ, бэкапы) с объёмом S/M/L.
- **Вкладка «Команды» в панели.** Команды из блоков кода терялись в переписке. Теперь главная → «Команды» собирает блоки кода из ответов всех сессий в один список, новые сверху: сессия, время, «для чего» (строка `# …` в блоке или строка текста перед ним), «Выполнить», «Копировать», отметка «выполнено» с кодом выхода, фильтр «Только невыполненные». Хранится на сервере (`commands-log.json`, последние 400) — переживает перезапуск и закрытие окна; транскрипт перечитывается, только когда изменился. API: `GET /api/commands`, `POST /api/commands/run`, `POST /api/commands/mark` (выполнять и отмечать — только владелец; папки команд видит только владелец).
- **Подсказка Claude в поле ввода.** Claude Code пишет предложенное следующее сообщение бледным текстом (`ESC[2m`) после «❯» в строке ввода — пульт читает его из `capture-pane -e` (`tmux.prompt_hint`, `Tmux.hint`); общие заглушки «Try "…"» не показываются. Панель: у свободной сессии подсказка — вместо «Сообщение для …» в пустом поле; лампочка в строке инструментов (или Tab на компьютере) вставляет текст, отправляете сами (`/api/hint`). Бот: подсказка появляется через секунды после ответа — бот в течение 90 с дописывает к сообщению с ответом кнопку «💡 …» (`editMessageReplyMarkup`), нажатие отправляет текст в окно.
- **Переименовать сессию.** Панель: долгое нажатие на сессию в шторке или «⋯» на карточке → «Переименовать» (своё поле ввода; `prompt()` в Telegram на iPhone ненадёжен), `/api/rename`. Бот: 📋 Окна → окно → ✏️ Переименовать → новое имя ответом. Имя — 1–40 знаков, без «:» и «.» (разделители цели в tmux), `tmux rename-window`; снимок `claude-restore` берёт имя из tmux, так что оно переживает перезапуск. Участник может переименовать, наблюдатель — нет.
- **Утренняя сводка «ждёт владельца»** (`digest.py`). Каждый день в `digest_at` (по умолчанию 09:00) бот пишет одно сообщение: открытые PR старше 2 дней или с красным CI во всех репозиториях `digest_github` (через `gh`, один запрос GraphQL), окна, где Claude ждёт ответа, и строки «Ждут «да»» из `HANDOFF.md` штабов (с подпунктами; рабочие копии worktree пропускаются). Пусто — не пишет. У пункта: «да» — слить PR (только зелёный без конфликта, с подтверждением), показать экран окна или передать «да» в окно проекта (с подтверждением); «закрыть» — убрать на месяц; «позже» — до следующей сводки. `/digest` — сводка сейчас. Состояние — `digest.json` (0600).

### Изменено
- **Прячущиеся панели — как в Safari и Telegram на iOS.** Раньше шапка и поле ввода уходили только при прокрутке в одну сторону, и было непонятно, как их вернуть. Теперь: прокрутка в любую сторону дальше 30 px — обе уходят; лёгкое обратное движение (10 px) или тап по ленте — возвращаются; в самом верху и в самом низу ленты видны всегда; не прячутся, пока открыта клавиатура, в поле текст или вложения, идёт запись голоса, открыто меню или вопрос Claude. Анимация 200 мс; «резинка» iOS у границ ленты за жест не считается. Кнопка «‹ Назад» вместе с шапкой не уходит — остаётся на месте круглой кнопкой.
- **Поле ввода уходит вместе с шапкой.** Листаете ленту дальше (палец снизу вверх) — шапка и нижняя панель с полем ввода уходят, вся высота экрана — переписке; обратное движение — обе возвращаются. Поле не прячется, пока в нём текст или вложения, открыта клавиатура, меню или вопрос Claude; дочитали до конца ленты — поле возвращается само. Кнопка «к последнему» и мини-плеер едут следом.
- **«‹ Назад» на каждом вложенном экране.** Вкладки главной «Команды» и «Интеграции» на телефоне — вложенные экраны: имя экрана в шапке, слева «‹ Назад» (к сессиям), вкладки не мешают; кнопка прячется и возвращается вместе с шапкой, в Telegram — его кнопка «Назад». Шторка, открытая пунктом другой шторки (Настройки → Люди → человек, папка → модель → усилия), — сверху «‹ Назад» к предыдущей, по цепочке до первой.
- **Имя сессии у поля ввода — переключатель.** Строка «куда уйдёт» под полем ввода («штаб ▾ · работает») стала кнопкой: нажатие открывает шторку «Сессии», выбор — переход в другую сессию. Как имя в шапке, но под большим пальцем.
- **Цвета точек статуса — одна система и экран «Обозначения».** Зелёная, мигает — работает (была синяя); жёлтая — ждёт вашего ответа; серая — свободна; красная — остановлена, нет процесса Claude (был серый кружок). Новый экран «Обозначения» (значок «?» в «Настройках» и в шторке сессий): точки, метки («новый ответ», точка у имени сессии, «Контекст», «обновлено») и кнопки — что значат и что делать. Таблица — в `docs/MINI_APP.md`.
- **«Команды»: честные статусы вместо «Выполнено».** У каждой команды — статус только по настоящему запуску через пульт (панель или «▶️» в боте): «выполняется» (сразу при запуске, видно и с других устройств; дольше 12 минут — «запуск прервался»), «код 0», «код N» (с выводом, «Копировать вывод», «на разборе»), «не запускалась». Ручная отметка — отдельное действие «Отметить: сделано вручную»: карточка остаётся в списке с пометкой, итог настоящего запуска не стирается. Фильтры «Все / Не запускались / С ошибкой» с числами вместо «Только невыполненные»; ничего не исчезает без следа. Старые ручные отметки переходят в новую пометку сами. Упавшую или выполненную команду можно «Выполнить снова».
- **Надписи: ревью кнопок.** Внизу каждой шторки вместо «Отмена» — «Закрыть» (отменять там нечего), под «Что нового» — «Понятно». Сессия везде «завершается», а не «закрывается»: в боте «⛔ Завершить» и «Да, завершить» с пояснением, что переписка сохранится; ««…» завершена». «Сделать активной» в боте — как в панели (было «активным»), уведомления «Только активная» (было «Активное»), «Открыть меню /model» (было «Меню выбора»). Уведомления в панели: «Не сейчас» вместо «Нет». Вход: «Войти по коду — для владельца» вместо «Код владельцу бота». Тосты: «Сессия завершена» вместо «Сессия закрыта» и «Завершение: закрыто».
- **Озвучка не обрывается и видна на сообщении.** Раньше уход из сессии останавливал плеер (`back()` → `stopPlayer()`), а сам плеер жил в нижней панели сессии. Теперь плеер один на всю панель: играет при переходах по меню и между сессиями, останавливается только ✕ или в конце. На сообщении, где нажали «Кратко»/«Целиком», — «Готовлю…», затем полоска прогресса, ⏸/▶ и ✕; на других экранах — мини-плеер над нижней панелью, тап по названию — вернуться к сообщению. Media Session API: название и пауза на экране блокировки. В демо вместо голоса — короткий тон.
- **Чат прежде всего (телефон).** Панель сразу открывает последнюю сессию (открытую в панели, иначе активную в чате бота) на весь экран; список сессий — не стартовый экран. В шапке — имя сессии с ▾: тап — шторка «Сессии» (статус точкой, «новый ответ», «+ Новая сессия», «Все сессии и интеграции»); тихая точка у ▾ — в другой сессии вопрос или новый ответ. Свайп от левого края — та же шторка, свайп по шапке влево-вправо — соседняя сессия. Долгое нажатие на сессию в шторке — «Открыть» / «Завершить» (`sheet()` умеет `hold` и точку статуса). Вкладки «Переписка/Экран» на телефоне заменила кнопка в шапке. На компьютере (от 1024 px) — как было: список слева, вкладки. `?home` в адресе — открыть список.

### Исправлено
- **Время в переписке было в UTC** (на час меньше амстердамского зимой). Журналы Claude Code пишут время в UTC, панель показывала его как есть. Теперь сервер сообщает свой часовой пояс (`/api/meta` → `tz`, из `/etc/localtime`), и переписка и вкладка «Команды» показывают время сервера — одинаково на любом телефоне, где бы он ни был. Пояс неизвестен — время телефона.
- **Модель сессии пропадала при другой строке статуса.** Модель бралась только из строки статуса Claude Code («🤖 Opus 5.5 · …»); у кого строка статуса другая, поле «модель» было пустым. Теперь, если строки нет, — модель последнего ответа из журнала Claude Code (`message.model`, «Opus 5.5»; GLM, DeepSeek — их id), пересчёт только при изменении журнала.
- **Бот и панель могли печатать в одно окно одновременно.** Замок окна был только внутри панели (`threading.Lock`), а бот — отдельный процесс: сообщение из бота и сообщение из панели (или слэш-команда и закрытие окна) в одно и то же время перемешивали ввод. Теперь замок окна — файл с `flock` в `locks/`, общий для обоих процессов; снимается сам, даже если процесс упал. Слэш-команда (`run_slash`) и закрытие окна (`quit`) — одна реализация для бота и панели.
- **Опасную команду нельзя было выполнить в браузере.** Скрипт Telegram загружается и вне Telegram, и подтверждение звало `tg.showConfirm`, а там он бросает `WebAppMethodUnsupported` — кнопка «⚠️ Выполнить» молчала. Теперь окно Telegram — только когда панель и правда открыта из Telegram (`initData`), иначе обычное `confirm`.
- **Claude по длинному пути не узнавался.** `ps` без `-ww` режет командную строку до 80 знаков: если путь к Claude длинный (установка через npm — `node …/@anthropic-ai/claude-code/cli.js`, глубокая папка), окно выглядело обычной оболочкой — сессии не было в панели и боте. Теперь `ps -ww`. Заметили по сквозному тесту: он начал падать, когда номер временного каталога pytest стал трёхзначным и путь к фальшивому `claude` перевалил за 80 знаков.
- **Одно сообщение доходило до Claude 3–4 раза.** Связь телефона рвалась, пока сервер вставлял текст (в журнале — `BrokenPipe`): панель считала сообщение неотправленным, возвращала текст в поле, и его отправляли снова. Теперь у сообщения id от браузера: сервер второй раз с тем же id не вставляет, а повтор, пришедший во время первой вставки, ждёт её исхода (`/api/send` → `id`, ответ `dup`). При обрыве панель пишет «связь прервалась — проверяю, дошло ли…», сама повторяет с тем же id и сверяет с перепиской; не вышло — «нет связи — не знаю, дошло ли» и кнопка «Повторить» (тот же id). В поле текст возвращается, только когда сервер отказал явно.
- **Бот засыпал Telegram: >170 сообщений за минуту → 429 Too Many Requests** (31.10 22:17). У журналов Claude Code на 11–18 МБ одновременно сменилось время изменения (ctime), и монитор, решавший «новый ли журнал» по ctime, переслал их с начала — всю переписку. Теперь (`transcripts.Tail.watch`) журналы, которые уже лежали в папке при первом взгляде на неё, читаются с конца; с начала — только появившиеся позже или маленькие свежие; подменённый или укороченный журнал — с конца. Больше 3 ответов окна за один обход монитора — бот шлёт последний и «пропущено ответов: N». На 429 бот молчит столько, сколько просит Telegram (`retry_after`), и после паузы шлёт одно сообщение о пропущенном, а не долбит запросами, продлевая запрет.
- **Тесты и проверки больше не могут задеть боевой tmux.** 31.10 13:27 проверка с `TMUX_TMPDIR` в длинном каталоге: путь сокета не поместился, и `tmux kill-server` закрыл боевой сервер (5 окон, восстановлены по снимку). Теперь `Tmux` принимает свой сокет (`socket=` или `GAS_PULT_TMUX_SOCKET` → `tmux -S`), сквозные тесты работают на коротком сокете в `/tmp/gp-…` и гасят только его, все остальные тесты смотрят на пустой сокет (`tests/conftest.py`), а тест-страховка не пропустит `kill-server` без `-S`. Правило — в `CONTRIBUTING.md`.
- **Выбор пункта, когда Claude «ждёт выбора», не срабатывал на iPhone.** Панель слала цифру, а не всякое меню Claude Code её принимает; `select()` брала самую верхнюю «❯» на экране — а выше меню бывают ваши прошлые сообщения с «❯ 1. …». Теперь пункт выбирается стрелками до «❯» и Enter (`/api/select` с номером `n`), номер и выделение ищутся в самом меню. Карточка не перерисовывается, пока вопрос и пункты те же, — кнопка под пальцем не подменяется. Касание — выделить пункт (`go: false`), второе касание того же или выделенного — выбрать.
