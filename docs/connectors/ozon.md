# Ozon Seller — коннектор пульта

Код — `src/gas_pult/connectors/ozon_mcp.py`, тесты — `tests/test_ozon_mcp.py`, контракт — `docs/CONNECTORS.md`.
Документация Seller API — https://docs.ozon.ru/api/seller/ . Сайт документации закрыт антибот-проверкой для программ.
Методы и примеры сверены 19.11.2026 по двум копиям: индекс Context7 `/websites/ozon_ru_api_seller` (страницы
docs.ozon.ru) и зеркало https://github.com/etozhearut/ozon-seller-api (файлы `docs/06-pricesandstocksapi.md`,
`14-fbs.md`, `16-fbo.md`, `37-reviewapi.md`).

**Статус: каркас, не проверено на песочнице.** У Ozon Seller API нет песочницы. Ключа ещё нет.

## Что умеет

| Инструмент | Что делает | Метод Seller API |
|---|---|---|
| `ozon_list_stocks` | Остатки по схемам: FBO (склады Ozon), FBS/rFBS (свой склад) — на складе, в резерве, можно продать | `POST /v4/product/info/stocks` |
| `ozon_list_prices` | Цена, зачёркнутая цена, минимальная цена, индекс цен, комиссии FBO/FBS, акции | `POST /v5/product/info/prices` |
| `ozon_list_orders` | Отправления за период (по умолчанию со вчера), свежие сверху: номер, статус, товары, сумма; `scheme=fbs` или `fbo` | `POST /v4/posting/fbs/list`, `POST /v3/posting/fbo/list` |
| `ozon_list_reviews` | Отзывы: оценка, текст, SKU, статус NEW / VIEWED / PROCESSED | `POST /v2/review/list` |
| `ozon_propose_review_comment` | Черновик ответа на отзыв. Сам ничего не публикует | — |
| `ozon_apply` | Публикует подтверждённый человеком ответ и помечает отзыв «обработан» | `POST /v1/review/comment/create` |

- Страницы: `cursor` (остатки, цены, заказы) или `last_id` (отзывы) — из поля `more` прошлого ответа.
- Даты в запросе — ГГГГ-ММ-ДД по Москве. Ozon работает в UTC: коннектор переводит сам, в ответе — UTC.
- Данные покупателя (имя, телефон, адрес, ИНН юрлица) коннектор **не запрашивает**: в запросе заказов нет блока
  `with`, а лишние поля ответа отбрасываются.
- Старый метод `/v3/posting/fbs/list` Ozon отключил (по документации — с 01.06.2026 или с 31.08.2026; даты в двух копиях
  разные). Коннектор сразу использует `/v4`.

## Чего не умеет (и не будет)

- Менять цены, остатки, карточки товаров, акции.
- Собирать, отгружать и отменять заказы; создавать поставки FBO; печатать этикетки.
- Финансы, выплаты, возвраты денег, чаты с покупателями, вопросы покупателей (вопросы — следующий шаг, если нужно).
- Удалять или менять отзывы. Запись — только ответ на отзыв через подтверждение человека.

## Ключ

Файл `~/.config/gastech-mcp/ozon.token` (права 0600), путь меняется `GAS_OZON_KEY_FILE`:

```json
{"client_id": "...", "api_key": "..."}
```

Как получить (делает владелец или клиент-продавец; путь в ЛК **не проверял** — по описанию в очереди):

1. Войдите в личный кабинет продавца Ozon: https://seller.ozon.ru
2. Откройте «Настройки» → «Seller API».
3. Создайте ключ с ролью только на чтение (точное название роли в ЛК не проверял). Для ответа на отзывы нужна роль
   с доступом к отзывам — добавьте её, только если нужна запись.
4. Скопируйте Client-Id и ключ. Ключ показывается один раз.
5. Сохраните в KeePassXC `gastech.kdbx`, группа `mcp/ozon`, и положите файл на сервер с правами 0600.

- Ключ всегда боевой: песочницы у Ozon нет. Поэтому — только роль «чтение».
- Отзывы (`/v2/review/list`, ответ на отзыв) доступны, только если у продавца есть подписка Ozon «Управление
  отзывами» или Premium Pro. Без подписки Ozon ответит 403 — это не ошибка коннектора.
- Если оферта Ozon не принята, Ozon отвечает `403 Offer not signed` — примите оферту в ЛК.

## Лимиты

Документация, раздел «Все методы»: не больше 50 запросов в секунду на один Client-Id; у отдельных методов свои
лимиты; при перегрузке Ozon временно блокирует метод («Circle is open»). Коннектор держит не больше 10 запросов
в секунду (`Throttle(10, 1)`). Ответ 429 ядро переводит в понятную ошибку.

## Сценарий

**Селлер Ozon + модуль `wb-ozon-stock`.** По будням в 09:00 агент вызывает `ozon_list_stocks` (остатки FBO и FBS) и
`ozon_list_orders` (`scheme=fbo` и `fbs`, за 28 дней, страницами) и считает, на сколько дней хватит товара (навык
`stock-forecast`). План — в `SUPPLY.md`, вопрос «Создать черновик поставки?» — человеку. Поставки коннектор не создаёт.

**Модуль `wb-ozon-reviews`.** Дважды в день `ozon_list_reviews(status=NEW)` → черновики ответов по `data/facts.md`.
Негатив (★1–3) — сразу отдельным вопросом. По «Да» — `ozon_propose_review_comment` → подтверждение в пульте →
`ozon_apply`.

**Модуль `wb-ozon-prices`.** `ozon_list_prices` → сверка с себестоимостью и минимальной ценой из `data/prices.csv`.
Менять цену коннектор не умеет — агент готовит файл для загрузки в кабинет.

**Оценка «минут до/после» (не замерено, оценка):** остатки — выгрузка из кабинета и сводная таблица ~20 мин в день →
готовая сводка без действий человека. Отзывы — 20 в день по ~2 мин в кабинете ~40 мин → прочитать черновики и нажать
«Да» ~8 мин. Замерить на первом клиенте-селлере.

## Подключение в harness

Запись в `portfolio-hq/integrations/servers.json` (работает после слияния и появления файла ключа):

```json
"ozon": {
  "type": "stdio", "command": "python3",
  "args": ["{gas_pult}/src/gas_pult/connectors/ozon_mcp.py"],
  "env": {"GAS_OZON_KEY_FILE": "{secrets}/ozon.token"},
  "auth": {"kind": "file", "file": "ozon.token", "keepass": "mcp/ozon",
           "get_key": "ЛК продавца Ozon → Настройки → Seller API → ключ с ролью «только чтение»"}
}
```

## Не проверено

- Ни один вызов на настоящем кабинете: fixtures `tests/fixtures/ozon/*.json` — примеры из документации, товары и тексты
  выдуманные.
- Поля отправления в ответе `/v4/posting/fbs/list`: в документации у v4 нет полного примера; fixture собран по примеру
  списка отправлений (те же поля, что в v3/FBO). Проверить на первом ключе.
- Фильтр `status` у `/v2/review/list`: в примере запроса документации поля перепутаны местами; коннектор шлёт
  `filters.status` = NEW / VIEWED / PROCESSED по схеме ответа.
- Формат ссылки на товар `https://www.ozon.ru/product/<sku>/` — с сайта Ozon, не из документации API.
