# Ревью безопасности диффа

Смотри только свои изменения: `git diff` (и `git diff --cached`, если уже добавил). Для каждого пункта — да/нет.
Нашёл проблему в своём коде — исправь сам, это не повод будить. Нашёл в коде, который был до тебя, или исправление
выходит за задачу — это причина 3: вопрос «Найдено: …, где. Исправлять сейчас?» (Да / Нет).

## Чек-лист

1. **Секреты.** Нет ключей, токенов, паролей, приватных адресов в коде, тестах, примерах, сообщении коммита.
   Подозрительные строки: `sk-`, `ghp_`, `github_pat_`, `AKIA`, `-----BEGIN`, `password=`, длинные base64.
2. **Ввод извне.** Всё, что приходит от пользователя, из сети, файла или переменной окружения, проверяется
   до использования: SQL — только параметрами; команды оболочки — списком аргументов, без `shell=True` и склейки
   строк; пути — без `..` и абсолютных путей от пользователя; HTML — с экранированием.
3. **Права.** Новая точка входа (маршрут, команда, кнопка) проверяет, кто вызывает и можно ли ему. Нет
   «временно отключённых» проверок.
4. **Данные людей.** Персональные данные (имена, телефоны, почта, адреса) не пишутся в логи, отчёты и тесты.
   В тестах — выдуманные данные («Иван», `user@example.com`).
5. **Зависимости.** Новая библиотека — известная, живая, нужной версии; аудит (`npm audit`, `pip-audit`) без
   high и critical, если инструмент есть.
6. **Ошибки.** Исключения не глотаются молча; текст ошибки для пользователя не раскрывает пути, запросы, ключи.
7. **Необратимое.** Дифф не удаляет данные, не меняет схему живой базы и не отправляет ничего наружу без
   вопроса (причина 1).

## Результат

В `REPORT.md` у задачи — строка «Ревью: чисто» или «Ревью: исправлено — <что>» или «Ревью: ждёт решения — <что>».
