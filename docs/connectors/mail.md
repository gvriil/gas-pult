# Коннектор почты IMAP/SMTP (`mail`)

**Статус: каркас, не проверено на реальном ящике.** Тесты идут на фейковых IMAP- и SMTP-серверах
(`tests/test_mail_mcp.py`); письма в `tests/fixtures/mail/mailbox.json` выдуманные, формат ответов — по RFC 3501
(IMAP4rev1) и RFC 6154 (роли папок). После появления файла ящика ночной конвейер проверит вход одним вызовом
`mail_list_folders`.

Один коннектор на любые ящики с IMAP/SMTP: Яндекс Почта, Gmail (второй ящик; первый — коннектор claude.ai), Yahoo,
Mail.ru. Proton не подключаем (IMAP только через платный Bridge). Код — `src/gas_pult/connectors/mail_mcp.py`, только
стандартная библиотека (`imaplib`, `smtplib`, `email`); контракт — `docs/CONNECTORS.md`.

## Что умеет

| Инструмент | Что делает | Команды IMAP/SMTP |
|---|---|---|
| `mail_list_boxes` | Подключённые ящики: имя, адрес, серверы. Пароли не показывает, на сервер не ходит | — |
| `mail_list_folders` | Папки и их роль: входящие, отправленные, черновики, спам, корзина (RFC 6154). Кириллица в именах — да | `LIST` |
| `mail_list_messages` | Письма папки, новые сверху: uid, дата ISO, от кого, кому, тема, прочитано ли, размер. Фильтры: `unseen`, `since` (ГГГГ-ММ-ДД), `from`, `subject`, `text`; до 100 строк | `EXAMINE`, `UID SEARCH`, `UID FETCH BODY.PEEK[HEADER.FIELDS …]` |
| `mail_get_message` | Одно письмо: заголовки, Message-ID, текст (text/plain; если только HTML — без разметки), список вложений с размером. Текст до 4000 знаков (`max_chars` до 20000) | `UID FETCH BODY.PEEK[]` (первые 3 МБ) |
| `mail_propose_draft` | **Черновик** письма в «Черновики» ящика. Сам ничего не пишет | только чтение (для ответа — заголовки исходного письма) |
| `mail_propose_send` | **Письмо к отправке.** Само не отправляет | то же |
| `mail_apply` | Выполнить подтверждённый черновик: положить в «Черновики» или отправить | `APPEND` (флаги `\Draft \Seen`) или SMTP |

- Чтение не меняет ящик: папка открывается `EXAMINE` (только чтение), письма — `BODY.PEEK`, поэтому не становятся
  прочитанными. Тест проверяет, что при чтении нет ни одной команды записи и ни одного `SELECT`.
- Ответ в ту же цепочку: `reply_to_uid` — коннектор читает Message-ID исходного письма, ставит `In-Reply-To` и
  `References`, тема — «Re: …».
- Отправка — только черновиком в пульте и после «Да» владельца (решение 11.11: «отправка — только после
  „отправляй“»). Выполняет `mail_apply`, только если `GAS_MAIL_WRITE=1` и человек подтвердил ровно этот черновик
  (кнопка в пульте или `python3 mail_mcp.py confirm <id>`). Сохранить черновик в ящик — тоже через подтверждение.

## Чего не умеет (и не будет)

- Удалять, перемещать письма, ставить и снимать пометки («прочитано», «важное»), чистить спам, создавать папки.
- Пересылать, отправлять вложения, рассылки: до 10 адресатов на письмо, только обычный текст.
- Отправлять без черновика и «Да» человека.
- Читать IMAP без шифрования: `tls: false` разрешён только для 127.0.0.1 (тесты).
- Скачивать вложения — только имя, тип, размер. Нужно — следующий шаг (с лимитом размера).
- Следить за ящиком непрерывно (IDLE). Пульт опрашивает по расписанию модуля.

## Как подключить ящик (делает владелец)

Файл на ящик: `~/.config/gastech-mcp/mail-<ящик>.json`, права 0600 (`<ящик>` — латиница, цифры, `-`, `_`:
`yandex`, `gmail2`, `yahoo`). Каталог меняется `GAS_MAIL_KEY_DIR`. Оригинал — KeePassXC `gastech.kdbx`, группа
`mcp/mail`, запись на ящик.

```json
{"host": "imap.yandex.ru", "user": "box@yandex.ru", "app_password": "<пароль приложения>"}
```

Необязательно: `imap_port` (993), `smtp_host` (для Яндекса, Gmail, Yahoo, Mail.ru — подставляется сам; иначе
`imap.` → `smtp.`), `smtp_port` (465, SSL).

**Яндекс Почта** — по справке [yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others)
(прочитано 15.11.2026; в интерфейсе **не проверял**):
1. Почта → Настройки → «Почтовые программы» → включить «С сервера imap.yandex.ru по протоколу IMAP» и «Пароли
   приложений и OAuth-токены» → Сохранить.
2. Яндекс ID → «Пароли приложений» (passport.yandex.ru/security/app-passwords) → плюс в строке «Почта» → название →
   «Далее». Пароль показывается один раз.
3. Серверы: IMAP `imap.yandex.ru:993` SSL (не из России — `imap.ya.ru`), SMTP `smtp.yandex.ru:465` SSL.
   Логин по справке — часть адреса до `@`; коннектор передаёт `user` как есть — если полный адрес не пройдёт,
   записать в `user` часть до `@` (**не проверял**).

**Gmail (ящик №2)** — по справке [support.google.com/mail/answer/7126229](https://support.google.com/mail/answer/7126229?hl=ru):
IMAP в личных аккаунтах включён всегда; вход по паролю аккаунта закрыт, по паролю приложения — можно при двухэтапной
аутентификации (Google это «не рекомендует», но поддерживает). Пароль приложения — myaccount.google.com →
Безопасность → Пароли приложений (**не проверял**). Серверы `imap.gmail.com:993`, `smtp.gmail.com:465` — общеизвестны,
по этой странице **не сверены**. Лимит — 15 одновременных подключений на аккаунт; коннектор держит одно на вызов.

**Yahoo** — Account security → Generate app password (**не проверял**); серверы `imap.mail.yahoo.com`,
`smtp.mail.yahoo.com`.

Пароль приложения — как пароль от ящика: кто его знает, читает почту. Утёк — удалить его в настройках и создать новый.

Включить запись (черновики и отправка): `GAS_MAIL_WRITE=1` в `env` сервера (по умолчанию 0).

## Лимиты

- Gmail: 15 одновременных IMAP-подключений на аккаунт; папки больше 10 000 писем Google советует не открывать
  клиентам (справка выше). Коннектор: одно подключение на вызов, до 100 писем в списке.
- Отправка: дневные лимиты сервисов (Яндекс, Gmail) — сотни писем в сутки; коннектор отправляет по одному письму
  после каждого «Да», так что до них не дойдёт. Точные цифры **не проверял**.
- Письмо больше 3 МБ читается не целиком: текст есть, список вложений может быть неполным (поле `note`).

## Не проверено (проверить на реальном ящике)

- Вход Яндекса с полным адресом в `user`.
- Поиск кириллицей (`SEARCH CHARSET UTF-8` литералом) — по RFC 3501 должен работать у Яндекса и Gmail.
- Копия отправленного в «Отправленных»: Gmail и, по опыту, Яндекс кладут её сами при отправке через SMTP;
  Yahoo — не проверял. Коннектор сам в «Отправленные» не пишет.
- Имя папки черновиков у Gmail (`[Gmail]/Drafts` или локализованное) — коннектор ищет по роли `\Drafts`.

## Сценарий

**Модуль `uk-requests` («Сроки обращений жителей») + почта УК.** Сейчас обращения, пришедшие на почту, сотрудник
переносит в `data/requests.csv` руками, ответы агент кладёт в `outbox/`, сотрудник копирует их в почту.

1. В 08:30 и 14:00 агент вызывает `mail_list_messages(box="uk", since=<вчера>, unseen=true)` и
   `mail_get_message(uid)` по новым письмам — заносит обращения в реестр с датой получения из письма, считает срок
   (навык `request-deadline`). Письма остаются непрочитанными — сотрудник видит их как раньше.
2. По обращениям со сроком сегодня–завтра агент готовит ответ и вызывает
   `mail_propose_send(reply_to_uid=<uid>, to=[житель], body=…)` — ответ в той же цепочке писем.
3. Пульт показывает вопрос модуля «Ответ жителю (дом, кв., тема), срок <дата> — отправить?» → «Отправить» → 
   `mail_apply(id)`. «Изменить» — новый черновик; «Не отправлять» — ничего не уходит.

Оценка (не замерено, по модулю): разбор почты и перенос в реестр — около 2 минут на письмо, ответ — 5–10 минут.
При 15 письмах в день: до — 1,5–2,5 часа; после — 10–15 минут на чтение черновиков и нажатие «Отправить».
Замер — на первом клиенте («минут до/после» в отчёте пилота).
