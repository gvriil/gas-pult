# Платежи (billing)

Решение владельца 22.11: «не экономим на безопасности платежей». Поставщика платежей пока нет: Stripe и т. п. —
когда будет компания в ЕС (**ждёт юрлица**). Поэтому сейчас — ядро без поставщика: счета, тарифы и журнал ведутся
в пульте, оплату владелец отмечает вручную с основанием.

## Что есть

| Часть | Где | Что делает |
|---|---|---|
| Деньги | `src/gas_pult/billing/money.py` | суммы — только целые центы (минимальные единицы ISO 4217); `float` на входе — ошибка; округление — явно (`half_even` / `half_up`), без него лишние знаки — ошибка |
| Хранилище | `src/gas_pult/billing/store.py` | SQLite `billing.sqlite3` в папке данных пульта, права 0600, режим WAL, `synchronous=FULL` |
| Поставщик | `src/gas_pult/billing/provider.py` | интерфейс `ProviderBase`, общий `verify_signature` (HMAC-SHA256, время, повтор), заглушка `none` |
| API | `src/gas_pult/billing/api.py` | единственное, что импортирует панель; права — `access.BILLING_GET` / `BILLING_POST` |
| Панель | `src/gas_pult/web/js/billing.js` | «Настройки» → «Команда и клиенты» → «Платежи» (только владелец) |

### Правила, которые держит сама база (триггеры SQLite)

- **Журнал `journal` — только добавление.** `UPDATE` и `DELETE` строк — ошибка. Исправление — встречной записью
  (`op = reversal`, сумма с обратным знаком, `reverses` — номер исправляемой строки).
- Строки счёта (`items`) и тарифы (`plans`) не меняются и не удаляются. Новая цена — новый тариф (новый код).
- Счёт не удаляется. У счёта меняются только статус и даты; номер, клиент, валюта и сумма — нет.
- Статус — только по допустимым переходам: `draft → issued | void`, `issued → paid | void`, `paid → void`.
  `void` — конечный. Аннулирование оплаченного — встречные записи к выставлению и к оплате.
- Суммы в базе — `INTEGER` (проверка `typeof(...) = 'integer'`), строка счёта = количество × цена.

### Идемпотентность

Каждое изменение несёт ключ операции `key` (8–80 знаков, `[A-Za-z0-9_.:-]`). Ключ уникален в журнале: повтор
с тем же ключом возвращает прежний итог и ничего не дублирует. Тот же ключ на другую операцию — ошибка.
Панель создаёт ключ при открытии формы: повтор после обрыва сети или после кода подтверждения — тот же ключ.

### API (только владелец; изменения — после кода подтверждения для нового входа из браузера)

| Метод | Путь | Тело / параметры |
|---|---|---|
| GET | `/api/billing/plans` | тарифы, состояние поставщика, список валют |
| GET | `/api/billing/invoices` | счета (последние 200) |
| GET | `/api/billing/invoice?id=N` | счёт со строками, журналом, остатком к оплате и допустимыми переходами |
| POST | `/api/billing/plan` | `key, code, title, price` («9.00») или `amount` (центы)`, currency, period` (`once`/`month`/`year`) |
| POST | `/api/billing/invoice/new` | `key, client, currency, lines: [{title, qty, price}]` или `[{plan, qty}]`, `space?`, `due_days?` |
| POST | `/api/billing/invoice/issue` | `key, id` |
| POST | `/api/billing/invoice/pay` | `key, id, reason` (основание обязательно), `ref?` |
| POST | `/api/billing/invoice/void` | `key, id, reason` |

Суммы в ответах — целые центы и строкой (`total_text`, `amount_text`): панель ничего не считает сама.

### Граница модуля

`billing` не импортирует бота, панель, tmux и настройки пульта; панель (`webapp.py`) импортирует только
`billing.api`. Проверка — `tests/test_billing_boundary.py`.

## Что ждёт юрлица

- Поставщик платежей (Stripe или другой): договор, ключи, приём вебхуков.
- Оплата онлайн по ссылке из счёта (`create_payment`), возвраты, налоги по странам, реквизиты продавца в счёте.
- До этого заглушка `none` на любой вызов честно отвечает: «поставщик не подключён — ждёт юрлица».

## Как подключить поставщика

1. Наследник `ProviderBase` в `billing/provider.py` (образец — `JsonHmacProvider`): `name`, `header` (заголовок
   подписи), `secrets()` — секреты вебхука (из файла 0600 в папке настроек; в git — никогда), `create_payment`,
   `parse_event` (тело → `Event`; суммы — целые центы).
2. Регистрация — в `PROVIDERS`; выбор поставщика — настройкой пульта.
3. Вебхук: `provider.verify_webhook(headers, body, seen=lambda s: store.remember_webhook(con, s))`. Общий код
   проверяет подпись HMAC-SHA256 за постоянное время, время (±300 с) и повтор (подпись запоминается в базе).
   Формат подписи — `t=<unix>,v1=<hex>`, подписывается `<t>.<тело>`; если у поставщика свой формат — свой разбор
   заголовка, но через те же проверки.
4. Событие оплаты — `store.mark_paid(..., key="evt:<id события>")`: повтор события поставщиком не задвоит оплату.
5. Маршрут вебхука — без входа, но только с проверенной подписью; отдельный PR с тестами на подделку, время и повтор.
