# Распределение пика по филиалам

Скрипт — рядом, только стандартная библиотека:

```
python3 .claude/skills/peak-spread/peak_spread.py --clients data/clients.csv --slots data/slots.csv \
  --branches data/branches.csv --from <дата> --to <дата> --max-load 0.85 --out outbox/slots-plan.csv
```

| Сегмент | Куда | Если там нет слота или день выше порога |
|---|---|---|
| хранение (`хранение_шин = да`, договор, согласие на уведомления) | филиал хранения шин | соседний филиал, пометка «нужна перевозка шин из …» — решает человек |
| прошлый (переобувался за два сезона, **согласие на рекламу**) | менее загруженный: свой прошлый или соседний | — |

- Загрузка дня = занятые слоты / все слоты филиала за день — больше постов, больше слотов, больше ёмкость.
- Отписка, нет согласия — клиент не попадает в план; в итоге — сколько пропущено, без имён.
- Скрипт ничего не отправляет и не записывает в систему: только `outbox/slots-plan.csv` и итог «загрузка до/после».

Дальше:

1. Пометка «нужна перевозка шин» или «нет свободного слота» — вопрос «Филиал перегружен — предложить клиентам
   соседний филиал?» («Да, соседний», «Добавить слоты», «Сдвинуть на неделю») **до** сборки пачки.
2. Пачки — навык `reminder-batch`, отдельно по сегментам: `templates/storage-season.md` (хранение) и
   `templates/season-offer.md` (прошлые). В тексте вопроса — загрузка филиалов до/после.
3. Ответы клиентов («подтверждаю», «другое время») — `reminder-replies`; подтверждённые слоты — в
   `outbox/changes-<дата>.csv` для системы записи.
