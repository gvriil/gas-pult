# «Проекты» — модель данных и макеты экранов

Задача 49, требование владельца от 07.11.2026: «Проекты» как в ChatGPT и Claude. Проект — папка со своими
инструкциями (`CLAUDE.md`), файлами, интеграциями и моделью по умолчанию; внутри — много сессий (чатов). Главный
экран — список проектов, внутри проекта — его сессии (активные и завершённые, поиск) и «Новая сессия в проекте».
Клиент (простой режим) видит только «Проекты → чаты», без слов tmux, код, терминал; режим кода (экран, терминал, git)
— только разработчику и владельцу. Сессии пространств — тоже по проектам.

**Это этап 1 — только документ.** Код, API, службы и данные не меняются. Реализация — отдельными PR по разделу 6,
каждый после «да» владельца.

Код — `main` на `42f756a` (#125); учтены #123 «Репозитории» (ещё не на `main`), аудит
`docs/metrics/audit-2026-11.md` (разделы 3 и 10) и задача 50 (интерактивный терминал в панели только в режиме
разработчика — делается параллельно, здесь на неё только ссылки).

## 1. Как сейчас

Почти всё, из чего складывается проект, в пульте уже есть — но разложено по папкам, окнам и настройкам владельца,
а не собрано в одну сущность.

**Шаги до типовых действий** (аудит, раздел 3): новая сессия в существующей папке — 2–3 нажатия, в новой — 3–4 и
ввод, из модуля — 4–5; в простом режиме новую сессию можно открыть только из модуля (4–5). Цель «Проектов» — не
длиннее: открыть проект — 1, новая сессия в нём — 1, продолжить прошлую — 2 (раздел 3.7).

**Треки** (аудит, раздел 10): список окон владельца и «Новая папка» — **инструмент**, простой режим, модули и
пространства — **продукт**. «Проекты» соединяют их одной моделью, поэтому сама модель и экраны — **общее**, а
отдельные PR помечены своим треком (раздел 6).

## 2. Модель данных

### 2.1. Проект

```jsonc
// <data>/projects.json (0600) — проекты владельца и участников
{
  "v": 1,
  "projects": {
    "p3f9a1c27e0": {
      "id": "p3f9a1c27e0",              // при миграции — от realpath папки (детерминированно), новые — случайный
      "name": "Магазин",                // показываемое имя; по умолчанию — имя папки
      "path": "~/projects/shop",        // главная папка: cwd новых сессий; хранится с ~ — без личных путей
      "paths": [],                      // доп. папки проекта (рабочие копии git worktree — вопрос 1, раздел 7)
      "owner": {"kind": "person", "uid": null},   // null — владелец пульта; число — участник; {"kind": "space", "slug": "…"}
      "share": [],                      // кто ещё видит проект: ID участников и наблюдателей (раздел 3.8)
      "origin": "auto",                 // auto (миграция) | new | module:<id> | repo:<владелец/имя>
      "created": 1762531200, "by": null,
      "profile": "",                    // профиль поставщика по умолчанию (models.PROFILES); "" — как у учётки
      "model": "", "effort": "",        // модель и усилие по умолчанию; "" — как у учётки (--model при запуске)
      "integrations": ["github"],       // включённые интеграции проекта: ключи PRESETS или своих серверов (2.4)
      "files": "files",                 // папка файлов проекта внутри path (вопрос 3)
      "repos": [],                      // подключённые репозитории — бывшие add_dirs (#123) для этой папки
      "pinned": false, "archived": false // pinned — прежнее общее закрепление, переносится в pins.owner
    }
  },
  "sessions": {                         // только то, чего нет в журнале Claude Code
    "6f1c…uuid": {"project": "p3f9a1c27e0", "title": "Скидки на зиму", "hidden": false}
  },
  "pins": {                             // закрепления — свои у каждого человека: «owner» или Telegram ID
    "owner": {
      "projects": {"p3f9a1c27e0": 1762531200},   // проект → время закрепления (порядок группы)
      "chats": {
        "sid:6f1c…uuid": 1762531300,      // по id сессии Claude Code — переживает перезапуск окна и «Продолжить»
        "path:~/projects/shop": 1762531400 // старое окно без метки id — по папке
      }
    }
  }
}
```

- **Инструкции** не копируются в `projects.json`: это `CLAUDE.md` в `path` — его читает сам Claude Code, а панель
  только показывает и правит файл. Так проект работает и без пульта (обычный `claude` в этой папке).
- **Источник правды о сессиях — журналы Claude Code**, не наш файл. В `sessions` лежат только переименования и
  скрытие; потеря `projects.json` не теряет ни одной сессии. Исключение — «Удалить»: журнал переезжает в корзину
  пульта (`chat_trash.py`), вернуть — «Корзина чатов».
- Запись — `config.write_private` (0600) под замком, как `focus.json`, `people.json`.
- **Закрепить** (`POST /api/pin` `{project | w | id+sid, on}`): проект, сессия (активная или остановленная) и
  завершённый чат. Закреплённые — группой «Закреплённые» наверху списка (проекты, «Сессии», «Активные» и
  «Завершённые» проекта), последний закреплённый — первым; на сервере — одинаково на телефоне и в браузере. Меню —
  «⋯» на карточке, долгое нажатие на телефоне или правая кнопка мыши. **Закрепления — свои у каждого человека**
  (`pins[кто]`): владелец (и фокус-ссылка — как выпустивший её владелец) — `owner`, участник — свой Telegram ID;
  `pinned` / `pinned_at` в ответах — для того, кто спрашивает. Прежние общие закрепления (`pinned` у проекта, плоские
  `pins`) при чтении переходят владельцу.

### 2.2. Сессия → проект

Связь **вычисляется**, а не хранится:

1. **Окно tmux → проект**: `realpath(path окна)` лежит внутри `path` или `paths` проекта — самое длинное совпадение.
   Окно в папке вне всех проектов — проект «Без проекта» (виден только в режиме кода) или новый авто-проект при
   следующей миграции.
2. **Окно → свой журнал** (новое, снимает «одно окно на проект»): новая сессия запускается с
   `claude --session-id <uuid>`, uuid пишется в опцию окна `@gas_pult_sid` — так же, как `@gas_pult` и
   `@gas_pult_by` (`tmux.py:177`). Переписка, превью, строка статуса и расход окна читают `<uuid>.jsonl`; у окна
   без метки (старые окна) — как сейчас, последний журнал папки.
3. **Завершённые сессии проекта** — все `*.jsonl` в `project_dir(path, home)` для каждой папки Claude, чьи окна
   могут быть в проекте: владелец — `~/.claude`, участник — `<data>/people/<id>/claude` (ADR 0001), пространство —
   его `config/claude`. Активные — те, чей uuid сейчас открыт в окне; остальные — «Завершённые».
4. **Название сессии**: своё из `sessions` → запись `summary` журнала Claude Code → первое настоящее сообщение
   человека (`transcripts.is_real_prompt`), обрезанное до 60 знаков.
5. **«Продолжить» завершённую** — новое окно в папке проекта с `claude --resume <uuid>` (а не `--continue`:
   он берёт последний разговор папки). Метка `@gas_pult_sid` — тот же uuid.

### 2.3. Хранение

| Чьи проекты | Метаданные | Папки | Журналы |
|---|---|---|---|
| Владелец | `<data>/projects.json` | `project_roots` (первый корень — для новых) | `~/.claude/projects/…` |
| Участник | там же, `owner.uid` = его ID | его корень — вопрос 4 (аудит, В2) | `<data>/people/<id>/claude/projects/…` |
| Пространство | **внутри пространства**: `home/.gas-pult/projects.json` | `home/projects/<проект>/` | `config/claude/projects/…` |

Метаданные пространства лежат у клиента, а не у пульта: они попадают в `pult-tenant backup` и исчезают при
`destroy`. Пульт читает их через группу `pult-ro`, а пишет командой от пользователя пространства
(`space_sessions.sh`), как уже делает с папками и корзиной. Вопрос 6.

### 2.4. Интеграции, модель, файлы, репозитории проекта

- **Интеграции**: сейчас — `-s user` (на всю папку Claude). Для проекта — файл
  `<config>/projects/<id>.mcp.json` (0600, в репозиторий проекта не попадает) и запуск
  `claude --mcp-config <файл>`; интеграции учётки при этом остаются. В `.mcp.json` в папке проекта не пишем: Claude
  Code спрашивает о нём отдельным диалогом и файл мог бы уйти в git клиента. Вопрос 10.
- **Модель и поставщик по умолчанию**: при запуске новой сессии проекта — `--settings <профиль>` и `--model`, как
  уже делает задача 37 для одного чата. Модель только этого чата (`window_models`) по-прежнему сильнее проекта.
- **Файлы**: загрузка в `<path>/<files>/` (у пространства — тем же путём через буфер tmux, `space_files.py`); в
  `CLAUDE.md` проекта одной строкой — где лежат файлы. «Прикрепить» в сессии проекта кладёт файл туда же, а не во
  `inbox/`.
- **Репозитории** (#123): `add_dirs` в `state.json` уже по папке — переносятся в `repos` проекта; каждая новая
  сессия проекта получает `--add-dir` для каждого.

### 2.5. Миграция — автоматически, ничего не теряется

При первом чтении `projects.json` нет — пульт строит его сам (и то же для пространства — при первом открытии):

1. Каждая папка из `Pult.projects()` (домашняя и подпапки `project_roots`) → проект `origin: "auto"`, `id` — от
   `realpath`, имя — имя папки (домашняя — «Домашняя»). Повторный запуск даёт те же id: миграция идемпотентна.
2. Каждое окно с Claude в папке вне списка (например, открытое руками) → тоже авто-проект.
3. `add_dirs` из `state.json` → `repos` проекта папки. Сам `add_dirs` не удаляется (старый код читает его как раньше).
4. Папка с `.gas-pult-module` → `origin: "module:<id>"`, имя — название модуля (как «агент» в простом режиме).
5. Пространство: каждая папка `home/projects/<имя>` (бывшая сессия задачи 32) → проект с одной сессией; корзина
   `trash/sessions` остаётся корзиной сессий.
6. Ничего не переносится на диске и не удаляется: папки, журналы и окна на месте. Откат — удалить `projects.json`
   (и `.gas-pult/projects.json` в пространстве): пульт работает как до «Проектов».

### 2.6. API — только добавлением

| Запрос | Что | Права |
|---|---|---|
| `GET /api/projects?q=` | список проектов человека: имя, счётчики (ждут / работают / всего), последняя активность | все вошедшие — только свои и `share` |
| `GET /api/project?id=` | проект: настройки, `CLAUDE.md` (текст), файлы, интеграции, репозитории | смотреть — кто видит; поля режима кода — по `cap.*` |
| `GET /api/project/sessions?id=&state=active\|done&q=&before=` | сессии проекта; поиск по названию и тексту (с лимитом) | кто видит проект |
| `GET /api/project/history?id=&sid=` | переписка завершённой сессии без окна | кто видит проект |
| `POST /api/projects/new` `{name, from?: "empty"\|"module:<id>"\|"repo:<…>"}` | новый проект | владелец, участник; в пространстве — его участник |
| `POST /api/project/update` `{id, name?, instructions?, profile?, model?, integrations?, archived?}` | настройки | владелец проекта; инструкции и интеграции — с `cap.dev_models_mcp` или владельцу |
| `POST /api/project/session` `{id, profile?}` | новая сессия в проекте (новое окно, `--session-id`) | писать — не наблюдатель |
| `POST /api/project/resume` `{id, sid}` | продолжить завершённую (`--resume`) | писать — не наблюдатель |
| `POST /api/project/files…` | загрузить / скачать / список файлов проекта | как файлы сессии |

В `/api/sessions` — новые поля `project` и `sid`; в `/api/meta` — `projects_ui: true`, пока экран включается. Старые
`/api/new`, `/api/folder`, `/api/modules/create`, `/api/space/*` остаются и работают; новые экраны вызывают новые
запросы. Фокус: `FOCUS_GET` получает только `/api/project?id=` своего окна (имя проекта в шапке).

## 4. Пространства

- **Где папки.** Проект пространства — `home/projects/<проект>/` (как сейчас папка сессии); все чаты проекта
  работают в этой папке, у каждого свой журнал в `config/claude/projects/…`. Метаданные — `home/.gas-pult/projects.json`
  (раздел 2.3). Файлы проекта — `home/projects/<проект>/files/` через буфер tmux (`space_files.py`): путь по-прежнему
  проверяется `realpath` внутри папки проекта.
- **Кто создаёт.** Участник пространства (тестировщик) — «Новый проект» в простом режиме: «Пустой» или «Готовый
  агент». Владелец — из группы «Пространства» («Поставить задачу» создаёт проект или чат в выбранном проекте).
  Наблюдатель и гость не создают. Модуль, созданный для пространства, создаётся **в пространстве**, а не в папке
  владельца (закрывает аудит 10.4, В).
- **Действия задачи 32 переезжают на уровень чата.** «Закрыть» — завершить чат (журнал остаётся, папка проекта
  тоже); «Продолжить» — `--resume <uuid>`; «Удалить» — журнал чата в корзину `trash/sessions/…` (14 дней). Удалить
  проект целиком — папка проекта и его журналы в корзину `trash/projects/…`, тот же срок.
- **Изоляция не меняется.** Пульт не пишет в пространство сам: всё — от пользователя пространства через его tmux
  (`space_sessions.sh`), имена — через `folder_name` и `shlex.quote`. Окна — `t:<slug>:@N`, тестировщик видит
  только своё пространство (`Routed.scope`).
- **Интеграции пространства** (в панели их нет — пробел продукта): проектный файл `--mcp-config` лежит в
  `config/projects/<id>.mcp.json` пространства, ключи — в его `secrets.json`; подключение — отдельный PR трека
  «продукт», после «Проектов».
- **Выпуск.** Панель для пространств пока одна с пультом владельца (`docs/RELEASES.md`, этап 4), поэтому экран
  «Проекты» у тестировщика появится вместе с `main`; включать его пространствам — флагом, после проверки у владельца.
