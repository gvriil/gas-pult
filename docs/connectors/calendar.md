# Коннектор календаря CalDAV / iCal (`calendar`)

**Статус: каркас, не проверено на реальном календаре.** Тесты — на фейковом сервере CalDAV и фейковой ссылке iCal
(`tests/test_calendar_mcp.py`, события в `tests/fixtures/calendar/` выдуманные; ответы сервера — по RFC 4791 и
RFC 5397). Яндекс Календарь, Nextcloud, iCloud и Google — **не проверены**.

Зачем: календарь без подписки Claude (коннектор Google Calendar есть только в claude.ai). Один коннектор на:
- **CalDAV** — Яндекс Календарь, Nextcloud, iCloud, Fastmail: чтение и создание событий (по паролю приложения);
- **ссылку iCal** — секретный адрес календаря Google (и любой другой `.ics`): только чтение.

Код — `src/gas_pult/connectors/calendar_mcp.py`, только стандартная библиотека (`urllib`, `xml.etree`, `datetime`,
`zoneinfo`); разбор iCalendar — свой. Контракт — `docs/CONNECTORS.md`.

## Что умеет

| Инструмент | Что делает | Запросы |
|---|---|---|
| `calendar_list_calendars` | Подключённые календари: вид (caldav / ics), сервер, календари внутри аккаунта CalDAV. Пароли и секретные ссылки не показывает | `PROPFIND` (CalDAV); ссылку iCal не скачивает |
| `calendar_list_events` | События за период по всем календарям или одному: начало и конец (ISO, в нужном поясе), название, место, описание (до 200 знаков), повтор. По умолчанию — сегодня и 6 дней вперёд; период до 366 дней; до 100 событий | `REPORT calendar-query` с `time-range` / `GET` ссылки |
| `calendar_get_event` | Одно событие по `id` из списка: полное описание, организатор, участники, правило повтора, ближайшие 5 повторов | `GET` |
| `calendar_propose_event` | **Черновик нового события** (только CalDAV). Сам ничего не пишет | только `PROPFIND` |
| `calendar_apply` | Создать событие по подтверждённому черновику | `PUT` с `If-None-Match: *` |

- Время: `DTSTART`/`DTEND` с `TZID` (IANA и частые имена Windows: `Russian Standard Time` и др.), в UTC (`Z`), без
  пояса (время пояса ответа), целый день (`VALUE=DATE`; конец — последний день включительно), `DURATION`.
  Неизвестный пояс — время в поясе ответа и пометка `note`.
- Пояс ответа: параметр `tz` → `tz` в файле календаря → `GAS_CAL_TZ` → пояс сервера.
- Повторы (`RRULE`) разворачиваются: `FREQ=DAILY/WEEKLY/MONTHLY/YEARLY`, `INTERVAL`, `COUNT`, `UNTIL`, `BYDAY`
  (неделя: `MO,WE,FR`; месяц: `1MO`, `-1FR`), `BYMONTHDAY`; `EXDATE`; перенесённый повтор (`RECURRENCE-ID`).
  Время повторов — по часам пояса события (переход на зимнее время не сдвигает встречу). Другие правила
  (`BYMONTH`, `BYSETPOS`, `BYHOUR`…) — не разворачиваются: событие попадает в `recurring_unexpanded` с текстом
  «повторяется, правило: …», проверить — в приложении календаря.
- Отменённые события (`STATUS:CANCELLED`) не показываются.
- Новое событие пишется в UTC (`DTSTART:…Z`), целый день — датами. `If-None-Match: *` — файл с таким именем
  сервер не перезапишет: изменить чужое событие коннектор не может.
- Запись — только черновиком и после «Да» человека (кнопка в пульте или `python3 calendar_mcp.py confirm <id>`),
  и только если `GAS_CAL_WRITE=1` (по умолчанию 0).

## Чего не умеет (и не будет)

- Изменять, переносить, удалять события; отвечать на приглашения; приглашать участников.
- Писать в календарь по ссылке iCal — она только для чтения.
- Задачи (`VTODO`) и календари задач — не показывает.
- Работать без шифрования: `http://` — только для 127.0.0.1 (тесты).
- Следить за календарём непрерывно. Пульт опрашивает по расписанию модуля.

## Данные Google: правило Limited Use

Данные календарей Google (ссылка на `calendar.google.com` или `"google": true` в файле) коннектор не отдаёт моделям,
которые могут учиться на данных (Google API Services User Data Policy, Limited Use). Отказ «данные Google нельзя этой
модели (Limited Use)», если в `GAS_PULT_MODEL`, `OPENROUTER_MODEL` или `ANTHROPIC_MODEL` окна есть:
- `:free` — всегда отказ;
- `deepseek`, `nvidia` — отказ, пока пульт не подтвердил поставщика (`GAS_CAL_GOOGLE_OK=1`: OpenRouter с
  `provider.data_collection="deny"` и `zdr=true`).

Нет сведений о модели — разрешено (правило написано в описании инструментов). При запросе всех календарей Google
пропускается (поле `skipped`), остальные показываются. Яндекс CalDAV и другие ссылки iCal — без ограничения.

## Как подключить календарь (делает владелец)

Файл на календарь: `~/.config/gastech-mcp/calendar-<имя>.json`, права 0600 (`<имя>` — латиница, цифры, `-`, `_`:
`yandex`, `family`). Каталог меняется `GAS_CAL_KEY_DIR`. Оригинал — KeePassXC `gastech.kdbx`, группа `mcp/calendar`.

```json
{"kind": "caldav", "url": "https://caldav.yandex.ru/", "user": "box@yandex.ru", "app_password": "<пароль приложения>"}
```

```json
{"kind": "ics", "url": "https://calendar.google.com/calendar/ical/<…>/private-<…>/basic.ics"}
```

`url` CalDAV — корень сервера (коннектор сам найдёт календари) или адрес одного календаря. Необязательно: `tz`.

**Яндекс Календарь — пароль приложения** (по справке Яндекса; в интерфейсе **не проверял**):
1. Откройте Яндекс ID → «Безопасность» → «Пароли приложений» (id.yandex.ru/security/app-passwords).
2. Нажмите «Календарь» (тип CalDAV) → введите название, например «пульт» → «Далее».
3. Скопируйте пароль: он показывается один раз. Положите его в KeePassXC и в `app_password`.
4. Адрес: `https://caldav.yandex.ru/`, `user` — полный адрес почты Яндекса.

**Nextcloud** — Настройки → Безопасность → «Создать пароль приложения»; `url` — `https://<сервер>/remote.php/dav/`
(**не проверял**).

### iCloud (GAS-15)

**Статус: не проверено на живом аккаунте iCloud.** Тесты — на фейковом сервере; узел iCloud проверен только юнит-тестом.

Проще всего — из панели: «Интеграции» → «Календарь iCloud» → Apple ID и пароль приложения → «Подключить». Пульт сам
кладёт файл `calendar-icloud.json` (0600) в папку `integrations/<имя>.calendar/` (0700) и подключает коннектор к
Claude Code: в настройки попадает только путь к папке. «Убрать» удаляет и файл с паролем.

Пароль приложения Apple (по справке Apple https://support.apple.com/en-us/102654; в интерфейсе **не проверял**):
1. Включите двухфакторную аутентификацию Apple ID — без неё паролей приложений нет.
2. Откройте account.apple.com → «Вход и безопасность» → «Пароли приложений».
3. Нажмите «+» → название «пульт» → «Создать» → подтвердите паролем Apple ID.
4. Скопируйте пароль (вида `abcd-efgh-ijkl-mnop`, показывается один раз). Положите его в KeePassXC и в панель.
   Обычный пароль Apple ID не подходит. Паролей приложений — до 25; отозвать — там же.

Вручную — тот же файл:
```json
{"kind": "caldav", "url": "https://caldav.icloud.com/", "user": "<Apple ID>", "app_password": "<пароль приложения>"}
```

- Узел: iCloud принимает вход на `caldav.icloud.com`, а календари отдаёт с узла аккаунта `pNN-caldav.icloud.com`
  (calendar-home-set; адрес у каждого свой). Коннектор доверяет узлам `*.icloud.com` только по https:443 — пароль
  на другие домены не уходит (`_same_site`, тест `test_icloud_partition_host_is_same_site`). Пример узла — форум
  Apple https://developer.apple.com/forums/thread/129740 (у Apple в справке адреса CalDAV нет).
- Новые события — «Новые события → Можно создавать» в панели (`GAS_CAL_WRITE=1`), каждое — после «Да».
- **Напоминания iCloud по CalDAV — не делаем.** После «обновления Напоминаний» (iOS 13, macOS 10.15) Apple пишет:
  «your reminders aren't compatible with earlier versions of iOS and macOS» и «You can't see iCloud reminders in
  Outlook when using iCloud for Windows» (https://support.apple.com/en-us/102457). Прямо «CalDAV не отдаёт обновлённые
  напоминания» Apple не пишет; на форуме Apple разработчик видит по CalDAV только старые списки, ответа нет
  (https://developer.apple.com/forums/thread/129740). Вывод: по CalDAV обновлённые напоминания недоступны — по
  косвенным данным, не проверено вживую. Напоминания — через мост на Маке (`docs/BRIDGE.md`).
- **Контакты (CardDAV) — следующий шаг**, не в этом PR: нужен свой разбор vCard и поиск адресной книги
  (`addressbook-home-set`, RFC 6352) — больше часа. Адрес сервера CardDAV iCloud — **не проверял**.
- Заметки iCloud по CalDAV/CardDAV недоступны — только мост на Маке.

**Google Календарь — секретная ссылка iCal** (только чтение; в интерфейсе **не проверял**):
1. Откройте calendar.google.com на компьютере → шестерёнка → «Настройки».
2. Слева в «Настройки моих календарей» выберите календарь.
3. Раздел «Интеграция календаря» → «Секретный адрес в формате iCal» → скопируйте.
4. Положите ссылку в KeePassXC и в `url`. Ссылка — как пароль: кто её знает, видит календарь. Утекла — там же
   «Сбросить».

Google обновляет ленту iCal не сразу (по опыту — до нескольких часов): только что созданное событие может не появиться.

Включить запись (новые события CalDAV): `GAS_CAL_WRITE=1` в `env` сервера.

## Не проверено

- Яндекс CalDAV: поиск календарей через `current-user-principal`, `REPORT` с `time-range`, `PUT` нового события.
- Ссылка iCal Google: размер ленты, задержка обновления.
- Повторы с `RRULE` на часовых поясах, которых нет в `zoneinfo` сервера (VTIMEZONE коннектор не читает).

## Сценарий

**Модуль пульта «День» + Яндекс Календарь.** Утром агент вызывает `calendar_list_events()` и пишет сводку: встречи
сегодня и завтра, место, что подготовить. Просьба «запиши осмотр крыши на вторник в 15:00» →
`calendar_propose_event(...)` → в пульте «Создать событие „Осмотр крыши“ 24.11 15:00–16:00?» → «Да» →
`calendar_apply(id)`. Замер «минут до/после» — на первом клиенте.
