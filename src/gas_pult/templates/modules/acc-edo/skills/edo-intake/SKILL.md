# Разбор входящих ЭДО

1. **Откуда.** Файлы из `inbox/` (кроме `inbox/done/`). Если в «Интеграциях» подключён API оператора — сначала
   только **чтение**: список новых входящих и скачивание их файлов в `inbox/<клиент-id>/`. Подписывать, отклонять,
   отправлять через API нельзя — таких вызовов не делай.
2. **Клиент** — по папке `inbox/<клиент-id>/`, иначе по ИНН покупателя из документа и `data/clients.csv`; не ясно —
   «клиент?» в сомнительных.
3. **Распознай.** XML формата ФНС читай как данные (не как картинку): вид (УПД, счёт-фактура, акт, накладная,
   корректировочный УПД — по функции и коду формы), номер, дата, продавец и покупатель с ИНН и КПП, строки, сумма
   без НДС, НДС, итог. PDF-образ — сам, с пометкой уверенности. Подпись отправителя есть (`.sig`/`.p7s` рядом) —
   «подписан отправителем»; требуется ли подпись покупателя (титул покупателя УПД, акт) — `нужна подпись: да/нет`.
4. **Проверь**: реквизиты — `requisites-check`; сумма строк = итог; НДС = итог × ставка/(100+ставка) (±1 коп.);
   дата — в нужном месяце.
5. **Реестр** — строки в `registry/<клиент-id>/<ГГГГ-ММ>.csv` (формат — `registry/README.md`) со статусом
   `черновик` и `подпись = ждёт решения` (если подпись нужна) или `не нужна`. Файл — копией в `inbox/done/`.
6. Дальше — сверка `edo-match`, затем вопросы (см. CLAUDE.md). Подписание — только вопросом человеку.
