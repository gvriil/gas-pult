# Модули-агенты

Модуль — готовое рабочее пространство под задачу или отрасль: агент с ролью и правилами (`CLAUDE.md`), навыки
Claude Code, пример данных, нужные интеграции, расписание и решения, которые человек принимает кнопками. Модуль —
**одна папка без кода**: новый (в том числе отраслевой) модуль добавляется папкой, пульт подхватывает его сам.

Из модуля создаётся **пространство** — новая папка в первом корне `project_roots` (по умолчанию `~/projects`)
с сессией Claude в ней. Существующая папка не перезаписывается никогда.

## Встроенные модули

| Модуль | Для чего | Расписание | Решения |
|---|---|---|---|
| `night-shift` — «Ночная смена» | Ночью по `PLAN.md`: код → проверка → ревью безопасности; лимит итераций (20); утром `REPORT.md` | 07:30 — утренний отчёт | будит только по трём причинам: необратимое/внешнее действие, блокировка, риск безопасности или данных — «Да» / «Нет» |
| `morning-numbers` — «Утренние цифры против плана» | План/факт/отклонение за вчера и с начала месяца, топ-3 отклонения; источник — CSV, Google Таблицы или выгрузка 1С | 08:00 каждый день | «Что делаем?» — 2–4 варианта под цифры дня |
| `client-alerts` — «Оповещения клиентов» | Напоминания и рассылки по шаблонам; пачка уходит только после «Да»; без канала — черновики в `outbox/` | 10:00 по будням | «Отправить пачку из N?» — «Да» / «Нет» |

Общие блоки (`_common`, заготовки — наполняются отраслевыми модулями): `reminders` «Подтверждения и напоминания»,
`reviews` «Отзывы и NPS», `receivables` «Дебиторка», `documents` «Документы».

## Где лежат модули

- Встроенные — в пакете: `src/gas_pult/templates/modules/<id>/` (ставятся вместе с пультом).
- Свои — `~/.config/gas-pult/modules/<id>/` (или `$GAS_PULT_CONFIG_DIR/modules/`). Свой модуль с тем же `id`
  заменяет встроенный. Папки, имя которых начинается с `_`, модулями не считаются.

## Папка модуля

```
templates/modules/<id>/
├── module.toml        описание (ниже) — обязательно
├── CLAUDE.md          роль и правила агента — обязательно; {{ключ}} заменяется значением из [settings]
├── skills/<имя>/SKILL.md   навыки Claude Code → .claude/skills/ пространства
├── settings.json      разрешения Claude Code → .claude/settings.json (необязательно)
└── …                  всё остальное (data/, templates/, PLAN.md…) копируется в пространство как есть
```

`SKILL.md` — формат навыков Claude Code: frontmatter `name` и `description` (когда навык использовать), дальше —
инструкция.

## module.toml

```toml
id = "morning-numbers"         # необязательно; если есть — как имя папки: латиница, цифры, дефис (2–41 знак)
version = "1.0"                # пишется в отметку пространства
title = "Утренние цифры против плана"          # обязательно
industry = "Общие"             # обязательно: отрасль — группа в каталоге («Общие» — первыми)
about = "В 8:00 — план, факт и отклонения…"   # обязательно: одна строка «для чего»
description = """Подробнее — абзац для экрана модуля. {{threshold}} — из [settings]."""
start = """Первое задание агенту сразу после создания пространства."""   # по умолчанию — «прочитай CLAUDE.md…»
uses = ["reminders"]           # общие блоки из _common (ниже); неизвестный id — ошибка

[settings]                     # простые значения; {{ключ}} в CLAUDE.md, description, start и prompt
threshold = 5
time = "8:00"

[[integrations]]               # что подключить; состояние и «Подключить» — на экране модуля в панели
id = "gdrive"                  # id из пульта: коннекторы claude.ai (notion, gmail, gcal, gdrive, slack, linear,
                               # atlassian, figma) или шаблоны (github, linear, notion, homeassistant, context7…)
title = "Google Таблицы (через Google Диск)"   # необязательно для известных id
why = "Если план и факт ведёте в Google Таблицах"
optional = true                # по умолчанию false — «нужно»

[[integrations]]               # своё, чего нет в пульте: kind = manual
id = "onec"
title = "Выгрузка из 1С"       # обязательно
why = "…"
how = "Как подключить словами" # обязательно, если optional = false
optional = true

[[data_sources]]               # откуда данные — только официальные API и выгрузки клиента
title = "План и факт: CSV или выгрузка из 1С в data/"
kind = "client_export"         # client_export — выгрузка клиента; official_api — официальный API
about = "необязательное пояснение"

[[schedule]]                   # в это время пульт отправит prompt в сессию пространства
at = "08:00"                   # ЧЧ:ММ, время сервера
days = [1, 2, 3, 4, 5]         # необязательно: дни недели 1–7 (1 — понедельник); по умолчанию — каждый день
title = "Сводка план/факт"
prompt = """…"""

[[decisions]]                  # какие решения человек принимает кнопками — для экрана модуля и бота
question = "Что делаем?"
options = ["Разобрать", "Подробно", "Всё в порядке", "Позже"]   # 2–4 варианта; по умолчанию «Да», «Нет»
when = "когда агент спрашивает"
```

Ошибка в `module.toml` — модуль не попадает в каталог, а владелец видит в панели («Из модуля») понятный текст:
какой модуль и какое поле (`gas_pult.modules.ModuleError`).

## Общие блоки

Повторяющиеся куски для отраслевых модулей — `templates/modules/_common/<id>/` (или `~/.config/gas-pult/modules/
_common/<id>/`):

```
_common/<id>/
├── block.toml     title, about
├── RULES.md       фрагмент правил
└── skills/<имя>/SKILL.md
```

В каталоге блоков нет. Модуль подключает их полем `uses = ["reviews", "receivables"]`: при создании пространства
навыки блока копируются в `.claude/skills/`, а `RULES.md` дописывается в `CLAUDE.md` разделом «Общий блок: <title>».
Источники `data_sources` дописываются в `CLAUDE.md` разделом «Откуда данные».

## Как добавить отраслевой модуль

1. Скопируйте близкий модуль: `cp -r src/gas_pult/templates/modules/client-alerts ~/.config/gas-pult/modules/horeca-orders`
   (или в репозиторий — `src/gas_pult/templates/modules/<id>/`, тогда модуль приедет всем с обновлением).
2. Поправьте `module.toml`: `id` = имя папки, `title`, `industry` (например «HoReCa»), `about`, интеграции,
   `data_sources`, расписание, решения; общие блоки — в `uses`.
3. Перепишите `CLAUDE.md`: роль, порядок работы, когда спрашивать человека (только инструментом выбора вариантов —
   AskUserQuestion), чего нельзя никогда. Навыки — в `skills/<имя>/SKILL.md`.
4. Пример данных — выдуманный и обезличенный («ООО Пример», «Иван», `+7 900 000-00-01`, `@example.com`).
5. Проверка: `PYTHONPATH=src python -c "from gas_pult import modules; e=[]; print([m['id'] for m in modules.catalog(e)], e)"`
   и `pytest tests/test_modules.py`. Код пульта не меняется.

## Создать пространство

**Панель:** «Новая сессия» → «Из модуля» → модуль → экран модуля: интеграции с состоянием (подключено / нет;
«Подключить» открывает тот же мастер, что во вкладке «Интеграции», «‹ Назад» возвращает к модулю), откуда данные,
расписание, решения кнопками, что будет в папке → имя папки (по умолчанию `<id>`, занято — `<id>-2`) → «Создать
и открыть сессию» (выбор модели — как у новой сессии). Видят каталог все роли; создавать — владелец и участник
(окно участника — с его папкой Claude, ADR 0001). API: `GET /api/modules`, `POST /api/modules/create`
`{id, name, profile}` → `{id, path, folder}`.

**Бот:** `/modules` (или «🆕 Новая» → «🧩 Из модуля…») → модуль → описание, интеграции, расписание, решения →
«✅ Создать «<id>»» или «✏️ Другое имя папки».

Что происходит: папка `<корень>/<имя>` — копия модуля (`CLAUDE.md` с подставленными `{{…}}`, навыки в
`.claude/skills/`, разрешения в `.claude/settings.json`, данные), отметка `.gas-pult-module` (JSON: `id`,
`version`, `title`, `created`, `by` — кто создал, если не владелец) и `git init` — любую правку агента можно
откатить. Затем — сессия Claude в папке и первое задание модуля (`start`). Свежая папка начинается с вопроса
Claude Code «доверяете этой папке?» — пульт ждёт ответа до 3 минут и тогда отправляет задание; не дождался —
пишет владельцам.

## Расписание

Бот раз в минуту смотрит пространства в корнях проектов (папки с `.gas-pult-module`) и пункты `[[schedule]]` их
модулей. Логика — как у утренней сводки (`digest.due`): время наступило, а сегодня ещё не отправляли
(`~/.local/share/gas-pult/modules.json`). Дальше:

- окно Claude в этой папке есть — `prompt` уходит в него (как сообщение из бота); окно занято вопросом — владельцам
  строка «задание не отправлено» с причиной;
- окна нет — пульт **открывает его сам** (папкой Claude того, кто создал пространство; проверка страны и поставщика —
  как у новой сессии) и отправляет `prompt` первым сообщением; владельцам — «🗓 … открыл сессию по расписанию».
  Решение: модуль для того и заводят, чтобы сводка была в 8:00 без участия человека;
- пульт был выключен в назначенное время — догоняет не позже 3 часов; пространство создано позже назначенного
  времени — сегодня не шлёт.

Время — сервера (`TZ` службы). Удалить расписание — удалить отметку `.gas-pult-module` или папку.

## Решения кнопками

Новых протоколов нет. Агент обязан задавать вопрос **инструментом выбора вариантов Claude Code (AskUserQuestion)** —
это написано в `CLAUDE.md` каждого модуля. Claude Code показывает меню, монитор бота узнаёт его и присылает экран
с кнопками 1/2/3/↑/↓/⏎ (`show_dialog`), панель показывает варианты кнопками. Пока человек не ответил, агент ждёт.
Экран в Telegram — последние 25 строк, поэтому сводку агент кладёт в текст вопроса коротко (до шести строк),
а полностью — в файл (`SUMMARY.md`, `REPORT.md`, `outbox/…`).

## Ограничения

- Лимит итераций, «не будить без причины», «без одобрения не отправлять» — правила для агента в `CLAUDE.md`,
  пульт их не проверяет. Технически ограничивают только разрешения Claude Code (`settings.json` модуля: например,
  у «Ночной смены» `git push`, `rm`, `curl`, `sudo` — с вопросом).
- Модуль меняется — уже созданные пространства не обновляются (версия — в `.gas-pult-module`).
- Пространства ищутся только в корнях `project_roots` на один уровень.
- Отправка клиентам идёт через интеграции (Gmail, свой MCP-сервер бота). Данные клиентов при работе агента
  попадают к поставщику модели — см. [`COMPLIANCE.md`](COMPLIANCE.md), раздел «Модули и данные клиентов».
