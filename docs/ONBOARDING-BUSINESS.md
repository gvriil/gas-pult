# Как подключить новый бизнес к пульту

Для владельца: что получает бизнес, что нужно с его стороны, как идёт подключение и что ещё не готово, когда
клиентов несколько. Всё ниже сверено с кодом на 01.11.2026. Цены здесь не указаны, их называет владелец.

## 1. Что получает бизнес

Агенты (Claude Code) ведут рутину в папках бизнеса, а люди управляют ими с телефона: чат с агентом, голос, ответы
на вопросы агента одной кнопкой, утренняя сводка «что ждёт вас». Работает через Telegram-бота и панель
(Mini App в Telegram или браузер). Люди получают роли, ключи и команды остаются на сервере бизнеса.

## 2. Что нужно со стороны клиента

### Сервер

| Что | Требование (из кода) |
|---|---|
| Система | Linux (Ubuntu/Debian и похожие) или macOS. Служба: systemd (пользовательская) или launchd |
| Python | **3.11 или новее**, с модулем `venv` (`install.sh` и `gas-pult doctor` это проверяют) |
| tmux | обязателен: каждая сессия агента — это окно tmux |
| Claude Code | команда `claude` в PATH (её ищут `install.sh` и `doctor`) |
| Ресурсы | ориентир — 2 vCPU, 4 ГБ памяти, 40 ГБ диска; если голос распознаётся на сервере (Whisper), нужно больше |
| Отдельный пользователь Linux | на каждый бизнес свой: «Выполнить» и агенты работают с правами этого пользователя |
| Домен с HTTPS | для постоянной панели: поддомен, Caddy с сертификатом Let's Encrypt, проброс порта. Чтобы просто попробовать, хватит `gas-pult webapp --tunnel` (адрес Cloudflare меняется при каждом перезапуске) |

### Telegram-бот

Бот создаёт владелец бизнеса у @BotFather (`/newbot`) и забирает себе. Токен вводится на сервере при
`gas-pult init` скрытым вводом и хранится в файле с правами 0600. Пересылать токен в чат нельзя.

### Люди и роли

| Роль в коде | Кто | Что может |
|---|---|---|
| `owner` (владелец) | Telegram ID из `owners` в `config.toml` | всё: «Выполнить» команды, закрыть или перезапустить сессию, ключи, модели, интеграции, люди |
| `member` (участник) | добавляет владелец | писать в сессии, отвечать на вопросы агента, команды, новые сессии, файлы. «Выполнить», ключи и люди ему недоступны |
| `viewer` (наблюдатель) | добавляет владелец | только смотреть |

Как человек получает доступ: в панели он жмёт «Войти через Telegram», владельцу приходит запрос, владелец нажимает
«Участник» или «Наблюдатель». Роль проверяется при каждом запросе, поэтому удалённый человек теряет доступ сразу.
Сам бот отвечает только владельцам, остальные работают в панели.

### Проекты

Направление бизнеса — это папка на сервере. В ней лежат `CLAUDE.md` (правила и контекст для агента), документы и
шаблоны. Папки ищутся в `project_roots` (по умолчанию `~/projects` и `~/worktrees`). Свои кнопки задаются в
`commands`, номера задач трекера — в `task_pattern`.

### Модели

Пульт запускает Claude Code в одном из профилей (`src/gas_pult/models.py`). Других поставщиков в коде нет.

| Профиль | Как подключается |
|---|---|
| Claude (Anthropic) | подписка (`claude` → `/login` на сервере) или ключ API |
| OpenRouter | ключ или вход в одно касание; надёжно работают только модели Anthropic |
| GLM (Z.ai) | ключ |
| DeepSeek | ключ |

Для российского юрлица это главный вопрос. По данным владельца, Claude и OpenAI российским юрлицам недоступны.
OpenAI в коде нет вообще. Остальные три поставщика зарубежные: договор, оплату и передачу данных за рубеж нужно
решить до старта. Российских моделей (GigaChat, YandexGPT) в коде нет (см. раздел 5). Коннекторы claude.ai (Notion,
Gmail и т. п. в «Интеграциях») требуют аккаунта Claude.

Голос: Piper и Whisper работают на сервере, данные никуда не уходят. ElevenLabs по желанию, тогда текст и голосовые
уходят в ElevenLabs. Голоса Silero для клиента не подходят: их лицензия (CC BY-NC-SA) запрещает коммерческое
использование.

### Данные и доступы

| Что | Где |
|---|---|
| Переписка с агентом | `~/.claude/projects/…` пользователя сервера (журналы Claude Code) |
| Настройки, токен бота, ключи | `~/.config/gas-pult/` (`config.toml`, `token`, `secrets.json` с правами 0600) |
| Люди, состояние, журнал команд | `~/.local/share/gas-pult/` (`people.json`, `state.json`, `commands-log.json`) |
| Ключи интеграций (MCP) | `~/.claude.json` на сервере |
| Документы | папки проектов на сервере |

До начала нужно договориться: какие данные кладём на сервер, кто его администратор, где он физически стоит,
кто делает бэкапы и что происходит с данными при отключении. Вход в Claude и ключи вводит сам владелец бизнеса.

## 3. Подключение по шагам

| # | Шаг | Команда или действие | Время |
|---|---|---|---|
| 1 | Сервер и пользователь | VPS или пользователь на имеющемся сервере; `sudo apt install python3 python3-venv tmux` | 30 мин |
| 2 | Claude Code | поставить по инструкции Anthropic; вход: `claude` → `/login` (владелец) или ключ поставщика позже в панели | 15 мин |
| 3 | Бот | владелец бизнеса: @BotFather → `/newbot` | 5 мин |
| 4 | Установка | `./install.sh` из клона репозитория (ключи `--no-voice`, `--no-service`). Скрипт сам запускает `gas-pult init`: токен, затем владелец пишет боту и этим подтверждает свой ID | 15 мин |
| 5 | Голос (по желанию) | `gas-pult voices install irina` (входит в `install.sh`, если не указан `--no-voice`) | 10 мин |
| 6 | Служба бота | `gas-pult service install` (systemd или launchd). Чтобы бот работал без входа в систему: `sudo loginctl enable-linger <пользователь>` | 5 мин |
| 7 | Проверка | `gas-pult doctor`: Python, tmux, настройки, Claude Code, бот, голос | 2 мин |
| 8 | Панель | на пробу: `gas-pult webapp --tunnel`. Постоянно: DNS, Caddy и две пользовательские службы (`gas-pult-caddy`, `gas-pult-webapp` с `gas-pult webapp --url https://…`) по [MINI_APP.md](MINI_APP.md), вручную | 30–60 мин |
| 9 | Модель | панель → «Интеграции» → «Модели»: выбрать профиль, ввести ключ | 5 мин |
| 10 | Проекты | папки направлений с `CLAUDE.md`; кнопки `commands` в `config.toml`, затем перезапуск службы | 30–90 мин на папку |
| 11 | Интеграции | панель → «Интеграции»: коннекторы claude.ai или MCP по ключу; вход выполняет владелец бизнеса | 15–60 мин на сервис |
| 12 | Люди | каждый жмёт «Войти через Telegram», владелец выдаёт роль | 2 мин на человека |
| 13 | Сводка | `digest_at = "09:00"`. PR в сводке есть только с GitHub (`digest_github` и `gh auth login`), «да» берутся из `HANDOFF.md` в папках | 10 мин |

## 4. Сколько времени «под ключ»

- Техническая часть (шаги 1–9): **2–3 часа** нашей работы и **30–60 минут** владельца бизнеса (бот, входы, ключи).
- Проекты и интеграции (шаги 10–13): **от половины дня до дня**, зависит от числа направлений и сервисов.
- Затем неделя сопровождения: подбираем кнопки, правим `CLAUDE.md`, отвечаем на вопросы.
- Итого: **1–2 рабочих дня** до запуска. Вопрос с моделью для российского юрлица в эту оценку не входит.

Цены (подключение, сопровождение, сервер, модель) **называет владелец**. Платные статьи у клиента: сервер, домен,
модель (подписка или оплата по факту), ElevenLabs по желанию.

Лицензия пульта (PolyForm Noncommercial) оставляет коммерческое использование за владельцем, поэтому условия для
клиента определяет договор с владельцем.

## 5. Что пока не готово для нескольких клиентов

Объём: **S** — до дня, **M** — 2–4 дня, **L** — неделя и больше.

| # | Что сейчас (по коду) | Что сделать | Объём |
|---|---|---|---|
| 1 | **Одна установка обслуживает один бизнес.** Один список `owners`, одна сессия tmux (`session`, по умолчанию `main`), одни каталоги. Несколько бизнесов в одном процессе не поддерживаются | Так и оставить, изоляция через отдельного пользователя Linux. Добавить скрипт «новый клиент»: пользователь, свой порт панели, свой поддомен в Caddy, linger | M |
| 2 | **Установка не для неспециалиста.** Пути и сессия настраиваются (`GAS_PULT_CONFIG_DIR`, `GAS_PULT_DATA_DIR`, `GAS_PULT_TMUX_SOCKET`, `session`, `--port`), но Caddy, DNS и службу панели надо настраивать руками: `service install` ставит только бота | `gas-pult service install --webapp --url …` и проверка панели в `doctor` | S |
| 3 | **Участник видит все сессии и папки сервера.** Ограничения по направлениям нет | Список папок у человека в `people.json`, фильтр в API и в панели | M |
| 4 | **Бот уведомляет только владельцев.** Участник узнаёт о вопросе агента только из панели | Уведомления участникам по их папкам | S |
| 5 | **Нет журнала «кто что сделал».** Журнал команд не записывает человека | Журнал действий людей на сервере и экран для владельца | S |
| 6 | **Нет учёта расхода и биллинга.** Не видно, сколько стоят агенты по людям и направлениям, счетов клиенту нет | Сбор токенов из журналов Claude Code и сверка со счетами поставщиков. Биллинг — отдельная система, не пульт | M (учёт), L (биллинг) |
| 7 | **Нет российских моделей.** Профили: Claude, OpenRouter, GLM, DeepSeek; все зарубежные. Claude Code требует API, совместимого с Anthropic | Профиль российского поставщика через совместимый шлюз, затем проверка качества на задачах клиента | M–L |
| 8 | **152-ФЗ.** Переписка хранится на сервере, но запросы к модели уходят зарубежному поставщику, а это трансграничная передача персональных данных. Пульт её никак не ограничивает и не отмечает | Сервер в РФ; правило «персональные данные не отправлять» в `CLAUDE.md`; российская модель (п. 7); документы по 152-ФЗ готовит юрист | M (с юристом) |
| 9 | **Нет бэкапа и выгрузки.** Переписка, настройки и люди лежат на одном сервере | `gas-pult backup` / `restore`: архив каталогов пульта, журналов Claude Code и папок проектов | S |
| 10 | **После перезагрузки сервера окна агентов не возвращаются.** Сам пульт окна tmux не восстанавливает | Снимок окон и восстановление при старте службы | S |
| 11 | **Утренняя сводка привязана к GitHub и `HANDOFF.md`** | Подключаемые источники сводки: трекер, CRM, почта, сроки | M |
| 12 | **Новое направление создаётся без шаблона.** Есть только «📁 Новая папка…» в боте | «Новое пространство» в панели: имя, шаблон `CLAUDE.md`, кому доступно | S |
| 13 | **Интерфейс только на русском** | Вынести строки в отдельный файл, английский добавить вторым | M |

Без пунктов 3–5 пульт подходит бизнесу, где с агентами работает сам владелец и 1–2 доверенных человека. Для
российского юрлица с персональными данными до запуска нужно закрыть пункты 7–8 или зафиксировать решение по ним
письменно.
