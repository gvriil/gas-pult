# 4 правила: «не платить за продукт дважды»

Критерий для каждого PR и для ночной проверки (решение владельца 22.11.2026). Правило — не пожелание: у каждого
пункта есть проверка, и её итог виден в CI.

Машинная проверка — `tools/four_rules.py` (только стандартная библиотека):

```bash
python tools/four_rules.py              # таблица «правило · пункт · итог · где»
python tools/four_rules.py --json       # то же в JSON — для ночной проверки
python tools/four_rules.py --no-tests   # без запуска pytest, только разбор кода (секунда)
```

Итог пункта:
- **OK** — пункт выполнен;
- **ПРЕДУПРЕЖДЕНИЕ** — ход работ: долг виден списком, CI не ломает;
- **ОШИБКА** — правило нарушено: код выхода 1, задание CI `rules` красное.

**PR не ухудшает 4 правила:** не добавляет ОШИБОК и не удлиняет списки ПРЕДУПРЕЖДЕНИЙ (новый файл больше 800 строк,
новая запись JSON мимо `store`). Сократить список — хорошо; удлинить — только с причиной в описании PR.

## 4. Экономить с умом

Готовые библиотеки и облачный вход — да (OIDC, passkeys, SQLite из стандартной библиотеки). **Не экономим** на
структуре данных, безопасности платежей и аналитике событий.

| Пункт | Чем проверяется | Сейчас |
|---|---|---|
| Деньги — целые центы; float в расчётах нет | `four_rules.py`: в `billing/` нет литералов `1.5` и вызовов `float(…)`; `tests/test_billing.py::test_cents_no_float_and_explicit_rounding` | OK |
| Журнал платежей — только добавление; исправление — встречной записью | триггеры `BEFORE UPDATE/DELETE ON journal` в `billing/store.py`; `tests/test_billing.py::test_journal_append_only`, `…void_is_reversal_not_edit` | OK |

## Ночная проверка

Ночной прогон (harness портфеля, вне этого репозитория) вызывает скрипт в свежей копии `main`:

```bash
python tools/four_rules.py --json > four-rules.json; echo $?
```

Формат JSON:

```json
{"ok": true, "errors": 0, "warnings": 3, "passed": 12,
 "rules": {"1": "MVP на фундаменте", "…": "…"},
 "checks": [{"rule": 1, "item": "файлы Python ≤ 800 строк", "status": "ПРЕДУПРЕЖДЕНИЕ", "level": "warn",
             "where": "docs/MONOLITH-PLAN.md", "details": ["src/gas_pult/webapp.py: 6154", "…"]}]}
```

Что делает ночная проверка:
- `ok: false` или код выхода 1 — сообщить: какой пункт (`level: "error"`), где;
- сравнить со вчерашним JSON: выросло `warnings` или удлинился `details` у пункта — сообщить, что ухудшилось;
- `details` сократился — записать в ход работ.

Pytest нужен в окружении (`pip install -e ".[dev]"`); без него ключевые тесты дают ОШИБКУ «pytest не запустился».
