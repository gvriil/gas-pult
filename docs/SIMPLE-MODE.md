# Простой режим панели

Режим для бизнеса: один разговор с агентом, без терминала, списка сессий и технических экранов, без английских слов.
Полный режим (режим разработчика) не меняется — простой включается настройкой человека.

## Как включить

- Панель → «Настройки» → **«Простой режим»**. Выключить — в простом режиме «Настройки» → «Выключить простой режим».
- Настройка — у каждого человека своя и хранится на сервере (`GET/POST /api/prefs`: `{simple, lang}`): у участника
  и наблюдателя — поле `prefs` в его записи `people.json`, у владельца — `<data>/prefs.json` (0600). В браузере
  (`localStorage`) — только кэш языка для первого экрана. По умолчанию выключено: у текущих пользователей ничего не
  меняется.
- Позже простой режим будет включаться ролью с будущего экрана выбора роли (ждём решения Gemini); пока — переключатель.

## Что видно

- **Телефон** — один столбец: шапка (имя агента, «? Подсказать», настройки), разговор, строка статуса, вопрос агента
  карточкой с чипами, поле ввода. **Планшет и ПК** — тот же разговор по центру шириной до 760 px, сбоку ничего.
- **Агенты.** Если их несколько — чипы под шапкой и лист «Мои агенты» (нажать на имя). Имя агента — название модуля, из
  которого создано пространство (в английском интерфейсе и для пространств без модуля — «Агент 2» / «Agent 2»); имён
  папок, веток и окон нет. Владелец и участник могут «Подключить агента»: отрасль → агент → «Подключить» (каталог
  модулей пока только на русском).
- **Проекты и чаты** (задача 49, `docs/PROJECTS.md`). Нажатие на имя вверху — лист «Проекты и чаты»: проекты
  чипами (точка — где ждут ответа), открытые чаты выбранного проекта, «Новый чат» (ещё один разговор в той же папке,
  у каждого своя переписка), «Прошлые чаты» — прежний разговор открывается только для чтения, «Продолжить этот чат»
  открывает его снова; строка «Чаты старше N дней удаляются сами». Вверху — название чата и проекта, чипы под шапкой —
  чаты открытого проекта. Ни папок, ни путей, ни веток; модель не выбирается. У тестировщика пространства — пока
  прежние «Мои агенты» (проекты пространств — отдельный шаг). Демо: `?demo&simple=1` → имя вверху.
- **Строка статуса** — общими словами из словаря: «Читает документ», «Правит документ», «Выполняет действие», «Ищет в
  интернете», «Работает с подключённым сервисом» и время; имён файлов и команд нет.
- **Вопрос агента** — переведённый заголовок и чипы. «Да» — один раз, «Нет» — отказ. Опасные пункты («больше не
  спрашивать», «разрешить все правки», «без вопросов») — за чипом «Другие варианты», каждый с пояснением. «Показать
  подробности» — лист с пересказом вопроса и смыслом каждого варианта; сырого экрана нет.
- **Ошибки Claude Code** в переписке («API Error», лимиты, баланс, вход, связь, длинный разговор, остановка) —
  человеческой фразой (`/api/history` добавляет к такому ответу поле `human`).
- **Настройки** простого режима: язык (чипы «Русский» / «English»), «Попросить агента отвечать по-…», оформление,
  «Выключить простой режим», «Обновить экран», выход.
- «? Подсказать» — та же шторка помощника; на экранах простого режима ответы только из их собственных вопросов карты,
  на языке человека.

## Язык: RU / EN

- Переключатель — на **первом экране** (вход) и в **настройках** (простого и полного режима). Выбор до входа
  запоминается в браузере и при входе сохраняется на сервере, если своей настройки у человека ещё нет.
- Строки простого режима, первого экрана, переключателей, помощника и все тексты пересказа — в словарях
  [`src/gas_pult/web/i18n/ru.json`](../src/gas_pult/web/i18n/ru.json) и [`en.json`](../src/gas_pult/web/i18n/en.json)
  (панель грузит `/i18n/<язык>.json`, и до входа). Тест: ключи совпадают, пустых нет, подстановки `{n}` одинаковые, в
  русском нет латиницы, в английском — кириллицы (кроме белого списка).
- Экраны полного режима не переводятся; условия использования и выбор страны — пока только по-русски.

### Язык ответов агента

У Claude Code есть официальная настройка **`language`** в `settings.json` («Preferred language for Claude responses»,
например `"russian"`, `"english"`). Поэтому:

- **Новое пространство из простого режима** («Подключить агента») — пульт пишет `"language": "russian"` или
  `"english"` в `.claude/settings.json` пространства (настройки модуля сохраняются, язык — добавкой;
  `modules.create(…, lang=…)`, поле `lang` в `POST /api/modules/create`). Строку в CLAUDE.md не добавляем.
- **Уже открытые разговоры** — только по явному нажатию «Попросить агента отвечать по-русски / in English» в
  настройках: пульт отправляет агенту одну строку («С этого момента отвечай, пожалуйста, на русском языке.»).
- Текст пользователя пульт не переписывает.

## Словарь шаблонов (`src/gas_pult/humanize.py`)

`humanize.parse(экран)` → `{kind, known, title_ru, title_en, detail_ru, detail_en, options, sig}`; пункт —
`{key, label_ru, label_en, send, level, note_ru, note_en}`. `send` — что нажать через существующие `/api/select` и
`/api/key`: `{"n": "1"}` (пункт по номеру, стрелками и Enter), `{"text": …}` (пункт без номера), `{"key": "Enter" |
"Escape"}`, `{"show": "details"}` (лист «Подробности», в окно ничего не уходит); `compose: true` — потом курсор в поле
ввода. `GET /api/ask?w=` — разбор экрана окна (и наблюдателю).

**Диалоги (16):** доверие к папке (`trust`: «Do you trust the files in this folder?», «Quick safety check … Yes, I
trust this folder»), план (`plan`: «Would you like to proceed?» с «auto-accept edits / manually approve / keep
planning»), отправка ответов (`submit`: «Ready to submit your answers?»), правка (`edit`: «Do you want to make this edit
to X?»), создание (`create`: «Do you want to create X?»), перезапись (`overwrite`), страница в интернете (`fetch`:
«Fetch», «Do you want to allow Claude to fetch this content?»), поиск (`search`: «Web Search»), сервис MCP (`mcp`:
«Tool use», «(MCP)»), команда (`bash`: «Bash command»), чтение вне папки (`read`), рабочая тетрадь (`notebook`),
общее «Do you want to proceed?» (`proceed`), вопрос агента AskUserQuestion (`question`: шапка «☐ …» или служебные
пункты), «Press Enter to continue» (`continue`) и неизвестное (`unknown`).

**Пункты (27):** «Yes», «Yes, proceed», «Yes, I trust this folder», «Yes, and don't ask again (this session / for …)»,
«Yes, and always allow …», «Yes, allow all edits during this session», «Yes, allow reading from …», «Yes, and bypass
permissions», «Yes, and auto-accept edits», «Yes, manually approve edits», «No, keep planning», «Type here to tell
Claude what to change», «No, and tell Claude what to do differently (esc)», «No, exit», «No», служебные пункты вопроса
агента «Submit», «Cancel», «Type something», «Other», «Chat about this»; общие «Да (расширенное разрешение)» для
незнакомого «Yes, …», «Нет» для незнакомого «No, …», «Разрешить», «Не разрешать», «Показать подробности»,
«Продолжить». Второй уровень (`level: 2`) — все «не спрашивать», «разрешить все», «без вопросов», «авто-правки».

**Вопрос агента (AskUserQuestion):** вопрос и варианты пишет сама модель (обычно уже на языке человека) — их не
трогаем; переводим только служебные пункты. «Type something», «Other», «Chat about this», «Type here to tell Claude…»
— Esc и курсор в поле ввода: пока вопрос на экране, пульт текст не вставляет, поэтому ответ своими словами — обычным
сообщением после закрытия вопроса.

**Неизвестное:** «Агент спрашивает разрешение» / «The agent is asking for permission» и чипы «Разрешить» (первый
пункт; без пунктов — Enter), «Не разрешать» (Esc — в вопросах Claude Code это «нет»), «Показать подробности». Незнакомые
пункты разрешений сырым текстом не показываются.

**Ошибки (8, `humanize.error`):** баланс (`Credit balance is too low`), лимит (`usage limit reached`, `rate limit`,
`429`), перегрузка (`Overloaded`, `5xx`), вход (`Invalid API key`, `Please run /login`, `OAuth token expired`, `401/403`),
связь (`Connection error`, `Request timed out`), длинный разговор (`Prompt is too long`, `Context low`), остановка
(`Interrupted by user`), прочие `API Error`.

**Строка статуса (`humanize.TOOLS`, `status_key`):** инструмент → обобщение (`Read/Grep/Glob` — читает документ,
`Edit/Write` — правит/создаёт документ, `Bash` — выполняет действие, `WebSearch/WebFetch` — ищет в интернете,
`Task` — поручил помощнику, `mcp__…` — работает с сервисом); фазы — как в полном режиме (`activity.py`). Та же таблица
в `index.html` (`SIMPLE_TOOL`) — тест сверяет.

### Как добавить шаблон

1. Диалог — строка в `DIALOGS` (`kind`, где искать: `"q"` — строка-вопрос, `"ctx"` — блок над пунктами, регулярка),
   пункт — строка в `OPTIONS` (`key`, регулярка, уровень; опасное — `2`), ошибка — в `ERRORS`.
2. Тексты — ключи `ask.<kind>.title` / `.detail`, `opt.<key>.label` / `.note`, `err.<key>` в **обоих** словарях.
3. Образец экрана — в `tests/test_humanize.py` (как его отдаёт tmux), `pytest`.
4. Если менялся разбор демо-экранов — `python -m gas_pult.humanize` (обновит `const SIMPLE_DEMO` в интерфейсе — `index.html` или `web/js/`; тест
   сверяет).

## Белый список латиницы

`humanize.LATIN_OK` — имена собственные, которые в русском простом режиме можно писать латиницей: Claude, Telegram,
Google, Ozon, WB, Wildberries, GigaChat, YandexGPT, ElevenLabs, GASTECH, iPhone, Android, OpenRouter, DeepSeek, GLM,
Notion, Gmail, Excel, PDF, HoReCa, Face ID и самоназвание «English» в переключателе языка. `humanize.CYRILLIC_OK` — «Русский»
(в английском интерфейсе). Оба списка — в одном месте; их берут тесты словарей и Playwright-проверка.

## Проверка

- `pytest tests/test_humanize.py tests/test_simple_mode.py` — разбор экранов, словари, настройки, API, язык ответов.
- `python tests/e2e/simple_mode.py http://127.0.0.1:8797/?demo [папка]` (Playwright) — демо `?demo&simple=1` и
  `&lang=en` на 390, 820 и 1366 px, светлая и тёмная тема: на экране (видимый текст, подсказки полей, подписи кнопок)
  нет латиницы вне белого списка в русском и кириллицы в английском; вопрос «Do you want to proceed?» — чипами, «Да»
  отвечает агенту; листы и помощник; первый экран `?demo&view=login&lang=en`; полный режим `?demo` — прежний.
- Демо: `?demo&simple=1` (вопрос о команде), `&ask=edit|question|unknown` — другие вопросы, `&lang=en`, `&theme=dark`.
  `question` — вопрос модели остаётся как есть (в демо он по-русски и в английском интерфейсе).
